## 关键设计决策

- **通用模板脱敏算子（参考 v0.8.0 TemplateOp）**：在 `SimpleMasker` 基础上引入 `TemplateParams` 结构（keep_prefix / keep_suffix / mask_char / mask_min_len / min_len / max_len）。`Rule.template: Option<TemplateParams>` 字段用 JSON 存储到 DB `rules.template` 列，避免新增 5 个 typed 列。`masker.rs::mask()` 在 `rule.kind == Mask` 分支内优先检查 `rule.template`：空模板（所有字段 None）→ 不脱敏（透传）；非空模板 → 走 keep_prefix/keep_suffix/mask_min_len + min_len/max_len guard + 重叠处理；无 template → 走旧逻辑（保留首尾各 1），向后兼容。
- **T49 子规则化：4 条独立规则 → 1 条 general-mask + 4 个预设**：原 v1.1.3 T48 落地的 4 条独立规则（`idcard-mask`/`phone-mask`/`birthdate-mask`/`bankcard-mask`）收敛为 `general-mask` 规则的 4 个预设函数（`idcard_preset()`/`phone_preset()`/`birthdate_preset()`/`bankcard_preset()`），不再单独 seed 到 DB。`with_defaults()` 从 7 条降为 4 条（3 name + general-mask）。`general-mask` 持空模板（`TemplateParams::default()`）→ SimpleMasker 视为不脱敏（透传）。前端选预设 → 填充 6 个可编辑参数框 → 执行脱敏时透传 template 给 `mask_column`，或经 `update_rule_template` 持久化到 DB。
- **空模板=不脱敏（透传）**：`TemplateParams::is_empty()` 判断所有字段是否为 None。`general-mask` 默认持空模板 → SimpleMasker 原样返回，承载"未选预设 → 不脱敏"的语义。前端选预设后填充字段 → `is_empty()` 返回 false → 走模板脱敏逻辑。
- **mask_char 优先级改为 `replacement > template.mask_char > 默认 *`**：保留 `mask_column` 命令的 `replacement` 参数语义（临时覆盖），用户在脱敏面板输入框填 `#` 即临时覆盖模板的 `*`；未填则用模板内置 mask_char。
- **mask_column 新增 template 临时参数**：`mask_column(sheet_id, column, rule_id, replacement, template, db)`。前端选预设 → 填充 6 参数 → 透传给 `template` 参数执行脱敏（临时覆盖规则自身 template，不写回 DB）。`update_rule_template` IPC 用于持久化 template 到 DB。
- **DB schema v3→v4：rules 表加 template TEXT 列**：`migrate_v3_to_v4` 用 `PRAGMA table_info(rules)` 检查列是否存在再 ALTER，幂等；`migrate()` 新增链式分支 `Some(2) => v2→v3→v4` 和 `Some(3) => v3→v4`，老用户升级自动补列。`row_to_rule` 读 `template` 列 → `serde_json::from_str` 反序列化为 `TemplateParams`；`upsert_rule` SQL + params 加 `template` 列（None → NULL）。`update_rule_template` 方法单独更新 `template` 列（参数绑定，不拼接 SQL）。
- **seed_builtin_rules 改为"按 id upsert 缺失规则"**：从"只在 count==0 时 seed"改为"遍历内置规则集，对每条 id 不存在的规则 upsert"。这样 v1.1.2 老用户升级 → 启动自动补 seed `general-mask` 规则（持空模板），已存在规则（含用户修改过 pattern/replacement 的）不动，参数不丢。
- **T50 遗留规则清理**：`seed_builtin_rules` 末尾新增 `cleanup_deprecated_rules()`，删除 v1.1.3 T48 遗留的 4 条独立脱敏规则 id（`idcard-mask`/`phone-mask`/`birthdate-mask`/`bankcard-mask`），用 `DELETE FROM rules WHERE id = ?1` + `params![id]` 参数绑定。幂等（id 不存在时 DELETE 影响 0 行）。前端 RulesPanel 规则信息卡片移除「目标列」行（后端 `Rule.field` 字段不动，仍用于 name 规则的目标列绑定语义）。
- **T51 共享模块 maskTemplate.js + 规则管理模板参数**：把 MaskPanel（T49）里的 MASK_PRESETS / EMPTY_TEMPLATE / stripNulls / detectPreset / buildTemplateForRun / resolveMaskChar 抽到 `frontend/src/components/panels/maskTemplate.js`，并新增 `normalizeTemplate` / `templateFromPreset` / `previewMask`（移植后端 `apply_template` 等价逻辑，含空模板透传 + min_len/max_len guard + 保留段重叠处理）。RulesPanel 选 general-mask 时「可填参数」卡片渲染子规则下拉 + 6 个模板参数框（InputNumber/Input），保存走 `updateRuleTemplate`（与 MaskPanel 一致），重置从 DB template 回显，内联测试走 `previewMask` 并显示透传/guard 提示。name-mask 仍只显示掩码字符输入（旧逻辑不变）。

## 已知边界

- `general-mask` 的 4 个预设为固定模板参数（keep_prefix/keep_suffix/mask_min_len 硬编码），但前端 6 个参数框可手动编辑覆盖预设值
- 身份证/手机/出生日期预设有 min_len=max_len guard，长度不匹配的输入原样返回（不脱敏）；银行卡预设无 len guard，任意长度均可脱敏
- 出生日期脱敏按字符串长度处理（keep 8/0 + mask 2），不校验日期合法性（非日期格式的 10 字符串也会被脱敏）
- T49 删除了 v1.1.3 T48 的 4 条独立规则 id（idcard-mask/phone-mask/birthdate-mask/bankcard-mask），T50 `cleanup_deprecated_rules()` 在 `seed_builtin_rules` 末尾自动从用户 DB 删除这 4 个遗留 id（幂等）。v1.1.3 用户升级后这 4 条规则会从 DB 消失，需改用 general-mask + 对应预设
- T50 前端 RulesPanel 移除「目标列」显示行，后端 `Rule.field` 字段不动（仍用于 name 规则的目标列绑定语义，只是不在规则信息卡片展示）
- T51 前端 `previewMask` 是后端 `apply_template` 的等价移植（纯前端逻辑，不写 DB），用于规则管理面板内联测试预览；实际脱敏仍由后端 `mask_column` 执行（结果一致）
