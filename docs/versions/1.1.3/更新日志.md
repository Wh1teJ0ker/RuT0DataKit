## 关键设计决策

- **通用模板脱敏算子（参考 v0.8.0 TemplateOp）**：在 `SimpleMasker` 基础上引入 `TemplateParams` 结构（keep_prefix / keep_suffix / mask_char / mask_min_len / min_len / max_len）。`Rule.template: Option<TemplateParams>` 字段用 JSON 存储到 DB `rules.template` 列，避免新增 5 个 typed 列。`masker.rs::mask()` 在 `rule.kind == Mask` 分支内优先检查 `rule.template`：空模板（所有字段 None）→ 不脱敏（透传）；非空模板 → 走 keep_prefix/keep_suffix/mask_min_len + min_len/max_len guard + 重叠处理；无 template → 走旧逻辑（保留首尾各 1），向后兼容。
- **T49 子规则化：4 条独立规则 → 1 条 general-mask + 4 个预设**：原 v1.1.3 T48 落地的 4 条独立规则（`idcard-mask`/`phone-mask`/`birthdate-mask`/`bankcard-mask`）收敛为 `general-mask` 规则的 4 个预设函数（`idcard_preset()`/`phone_preset()`/`birthdate_preset()`/`bankcard_preset()`），不再单独 seed 到 DB。`with_defaults()` 从 7 条降为 4 条（3 name + general-mask）。`general-mask` 持空模板（`TemplateParams::default()`）→ SimpleMasker 视为不脱敏（透传）。前端选预设 → 填充 6 个可编辑参数框 → 执行脱敏时透传 template 给 `mask_column`，或经 `update_rule_template` 持久化到 DB。
- **空模板=不脱敏（透传）**：`TemplateParams::is_empty()` 判断所有字段是否为 None。`general-mask` 默认持空模板 → SimpleMasker 原样返回，承载"未选预设 → 不脱敏"的语义。前端选预设后填充字段 → `is_empty()` 返回 false → 走模板脱敏逻辑。
- **mask_char 优先级改为 `replacement > template.mask_char > 默认 *`**：保留 `mask_column` 命令的 `replacement` 参数语义（临时覆盖），用户在脱敏面板输入框填 `#` 即临时覆盖模板的 `*`；未填则用模板内置 mask_char。
- **mask_column 新增 template 临时参数**：`mask_column(sheet_id, column, rule_id, replacement, template, db)`。前端选预设 → 填充 6 参数 → 透传给 `template` 参数执行脱敏（临时覆盖规则自身 template，不写回 DB）。`update_rule_template` IPC 用于持久化 template 到 DB。
- **DB schema v3→v4：rules 表加 template TEXT 列**：`migrate_v3_to_v4` 用 `PRAGMA table_info(rules)` 检查列是否存在再 ALTER，幂等；`migrate()` 新增链式分支 `Some(2) => v2→v3→v4` 和 `Some(3) => v3→v4`，老用户升级自动补列。`row_to_rule` 读 `template` 列 → `serde_json::from_str` 反序列化为 `TemplateParams`；`upsert_rule` SQL + params 加 `template` 列（None → NULL）。`update_rule_template` 方法单独更新 `template` 列（参数绑定，不拼接 SQL）。
- **seed_builtin_rules 改为"按 id upsert 缺失规则"**：从"只在 count==0 时 seed"改为"遍历内置规则集，对每条 id 不存在的规则 upsert"。这样 v1.1.2 老用户升级 → 启动自动补 seed `general-mask` 规则（持空模板），已存在规则（含用户修改过 pattern/replacement 的）不动，参数不丢。

- **T55c 性别联合校验 = 提取时参数（不落 DB）**：用户决策「手动指定性别列」。不同 sheet 列名不同，性别列不能固化到 `rules` 表 → 不新增 DB schema 列、不改 `Rule` 结构体、不改 `update_rule_extract_config` IPC。性别列作为 `extract_validate_to_new_sheet` IPC 的新可选参数 `gender_col: Option<String>`，前端在提取时从当前 sheet headers 中选择。后端解析为 `gender_col_idx`，读性别列构建 `HashMap<u32,String>` 行号→原值映射，对有效 idcard 候选比对第 17 位推断性别与性别列归一化值：矛盾→`valid=false`+`note="性别不一致: 身份证推断{男/女}，性别列{原值}"`；空值/不可识别→跳过比对，保持 `valid=true`；匹配→保持 `valid=true`。`normalize_gender(s)` 接受中英文（"男"/"male"/"m"/"1"→'男'，"女"/"female"/"f"/"2"→'女'，其他→None 跳过）。非 idcard 规则传 `gender_col=None` 无影响。
- **T55c 末位 X 不影响性别推断**：用户提问「如果存在 x 的情况」。X 是校验码（第 18 位），性别看第 17 位 → X 不影响性别推断。`is_valid_idcard` 接受大写 X 和小写 x（case-insensitive），校验码查表比对时统一大写化。
- **T56 批量多规则 + 两列 [类型, 数据值] 只留有效**：用户要求「提取并校验仅支持单条规则」改为支持批量多规则，且新 Tab 输出格式改为纯两列 [类型, 数据值]（第一列=类型名称，第二列=数据值），只保留有效结果。决策：纯两列，只留有效结果——无效候选不写入新 Tab（但仍保留在返回的 `Vec<ExtractValidateRow>` 供测试断言）；移除单条限制，多选即批量（不加「全选」按钮，用户在多选下拉自由勾选）；类型标签 = 规则名去掉「提取」后缀（结果为空用原名兜底，如「身份证号提取」→「身份证号」、「姓名提取」→「姓名」）；idcard 在批量中时仍显示性别列——`isIdcardExtract = selectedRuleIds.some(id => ruleById[id]?.params?.validator === "idcard")`（去掉 `length === 1` 限制，改 `.some()`），性别不一致的 idcard 判无效被过滤。`extract_validate_to_new_sheet_inner` 签名 `rule_id: &str` → `rule_ids: &[String]`，预编译所有规则正则，核心循环改为双层（外层源行 → 内层规则按 `rule_ids` 顺序），同一行多规则命中 → 多条输出；`any_idcard` 判定性别映射构建（批量含 idcard 即构建，对所有 idcard 候选生效）。`name-extract`（params=None）参与批量，`validate_extracted` 对 `None` 返回 `(true, "")` → 全部写入。`log_operation` params JSON `ruleId: String` → `ruleIds: [String]`。
- **T57 行级多字段校验 vs 列级提取校验（不复用 `extract_validate_to_new_sheet`）**：现有 `extract_validate_to_new_sheet` 是**列级提取**（从单列文本正则提取候选 → 校验 → 写两列 [类型, 数据值]），T57 是**行级校验**（对每行的多个字段列分别校验原值不提取 → 跨字段联合 → 整行按通过/失败分流到两个新 Tab，保留原列不新增列）。两者数据流完全不同（提取 vs 原值校验；单/多列；两列 [类型,数据值] vs 保留原列；单 Tab vs 双 Tab 分流），故新建 `validate_rows_to_two_sheets` 命令，不复用现有提取命令。
- **T57 字段→列映射模型（`FieldColumnMapping`，不落 DB）**：用户的 sheet 列名不固定，字段→列映射不能固化到 DB。IPC 接收 `FieldColumnMapping`（7 个 `Option<String>` 字段→列名映射：username/name/sex/birth/idcard/phone/address，值=列头名，未映射=None=不校验该字段）。前端在 `RowValidatePanel.jsx` 为每个字段类型用 Select（allowClear+showSearch，options 来自当前 sheet headers）选择对应列。跨字段联合校验仅在相关字段都映射时生效（sex vs idcard 需两者都映射；birth vs idcard 需两者都映射）。
- **T57 校验函数为独立函数（不新增 `ExtractParams` 变体）**：`ExtractParams` 是提取规则的参数枚举（绑定 DB rule 记录）。T57 是固定字段校验器，不需要 DB rule 记录，直接用独立函数。在 `func_validator.rs` 新增 `is_valid_username`（纯字母数字，`bytes().all(is_ascii_alphanumeric)`）/`is_valid_sex`（仅"男"/"女"）/`is_valid_birth`（8 位数字）/`is_valid_phone`（11 位 1 开头 + 复用 `check_phone_prefix`）/`is_valid_address`（`OnceLock<Regex>` 缓存，全中文 + 号 1-1500 + 室 101-999），复用已有 `is_valid_idcard`/`idcard_gender`/`check_phone_prefix`/`normalize_gender`。
- **T57 跨字段联合校验（sex vs idcard、birth vs idcard）**：仅当 idcard 字段映射且 idcard 本身通过 `is_valid_idcard` 时才做跨字段。sex vs idcard：`idcard_gender(idcard_val)`（第 17 位奇=男/偶=女）与 `normalize_gender(sex_val)` 比对，矛盾→失败原因"性别与身份证不一致"。birth vs idcard：`idcard_val[6..14]`（YYYYMMDD）== `birth_val`，不一致→失败原因"出生日期与身份证不一致"。idcard 未映射或无效 → 跳过跨字段（sex/birth 仅走单字段校验）。
- **T57 双 Tab 输出保留原列不新增列**：用户要求"保留原有字段，不新增列"。创建两个新 sheet：`{源sheet名}_校验通过` + `{源sheet名}_校验失败`，各写表头（row_idx=0）+ 对应行（从 row_idx=1 起），列数 = headers.len()，列顺序与源 sheet 一致。失败原因**不写入 sheet**（用户要求不新增列），仅在 IPC 返回的 `invalidReasons: Vec<{sourceRow, field, reason}>` 中供前端 summary 消息显示（top 失败原因统计）。
- **T57 双 Tab 不进撤销栈**：`validate_rows_to_two_sheets` 调 `log_operation("validate_rows_to_two_sheets", before_snapshot=None)`，不进撤销栈，撤销=关 Tab，与 `extract_validate_to_new_sheet` / `parse_column_as_json` 一致。
- **T57 `get_sheet_name` DB 方法**：新增 `get_sheet_name(sheet_id) -> Result<Option<String>, DbError>`（`SELECT name FROM sheets WHERE id = ?1` + `params![]` 绑定 + `OptionalExtension`），用于双 Tab 命名 `{源sheet名}_校验通过` / `{源sheet名}_校验失败`。返回 None → 命令报错「sheet 不存在」。
- **T57 DB schema 不变**：不新增表/列，不改 `Rule`/`ExtractParams` 结构体，不改 capabilities/default.json（自定义命令无需注册权限）。所有字段→列映射和手机前缀都是运行时 IPC 参数（不落 DB），不同 sheet 列名不同。
