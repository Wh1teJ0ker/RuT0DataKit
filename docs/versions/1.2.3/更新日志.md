## 修复摘要

v1.2.3 修复 Windows 上导入 pcap 文件失败的问题。根因有三层，分别修复：

1. **`-q` 标志 + 错误分类**（`crates/core/src/pcap/reader.rs`）：tshark 默认把 banner / 捕获信息写到 stderr，Windows 控制台编码下经 `String::from_utf8_lossy` 解码后变成含乱码的错误串，被误判为「解析失败」。修复：命令统一加 `-q` 关闭 banner，使 stdout 纯净为字段、stderr 纯净为错误；spawn 失败 → `DependencyMissing`（提示配置路径/安装 Wireshark）；非零退出 → `Other`（stderr 单行化）；字段无效 → `NotImplemented`（引导升级）；无 HTTP 匹配帧 → 空列表（正常语义）。

2. **自动探测 + 缓存**（`crates/core/src/pcap/detect.rs`）：旧 `resolve_tshark_cmd()` 在用户未显式配置路径时直接回退字面量 `"tshark"`，依赖 PATH 查找。但 Windows 上 Wireshark 默认安装到 `C:\Program Files\Wireshark\` 而**不加入 PATH**，导致 `Command::new("tshark").output()` spawn 失败 → 导入报 `missing dependency: tshark program not found`。修复：`resolve_tshark_cmd()` 在覆盖为 None 时调 `detect_tshark()` 自动探测候选路径（含 Windows 绝对路径），探测结果进程生命周期内缓存（`TSHARK_CACHE`），`set_tshark_path` 改变覆盖时清空缓存。

3. **探测健康检查简化 + `CREATE_NO_WINDOW`**（`crates/core/src/pcap/detect.rs`）：第二层修复后用户反馈「设置页配置路径后仍无法使用」。根因：`probe_tshark` 在 `--version` 之外额外跑 `-q -T fields -e frame.number -r <null>` 健康检查，但 Windows 上 `tshark -r NUL` 因 NUL 不是合法 pcap 文件会导致 tshark 报错退出非 0，且部分版本 stderr 含「not valid」字样被探测逻辑误判为「字段不兼容」→ `probe_tshark` 对有效 tshark 返回 `None` → `detect_tshark` 失败 → 设置页「自动检测」返回 null。修复：`probe_tshark` 简化为仅检查 `--version` 退出 0 + 首行非空，字段兼容性改由实际 pcap 解析时的 `classify_tshark_failure` 兜底。同时新增 `build_tshark_command()` 公共构造器，所有 tshark 子进程统一通过它构造，Windows 上设 `CREATE_NO_WINDOW`（`0x08000000`）标志，避免 GUI 应用 spawn CLI 子进程时弹控制台窗口闪烁。
