# v1.2.3 规划需求

> 修复 Windows 上导入 pcap 文件失败的问题；保持本地数据处理语义、数据库 schema 和既有规则数据兼容。

## 目标

1. Windows 上导入 pcap 文件时 tshark 默认 banner 干扰解析，统一加 `-q` 标志使 stdout 纯净为字段、stderr 纯净为错误，并按 spawn 失败 / 非零退出 / 字段无效分类报错。
2. Windows 上 Wireshark 默认安装到 `C:\Program Files\Wireshark\` 而不加入 PATH，导致 `Command::new("tshark")` spawn 失败。`resolve_tshark_cmd()` 在无用户覆盖时自动探测候选路径（含 Windows 绝对路径），探测结果进程生命周期内缓存。
3. Windows 设置页配置 tshark 路径后仍无法使用。根因：`probe_tshark` 的 NUL 健康检查误判有效 tshark 为不兼容。简化探测为仅 `--version` 退出 0 + 首行非空，字段兼容性由实际 pcap 解析兜底。
4. 所有 tshark 子进程（探测 + 实际解析）统一通过 `build_tshark_command()` 构造，Windows 上设 `CREATE_NO_WINDOW` 标志，避免 GUI 应用 spawn CLI 子进程时弹控制台窗口闪烁。
5. 将应用版本统一升级至 `1.2.3`，完成 Rust/前端构建与测试验收。

## 非目标

- 不修改 CTF `answer/` 标准答案或用户的测试样例删除状态。
- 不改变 `SCHEMA_VERSION=5`，不做数据库迁移。
- 不新增网络服务、云端处理或外部依赖。
- 不改变前端 IPC 契约。

## 验收标准

| 项目 | 验收 |
|---|---|
| tshark 调用 | 命令统一加 `-q`，stdout 为纯字段、stderr 为纯错误；spawn 失败 → `DependencyMissing`，非零退出 → `Other`，字段无效 → `NotImplemented`。 |
| 自动探测 | `resolve_tshark_cmd()` 无覆盖时调 `detect_tshark()` 探测候选路径；探测结果缓存；`set_tshark_path` 改变覆盖时清空缓存。 |
| 探测健康检查 | `probe_tshark` 仅检查 `--version` 退出 0 + 首行非空；不再因 NUL pcap 健康检查误判有效 tshark 为不兼容。 |
| 无窗口 | 所有 tshark 子进程通过 `build_tshark_command()` 构造；Windows 上设 `CREATE_NO_WINDOW`。 |
| 质量门禁 | `cargo test -p ruT0-data-kit-core`、`cargo test -p ruT0-data-kit`、`cargo check --workspace`、`pnpm --prefix frontend build` 通过；版本源均为 `1.2.3`。 |
