# v1.2.2 规划需求

> 修复 SQL 数据源兼容性、规则参数配置与三个工具面板的运行时故障；保持本地数据处理语义、数据库 schema 和既有规则数据兼容。

## 目标

1. 导入常见 MySQL dump 时，兼容 MySQL 专有注释、DDL 选项和反斜杠转义，并保留 SQLite SQL 的既有行为。
2. 地址校验拒绝英文字母，允许用户在规则管理和行级校验中按需限制“号”和“室”的数字范围。
3. 补齐出生日期格式配置、身份证首位为 `0` 的临时提取开关，并保证后端 IPC 与前端设置一致。
4. 修复列操作和加解密面板因缺失 React Form/state 声明导致的白屏。
5. 将应用版本统一升级至 `1.2.2`，完成 Rust/前端构建与测试验收。

## 非目标

- 不修改 CTF `answer/` 标准答案或用户的测试样例删除状态。
- 不改变 `SCHEMA_VERSION=5`，不做数据库迁移。
- 不改变 CSV 导出字段策略或继续调查历史 `compare.py` 结果。
- 不新增网络服务、云端处理或外部依赖。

## 验收标准

| 项目 | 验收 |
|---|---|
| MySQL dump | MySQL 专有语句/选项被安全处理，含 `\\'`、`\\"`、`\\\\` 的 INSERT 可被 SQLite 导入；标准 SQLite SQL 回归通过。 |
| 地址规则 | 旧 `{"validator":"address"}` 可反序列化；英文地址失败；号/室范围在后端、规则管理、行级校验和预览中一致生效。 |
| 规则配置 | 出生日期格式可持久化；身份证首位为 `0` 开关只作本次提取运行时覆盖；IPC 前后端参数一致。 |
| 面板 | ColumnOpsPanel 和 CryptoPanel 初始化各自的 Form 及加载 state，不再引用未声明变量。 |
| 质量门禁 | `cargo test -p ruT0-data-kit-core`、`cargo test -p ruT0-data-kit`、`cargo check --workspace`、`pnpm --prefix frontend build` 通过；版本源均为 `1.2.2`。 |
