# v1.1.0 规划需求

> 本文件为 v1.1.0 版本子文档，范围与任务清单与 [`docs/03-开发任务清单.md`](../../03-开发任务清单.md) 对齐。版本状态口径见 [`docs/04-版本标准.md`](../../04-版本标准.md)。

## 1. 版本定位

v1.1.0 在 v1.0.0 纯框架 shell 之上，交付**数据处理原型三件套**——脱敏 / 校验 / 提取——以及**规则管理基础结构（DB 持久化）**：

- 在 `crates/core` 新增 `processor` 模块（纯逻辑引擎，无 host 依赖），定义 `Masker` / `Validator` / `Extractor` trait 与原型实现，以及 `Rule` / `RuleKind` / `RuleRegistry` 规则管理结构。
- 内置**三条姓名相关规则**（脱敏 / 校验 / 提取各一）：
  - `name-validate`（Validate，pattern=`^[\u4e00-\u9fa5]{2,4}$`，2-4 位中文字符）
  - `name-mask`（Mask，replacement=None，走 `SimpleMasker` 「保留首字符 + 其余 `*`」逻辑）
  - `name-extract`（Extract，pattern=`[\u4e00-\u9fa5]{2,4}`，前端测试时用此 pattern 做正则提取预览）
- 在 Tauri 命令层新增 6 个 IPC（`mask_column` / `validate_column` / `extract_column` / `list_rules` / `toggle_rule` / `update_rule_params`），打通「选列 → 处理 → 回写 / 高亮」端到端链路。
- 规则**持久化到 SQLite**（`rules` 表，`SCHEMA_VERSION=2`），应用重启后规则与参数保留。
- 前端 4 个能力面板从占位提示升级为真实 UI：MaskPanel / ValidatePanel / ExtractPanel / RulesPanel，支持行状态高亮（`masked` / `invalid` / `hit`）。

v1.1.0 **不实现**：撤销栈 / 操作回滚、AI 真实接入、全局搜索、Tools / tshark 集成、PCAP 分析——均推迟至 v1.2+。

## 2. 范围边界

## 3. 验收标准（v1.1.0）

1. `cargo fmt --check` / `cargo clippy --workspace -- -D warnings` / `cargo test --workspace` 全通过（含 processor 模块 + db 层新增单测）。
2. `pnpm build` 前端编译通过，无 lint 报错。
3. 4 个能力面板从占位提示升级为真实 UI：选列 + 执行 → 行状态高亮正确（`masked` / `invalid` / `hit`）。
4. RulesPanel 在 Workbench 主区渲染两栏布局：左侧 240px 规则列表 + 右侧规则详情（名称/描述/类别/可填参数/内联测试）；三条规则（脱敏/校验/提取各一）可见；可填参数保存后持久化到 DB；重启后规则与参数仍在；**无新增规则入口**。
5. 版本号在 4 处（Cargo.toml / tauri.conf.json / package.json / constants.js）一致为 `1.1.0` / `v1.1.0`。
6. `processor` 模块在 `crates/core` 独立，无 host 依赖（`regex` crate 纯 Rust）。
7. DB schema 升级为 `SCHEMA_VERSION=2`，含 `rules` 表；v1→v2 增量迁移幂等。

## 4. 技术约束

- **正则 crate**：`regex = "1"`，纯 Rust 实现，无 native 依赖，不影响 CI / Release。
- **Row 索引映射**：`row_idx=0` 为表头行，数据行从 `1` 开始（由 `data.rs` 导入流固定）。前端 `_rowIdx = (page-1)*pageSize + i + 1`，与后端 `rowIdx` 对齐用于状态高亮。
- **规则持久化**：v1.1.0 规则持久化到 SQLite `rules` 表（`SCHEMA_VERSION=2`）。启动时 `DbManager::seed_builtin_rules()` 在 DB 为空时写入 3 条内置规则；用户可修改可填参数（`pattern` / `replacement`）并通过 `update_rule_params` IPC 持久化；**不提供新增规则能力**（无新增规则 Button / Modal）。
- **内联测试**：validate/extract 的测试在前端用 `new RegExp(pattern)` 做正则预览；mask 的测试调用 `mask_column` 对激活 Sheet 的目标列就地脱敏并高亮。
- **Schema 兼容**：v1→v2 增量迁移（新增 `rules` 表 + 索引，`IF NOT EXISTS` 幂等），不触发备份重建；`operations` 表 `kind` 列已支持 `mask` / `validate` / `extract`；`cells` 表 upsert 语义已具备回写能力。
