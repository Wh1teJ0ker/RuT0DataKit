## v0.7.4 两处 BUG 修复（本版本承载）

### Fix A — `SqlParseInput` 加 `#[serde(rename_all = "camelCase")]`（root cause）

**文件**：`crates/core/src/tools/sql_parse.rs:58-68`

```rust
/// **v0.7.4**：加 `#[serde(rename_all = "camelCase")]`——Tauri v2 `#[command]`
/// 仅对命令顶层参数做 camelCase→snake_case 自动转换，**嵌套结构体字段走
/// 原生 serde**。前端发 `responseBodySize` / `sourceIp`（camelCase），
/// 无此属性则 serde 静默丢弃 → `response_body_size: None` → `probe.rs`
/// `None => return Vec::new()` → 0 探针 → schema 空。v0.7.2 Rust 侧测试
/// 直接构造 struct 字面量（不经 serde）所以全绿但 GUI 从未跑通。
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct SqlParseInput {
    pub sql: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub response_body_size: Option<u64>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub source_ip: Option<String>,
}
```

**根因链**：
1. Tauri v2 `#[command]` 只对命令**顶层参数**做 camelCase→snake_case 自动转换（如 `parse_sql_tool(inputs)` 的 `inputs`）。**嵌套结构体字段走原生 serde**——这是 Tauri v2 的固定行为，不是 bug。
2. 前端 `SqlParseTool.jsx:61-73` `onParse` 与 `PreprocessView.jsx:104-108` `handleBlindAutoExtract` 都构造 `{ sql, responseBodySize, sourceIp }`（camelCase）。
3. `SqlParseInput` 无 `rename_all` → serde 按 snake_case 字段名匹配 → `responseBodySize` 找不到对应字段 → **静默丢弃**（不报错，serde 默认 `deny_unknown_fields` 未设）→ `response_body_size: None`。
4. `crates/core/src/logsign/blind/probe.rs:63` `None => return Vec::new()` —— `extract_blind_probe_with_line` 在 `response_body_size` 为 None 时直接返回空 Vec。
5. 结果：0 探针 → schema 空 → 还原失败。用户在 GUI 里点「盲注自动提取」后跳转 Tools/Sql 但 schema/还原结果为空。

**为什么 v0.7.2 测试全绿但 GUI 从未跑通**：v0.7.2 新增的 core 单测用 struct 字面量 `SqlParseInput { sql, response_body_size: Some(862), source_ip: None }`（snake_case 直构）**绕开了 serde**，所以测试全绿，但实际 IPC 路径（前端 JSON → Tauri → serde → struct）从未跑通。

**独立 serde 验证**（`/tmp/serde_test_proj`）：
```
NoRename   (camelCase input): response_body_size: None, source_ip: None    ← SILENTLY DROPPED
WithRename  (camelCase input): response_body_size: Some(862), source_ip: Some("1.1.1.1")  ✓
```

**系统性风险**：任何 Tauri v2 命令接收嵌套 Rust struct 的字段，若无 `#[serde(rename_all = "camelCase")]`，前端 camelCase 字段会被静默丢弃。本版本仅修 `SqlParseInput` 一处，全量审计推迟（见「不做」）。

### Fix B — `detect_sql_blind_features` 移除 50 截断

**文件**：`src-tauri/src/commands/log.rs:78`

```rust
// v0.7.4：移除 samples 上限 50——盲注二分还原必须拿到全量探针，
// 丢弃第 50 条之后的探针会导致 gap（如缺 110/111 → insufficient_probes）。
// dedup + 全量传给 parseSqlTool，IPC 体积在 Tauri JSON 可控范围内。
for cell in row {
    if cell.is_empty() {  // ← 原为 `if cell.is_empty() || samples.len() >= 50`
        continue;
    }
    ...
}
```

**根因**：用户反馈「盲注自动提取只处理了前 50 列，后续的没有全部处理完整」。50 截断在长 log 上会人为制造 gap → 聚合时 `max_true+1 != min_false` → `insufficient_probes` → 还原失败。dedup 后全量传给 `parseSqlTool`，IPC 体积在 Tauri JSON 可控范围内。

- 放宽 `max_true+1 == min_false` 严格自洽校验（取证工具保守，需独立设计讨论）
