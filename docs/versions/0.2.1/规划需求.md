# v0.2.1 规划需求

## 范围

日志处理切片的语义增强补丁：在 v0.2.0 SQLi 6 类签名引擎基础上，新增 SQLi payload
语义解析（6 类结构化字段提取）+ 原始日志字段还原（query/path/UA 双重 URL 解码 + `+` 解码）。

## 目标

- `parse_query` 解 `+`（form-urlencoded 标准：`+` → space）+ `LogEntry` 新增 `decoded_path`
  / `decoded_query` / `decoded_ua` 字段，供签名引擎与 GUI 直接消费已解码文本。
- `payload_parser` 模块（`crates/core/src/logsign/payload_parser.rs`）：对命中后的 decoded
  payload 做结构化语义解析，产出 `ParsedPayload`（6 类：blind_boolean / union / error / time
  / tautology / comment），含 read_target / char_position / union_columns / sleep_seconds 等
  字段 + 人类可读 `summary`。
- `SignatureHit.parsed_payload: Option<ParsedPayload>`：`scan_log_entry` 产 hit 时自动填充。
- `Finding.extra: Option<serde_yml::Value>`（`skip_serializing_if = "Option::is_none"`，向后
  兼容）：`scan_log` pipeline 把 `parsed_payload` 序列化透传进 `extra`，供前端展示「解析结果」/
  「读取目标」列。
- 6 类签名 pattern 扩变体：`sqli_union` 兼容 `union all select`；`sqli_error_based` 兼容
  `exp(~(select * from dual))` / `floor(rand(0)*2)` 变体。
- GUI LogView findings 表新增「解析结果」/「读取目标」列；原始日志表新增 `decoded_path` /
  `decoded_query` / `decoded_ua` 列。

## 验收

- `parse_query("a=b+c")` → `[("a", "b c")]`（`+` 解为空格）。
- payload_parser 6 类正反例：blind `ascii(substr((database()),1,1))>79` 解出 read_target=
  `database()`；union `1 union select 1,2,3` 解出 union_columns=3；error `extractvalue(1,
  concat(0x7e,user()))` 解出 read_target=`user()`；time `sleep(5)` 解出 sleep_seconds=5；
  tautology `or 1=1` 命中；comment `--` 命中；正常 query 不命中。
- `scan_log_entry` 产出的 sqli hit 携带 `parsed_payload`；`scan_log` 产出的 sqli finding
  `extra` 非空（含 ParsedPayload 序列化）；weak_password finding `extra` 为 `None`。
- GUI LogView 展示「解析结果」/「读取目标」列 + 原始日志表 decoded 三列。
- `cargo test --workspace` 全绿（含新增 e2e：payload_parser 端到端 + decoded_query 还原）。
- 版本号 0.2.0 → 0.2.1（Cargo.toml×3 + tauri.conf.json + frontend/package.json）。
