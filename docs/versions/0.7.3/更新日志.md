# v0.7.3 更新日志

> PreprocessView 新增「盲注自动提取」按钮：扫描全表盲注探针 + 自动从同行 `size`/`ip` 列配对 body_size + source_ip，拼 `body|sql` 文本跳转 Tools/Sql。
>
> 用户诉求（verbatim）：「但是现在无法得到这样的数据，要求需要在数据预处理处加入自动提取的按钮，然后提取并且跳转 `862|username=1'%20or%20ascii(substr((database()),1,1))%3E110%23&password=1`」。

## 根因

v0.7.2 打通了 textarea `body|sql` 前缀解析，但用户**无法手动获得**带 body_size 前缀的数据——需要用户自己知道哪行 body=862、哪行 body=875 并手动加前缀。

实际上 **log 源的 `size` 列就是 HTTP 响应 body 字节数**（`crates/core/src/readers/log_reader.rs:36` HEADERS 含 `size`，`log_reader.rs:58` `e.size.map(|n| n.to_string())`），`ip` 列就是来源 IP。用户导入 log 文件后，PreprocessView 的 records 已包含每行的 body_size 和 source_ip——只是现有的 `detect_sql_blind_features` 命令（`src-tauri/src/commands/log.rs:58-88`）扫描到盲注探针时**丢弃了 body_size 和 source_ip**，只返回 `samples: Vec<String>`（纯 SQL 文本）。

## 方案

扩展 `detect_sql_blind_features` 命令返回结构化 samples（带 body_size + source_ip），在 PreprocessView 段 ④ 跳转区新增「盲注自动提取」按钮，点击后自动扫描全表 → 配对 body_size/ip → 拼 `body|sql` 文本 → 调 `parseSqlTool` → 跳转 Tools/Sql。

**关键设计决策**：
- 扩展既有 `detect_sql_blind_features` 命令（非新增命令）——它已接收 `headers + rows`，已含 URL-decode 逻辑，当前**无任何前端调用方**（v0.5.x 删除了自动跳转入口），改返回形状零破坏
- body_size / source_ip 从同行 `size` / `ip` 列按 header 名定位（非固定下标，兼容列重命名）
- 非 log 源（csv/xlsx/sql/json/txt/pcap）无 `size`/`ip` 列 → body_size=null、source_ip=null → 文本无 `body|` 前缀，向后兼容 `parse_payload` 兜底
- 按 `(sql, body_size, source_ip)` 三元组去重，避免 `query` 列（encoded）和 `decoded_query` 列（decoded）重复收集

## 变更明细

### T27-1 扩展 `detect_sql_blind_features` 返回 body_size + source_ip + 去重 + 测试（P0）

#### ① 返回形状变更（`src-tauri/src/commands/log.rs`）

旧：`{ detected: bool, samples: Vec<String> }`
新：`{ detected: bool, samples: Vec<{ sql: String, body_size: Option<u64>, source_ip: Option<String> }> }`

改造要点：
- 从 `headers` 定位 `size` 列下标（`headers.iter().position(|h| h == "size")`）和 `ip` 列下标
- 外层 `for row in &rows` 循环保留，内层 `for cell in row` 循环
- 命中 `looks_like_blind_probe` 时，从同行取 body_size（`size_idx` 列 cell 解析为 `u64`，空/`-` → `None`）和 source_ip（`ip_idx` 列 cell，空 → `None`）
- 去重：`Vec<(String, Option<u64>, Option<String>)>` 线性扫描，按 `(sql, body_size, source_ip)` 三元组去重
- samples 上限仍 50

#### ② 测试更新

- 更新 3 个既有测试断言新返回形状（`samples[0]["sql"]` / `samples[0]["body_size"]` / `samples[0]["source_ip"]`）
- 新增 `detect_sql_blind_features_carries_body_size_and_source_ip`：构造含 `size` + `ip` 列的 log 源 rows，断言返回的 sample 带 `body_size=Some(862)` + `source_ip=Some("1.1.1.1")`
- 新增 `detect_sql_blind_features_deduplicates`：同一行 `query`（encoded）+ `decoded_query`（decoded）列都含同一探针，断言 samples 去重后仅 1 条
- 新增 `detect_sql_blind_features_no_size_header_body_size_none`：无 `size` 列时 body_size=None
- 新增 `detect_sql_blind_features_size_dash_parses_none`：size 列为 CLF `-` 时 body_size=None

### T27-2 前端 PreprocessView 新增「盲注自动提取」按钮 + tauri.js 注释更新（P0）

#### ① 新增 `handleBlindAutoExtract` 函数（`PreprocessView.jsx`）

紧邻 `handleColumnSqlParse` 之后新增：

```javascript
const handleBlindAutoExtract = async () => {
  if (!records) return;
  try {
    const res = await detectSqlBlindFeatures(records.headers, records.rows);
    if (!res.detected || !res.samples || res.samples.length === 0) {
      message.warning("未检测到盲注探针特征行");
      return;
    }
    const inputs = res.samples.map((s) => ({
      sql: s.sql,
      responseBodySize: s.body_size ?? null,
      sourceIp: s.source_ip ?? null,
    }));
    const text = res.samples
      .map((s) => (s.body_size != null ? `${s.body_size}|${s.sql}` : s.sql))
      .join("\n");
    const result = await parseSqlTool(inputs);
    dispatch({ type: "SET_SQL_PARSE_INPUT", sqlParseInput: text });
    dispatch({ type: "SET_SQL_PARSE_RESULT", sqlParseResult: result });
    dispatch({ type: "SET_VIEW", activeView: "tools" });
    dispatch({ type: "SET_TOOLS_ACTIVE_TAB", toolsActiveTab: "sql" });
  } catch (e) {
    showError(`盲注自动提取失败: ${e}`);
  }
};
```

- import `detectSqlBlindFeatures`（已在 `tauri.js:223` 导出，当前 PreprocessView 未引入）

#### ② UI 按钮（段 ④ 跳转区）
