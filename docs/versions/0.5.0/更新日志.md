## 变更明细

### T12-1 blind_aggregator 拆分（P0）

- `crates/core/src/logsign/blind_aggregator.rs`（1790 LOC / 58 函数）→ 删除，内容迁移到 `logsign/blind/` 子目录：
  - `blind/mod.rs`：模块入口 + pub use 重导出（AggregatedResult / BlindAggregator / BlindProbe / PositionDetail / ProbeKind / ReconstructedDatabase / ReconstructedRow / ReconstructedTable / extract_blind_probe / extract_blind_probe_with_line）
  - `blind/probe.rs`：`looks_like_blind_probe` / `extract_blind_probe*` / `ProbeKind` / `BlindProbe` + 3 个正则缓存（ascii_binary / equality / length）
  - `blind/aggregate.rs`：`BlindAggregator` struct + `collect_from_entries` + `aggregate_*_group` / `aggregate_position` / `aggregate_equality_position` / `build_decoded_string` / `mode_per_position_true_size` + `PositionDetail` / `AggregatedResult`
  - `blind/reconstruct.rs`：`ReconstructedDatabase` / `ReconstructedTable` / `ReconstructedRow` + `reconstruct_database` + `parse_table_name_predicate` / `parse_from_table` / `parse_row_data_columns` / `build_table_columns_and_rows` + 3 个 read_target 正则缓存
- `logsign/mod.rs` 的 `pub mod blind_aggregator` → `pub mod blind`，pub use 路径调整（新增 `looks_like_blind_probe` 重导出，原 `blind_aggregator::looks_like_blind_probe` 路径不再可用，src-tauri `commands.rs` 改走 `logsign::looks_like_blind_probe`）。
- 拆分实测 LOC：`blind/mod.rs` 150 / `blind/probe.rs` 401 / `blind/aggregate.rs` 813 / `blind/reconstruct.rs` 575；`blind_aggregator.rs` 已删除。
- 验证：`cargo build --workspace` 0 error；`cargo test --workspace` 全绿（446 passed，基线 445 + 新增 1 个 mk_entry 编译占位测试）。
- 行为零回归：未改任何函数实现逻辑、算法、正则字符串；跨文件 helper 用 `pub(super)`：`probe::ascii_binary_regex / equality_regex / length_regex`、`reconstruct::parse_separator_char`。

### T12-2 commands.rs 拆分（P0）

- `src-tauri/src/commands.rs`（1173 LOC / 32 命令）→ 删除，内容迁移到 `src-tauri/src/commands/` 目录：
  - `commands/mod.rs`：模块入口 + `source_type_name` 共享 helper + pub use 重导出全部 32 命令
  - 10 个领域子文件：file.rs / mask.rs / validate.rs / export.rs / ruleset.rs / log.rs / pcap.rs / extract.rs / search.rs / tools.rs
- `main.rs` 的 `mod commands;` 声明不变（文件模块 → 目录模块自动生效），`commands::<name>` 引用路径不变。

### T12-3 operator.rs 拆分（P1）

- `crates/core/src/rules/operator.rs`（976 LOC / 41 函数）→ 删除，内容迁移到：
  - `rules/mask_op.rs`：`MatchMode` + `TemplateOp` / `SplitTemplateOp` / `RegexReplaceOp` / `ConstReplaceOp` + `MaskOp` enum + `apply_mask_op` + `apply_template` / `apply_split_template` / `apply_regex_replace` + `*_from_params` + `parse_match_mode` / `parse_usize` / `parse_bool` helpers
  - `rules/validate_op.rs`：`AlgoKind` / `GuardKind` + `RegexOp` / `AlgorithmOp` / `RegexWithGuardOp` + `ValidateOp` enum + `from_rule` + `apply_validate_op` + `apply_regex` / `apply_algorithm` / `apply_regex_with_guard`
- `rules/mod.rs` 的 pub use 声明调整，外部消费者 import 路径不变。

### T12-4 patterns.rs 集中正则（P1）

- 新建 `crates/core/src/rules/patterns.rs`：8 种 scope（idcard/phone/bankcard/email/ip/mac/username/name）的 extract + validate 正则成对集中定义。
- `scan/mod.rs::extract_pattern` 改查 `patterns::extract_pattern(scope)`。
- `validators/phone.rs` 硬编码 `^1\d{10}$` → `patterns::scope::PHONE.validate`。
- `validators/ip.rs` 改引用 patterns.rs。
- `rules/validate_op.rs`（T12-3 产出）RegexWithGuard phone 守卫正则改引用 patterns.rs。
- `presets.rs` 的 9 个正则常量迁移到 patterns.rs（presets.rs 删除或改 re-export 兼容层）。

### T12-5 前端 state 切片（P2）

- `frontend/src/state.js`（385 LOC / 29 action）→ 保留单 useReducer，内部按 11 领域分组为子函数（fileDomain / maskDomain / validateDomain / logDomain / pcapDomain / rulesDomain / searchDomain / toolsDomain / extractDomain / settingsDomain / exportDomain）。
- 29 个 action type 抽 `ACTION` 常量对象（字符串值不变，组件 dispatch 零改动）。

### T12-6 ColumnRuleMapper 公共组件（P2）
