## 变更明细

### T20-1 字段重命名 state 级联 + PreprocessView 表头编辑 UI + 数据源指示（P0）

#### ① state.js — 新增 COLUMN_RENAME_SET action + 级联 re-key

- **`frontend/src/state.js`** ACTION 对象新增 `COLUMN_RENAME_SET: "SET_COLUMN_RENAME"`。
- `fileDomain` 新增 `case ACTION.COLUMN_RENAME_SET`：
  - 载荷 `renames: [{ oldName, newName }]`，支持批量。
  - 构建 `Map<oldName, newName>`（过滤掉空值与同名）。
  - 真实改写 `state.records.headers`（`map(remapKey)`）。
  - 级联 re-key 所有 header-keyed 状态切片：
    - `selectedColumns` / `columnOrder` / `exportColumns`（数组元素 remap）
    - `maskOverrides` / `validateOverrides`（对象 key remap + value.field remap）
  - 清空 `maskedRows` / `maskedSummary` / `validateResult`（headers 变了，旧脱敏/校验结果不再对齐，需重新运行）。
- **全局规则不改**：`state.rules.validators/maskers[].field` 是跨会话的全局规则库，重命名**不**自动改写其 `field`——若某 preset 的 `field` 在改名后不再匹配新 headers，需用户在 RulesView 重新应用 preset。这是合理流程：重命名是结构性变更，preset 重新应用是预期操作。

#### ② PreprocessView.jsx — 表头可编辑 + 数据源指示

- **单字段重命名**：预览表每个列标题渲染为 `<Space><span>{h}</span><Button type="text" size="small" icon={<EditOutlined />} onClick={() => handleRenameOne(h)} /></Space>`。点击弹 `Modal.confirm`（内含 `Input`，默认值=原表头），确认后 dispatch `SET_COLUMN_RENAME { renames: [{ oldName, newName }] }`。
- **批量重命名**：预览 Card 右上 `extra` 区加「批量重命名」按钮（`DiffOutlined`，无 records 时 disabled），弹 Modal 列出全部 headers 与对应 `Input`（左 disabled 原名、右可编辑新名），点「应用重命名」一次性提交多个 rename（只取改了的字段）。
- **数据源指示 Tag**：导入 Card 顶部加 `Tag color="geekblue"` 文案「数据源：预处理流」，明确此视图消费 `state.records`（与 ExtractView 提取流独立，不串扰）。

#### ③ ExtractView.jsx — 数据源指示 Tag

- 输入 Card 顶部加 `Tag color="geekblue"` 文案「数据源：提取流（与预处理流独立，不共享 records）」，明确此视图走 `extractInput` / `extractResult` 独立链路（`std::fs::read_to_string` → 文本扫描），不消费 `state.records`。

#### ④ docs/01-页面与交互说明.md — 补充重命名交互规范

- PreprocessView 界面 1 处补充：表头可编辑（✏ 按钮 + Modal.confirm）、批量重命名（Modal 列出全部 headers + Input）、重命名级联影响（selectedColumns/columnOrder/exportColumns/maskOverrides/validateOverrides + 清空 maskedRows/maskedSummary/validateResult）、全局 rules.validators/maskers[].field 不改（preset 重新应用）、数据源指示 Tag。
- ExtractView 界面 9 处补充：数据源指示 Tag 文案与含义。
