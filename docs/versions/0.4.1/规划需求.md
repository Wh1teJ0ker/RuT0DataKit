# v0.4.1 规划需求

## 范围

**5 项缺陷修复**：针对 v0.4.0 发布后用户反馈的 5 个问题做定向修复，不引入新功能模块，不破坏 v0.4.0 架构契约。

## 用户原始诉求（5 条，逐字保留）

1. **数据流没有打通**：严格检查是否遵守从数据预处理到之后的工作流，数据预处理导入后，在搜索界面无法搜到。
2. **每一个界面上方不应该有导入文件的按钮**。
3. **Tools 页面应该是一个下拉栏，不是横版标签**。
4. **如果在数据预处理的时候解析到了 SQL 盲注的特征，自动跳转到对应的工具页面**。
5. **优化正则解析工具**：不是要求内置模版，而是给出一个语句，能自动化帮用户构造正则。

## 目标

### 1. 数据流打通（T6-1）

- 根因：`ExportView` 读 `state.filePath`（SET_FILE 通道），而 `PreprocessView.handleImport` 只写 `state.records`（SET_RECORDS 通道），两条通道不交叉导致导出「原始数据」永远 disabled。
- 修复：`ExportView` 迁移到读 `state.records`，`computeExportArgs` fallback 到 records 作为后端 inputPath。
- 验证：新增 e2e `preprocess_to_search_finds_hits`（csv → read_records → search_records Keyword 命中）。

### 2. 移除各界面 FileToolbar（T6-2）

- 删除 `frontend/src/components/FileToolbar.jsx`。
- `App.jsx` 移除 `NO_TOOLBAR_VIEWS` 集合与 `<FileToolbar/>` 渲染分支。
- 导入唯一入口收敛到 `PreprocessView` 内置导入按钮（v0.4.0 设计本意）。

### 3. ToolsView 下拉栏（T6-3）

- `ToolsView` 由 antd `Tabs`（横版标签）改为 antd `Select`（下拉栏）。
- `options=[{value:"sql",label:"SQL 解析"},{value:"regex",label:"正则解析"}]`。
- `onChange` dispatch `SET_TOOLS_ACTIVE_TAB`，默认 sql fallback。

### 4. SQL 盲注特征自动跳转（T6-4）

- core `looks_like_blind_probe(sql: &str) -> bool`：复用 `ascii_binary_regex` / `equality_regex` / `length_regex` 三类正则，不依赖 `response_body_size`（区别于 `extract_blind_probe`）。
- Tauri `detect_sql_blind_features(headers, rows) -> {detected: bool, samples: Vec<String>}`：迭代所有 cell，命中收集最多 50 条样本。
- GUI `PreprocessView.handleImport` 在 `SET_RECORDS` 后调用，命中即 `SET_VIEW("tools")` + `SET_TOOLS_ACTIVE_TAB("sql")` + `SET_SQL_PARSE_INPUT(samples.join("\n"))` + `message.success` 提示。
- 仅本地正则匹配，**不外发数据**。

### 5. RegexTool 语句→构造正则（T6-5）

- 移除内置模板 Tab（`TemplateTab` + `ParamInput` + `generate_regex` / `list_regex_templates` Tauri 命令 + `regexTemplateSelected` / `regexTemplateParams` / `regexGenerated` state 字段）。
- 新增 `ConstructTab`：antd `TextArea` 语句 → `regexConstruct(statement)` → `pattern` `Paragraph` copyable + `matched_clues` `Tag` 列表 + 测试样例高亮复用 `highlightMatches` + `adaptRegexForJs`。
- core 新增 `crates/core/src/tools/regex_construct.rs::construct_regex(statement: &str) -> Result<ConstructedRegex, CoreError>`，规则化推断 6 类线索（位数 / 字符集 / 锚定前缀 / 邮箱 / URL / 身份证），语义优先级 邮箱 > URL > 身份证 > 通用，末尾 `Regex::new` 校验保证 pattern 可编译。
- `ConstructedRegex { pattern, explanation, matched_clues }`。
