# v1.2.0 规划需求

> 本版本是「架构升级」版本，不以新增用户功能为目标，而以**可维护性**为核心：拆分过大模块、消除重复代码、清理临时文件、精简前端 UI 描述。

## 1. 版本目标

| 目标 | 描述 |
|---|---|
| 后端模块拆分 | `commands/processor.rs`（3172 行）→ 按职责拆为 rules_ops / mask_ops / extract_ops / undo_ops 子模块；`db/mod.rs`（2685 行）→ 按领域拆为 cells / sheets / rules / search / operations 子模块；`core/processor/rules.rs`（1501 行）→ 按类型拆为 template / extract_params 子模块 |
| 前端 UI 文案优化 | 所有面板描述精简为简洁清晰的一句话；移除冗余解释、行话堆砌、多行 footer |
| 前端模块架构优化 | 抽出共享 hooks（useColumnData）与共享 UI 原语（ColumnSelect / PhonePrefixSelect / RefreshUndoBar）；消除 MaskPanel ↔ RulesPanel 模板编辑器重复 |
| 临时文件清理 | 删除 `STARTER.md`、6 个旧版 `RELEASE-NOTES.md` / `RELEASE-BODY.md`；归档 79 个 handoff/archive 临时文件 |

## 2. 范围

### 本期做

- **后端重构**：纯结构拆分 + 测试迁移，不改外部行为（IPC 签名、DB schema、返回 JSON 均不变）
- **前端重构**：共享抽象 + 文案精简，不改交互逻辑
- **清理**：删除无引用的临时/遗留文件

### 本期不做（out of scope）

- 不新增 IPC 命令
- 不修改 DB schema（SCHEMA_VERSION 保持 5）
- 不改 `core` 对外 trait 签名
- 不引入新依赖 crate
- 不做 tshark / PCAP / 真实 AI 能力（属 v1.3.0 / v1.4.0）
