# v0.6.8（修订）更新日志

> 手机号规则（提取 phone + 校验 pinfo_phone）统一支持自定义前 1-3 位号段，缺省默认 1 开头正常号码。
>
> 用户诉求（verbatim）：「数据提取的phone可以支持自定义前缀三位，如果没有就默认1的正常号码，数据校验的也是支持自定义前缀三位，如果没有就默认1的正常号码，你刚刚默认的52是不正确的 这个还是0.6.8版本，完成后推送」
>
> 本修订版覆盖上一轮 v0.6.8 的错误实现（上一轮默认 52 虚假号段不正确，用户明确反馈），保持版本号 0.6.8 不 bump。核心架构决策：**统一 `phone` 与 `pinfo_phone` 两个 scope**，均路由到 `PhoneValidator`，缺省走 `^1\d{10}$`（1 开头正常号码），`params.prefixes` 提供时则按自定义前 1-3 位号段集合匹配。删除 `PInfoPhoneValidator`。

### T23-1 Rust 后端：PhoneValidator 扩展 prefixes + 统一 pinfo_phone（P0）

#### ① `crates/core/src/validators/phone.rs`（重写）

`PhoneValidator` 扩展为支持 `params.prefixes`（前 1-3 位号段集合）：

```rust
pub struct PhoneValidator {
    re: Regex,                          // ^\d{11}$ 基础长度校验
    prefixes: Option<HashSet<String>>,  // None=默认 1 开头；Some=前 1-3 位号段集合
}

impl PhoneValidator {
    pub fn new(params: HashMap<String, Value>) -> Self {
        let prefixes = params.get("prefixes")
            .and_then(|v| v.as_sequence())
            .map(|seq| seq.iter()
                .filter_map(|x| x.as_str().map(|s| s.trim().to_string()))
                .filter(|s| !s.is_empty())
                .collect::<HashSet<String>>())
            .filter(|s| !s.is_empty());
        Self { re: Regex::new(r"^\d{11}$").expect("valid regex"), prefixes }
    }
}

impl Validator for PhoneValidator {
    fn validate(&self, value: &str) -> ValidationResult {
        let v = value.trim();
        if !self.re.is_match(v) {
            return ValidationResult::fail("phone must be 11 digits");
        }
        match &self.prefixes {
            None => {
                // 缺省：1 开头正常号码
                if v.starts_with('1') { ValidationResult::ok() }
                else { ValidationResult::fail("phone must start with 1") }
            }
            Some(set) => {
                // 自定义前 1-3 位：任一 prefix 是 v 的前缀即合法
                if set.iter().any(|p| v.starts_with(p.as_str())) { ValidationResult::ok() }
                else { ValidationResult::fail("phone prefix not in allowed set") }
            }
        }
    }
}
```

新增 11 个单测：缺省（138... valid / 238... invalid）、自定义 prefixes（734/138 valid / 159 invalid）、空 prefixes 等同缺省、非 11 位、非数字、空、纯空白 prefixes 等同缺省、whitespace trim。
