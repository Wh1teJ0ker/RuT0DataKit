# v0.2.2 规划需求

## 范围

日志处理切片的盲注聚合还原补丁：在 v0.2.1 SQLi payload 单条语义解析基础上，新增
跨 entry 布尔盲注二分序列聚合还原，把同一 `(read_target, source_ip)` 的多行二分探针
按 `char_position` 聚类，还原出被盲注读取的完整字符串（如 `database()`、
`table_name`、`column_name`），并以 GUI 卡片形式展示。

## 目标

- `blind_aggregator` 模块（`crates/core/src/logsign/blind_aggregator.rs`）：对一批
  `LogEntry` 跑自带正则抽取 `ascii(substr((<read_target>),N,1))<cmp><thr>` 形态的
  二分探针，按 `(read_target, source_ip)` 分组 + `char_position` 子分组，基于
  `LogEntry.size`（HTTP 响应 body 字节数）自动聚类真假方向（fixture 验证后写死
  `true_size = min(body_size)`），还原每个位置的 ascii 字符，按位置升序拼接出完整
  字符串，首个 `beyond_end` 即停止拼接。
- `BlindProbe` / `PositionDetail` / `AggregatedResult` 结构化字段：read_target /
  char_position / threshold / body_size / source_ip / line_no / decoded_char /
  ascii_val / true_size / probe_count / status / decoded_string / resolved_chars /
  unresolved_chars / beyond_end_positions / position_details。
- `Report.extra` 由 v0.2.1 的 `Value::Null` → `Value::Mapping({blind_aggregation: [...]})`
  透传 `Vec<AggregatedResult>`（向后兼容：旧前端读 extra 为 null 不受影响）。
- 自带嵌套正则 `read_target` 用 `(?:[^()]|\([^()]*\))*` 吃掉单层 `(...)`（regex crate
  无 look-around，单层嵌套支持，多层嵌套是已知简化）。
- GUI LogView 新增「盲注聚合结果」卡片（段 ③.5）：每行一个 read_target 的还原串 +
  探针数 + 来源 IP + 位置明细 Tooltip，空态 antd `Empty`。

## 未实现 / 遗留（v0.2.2 不交付）

- 时间盲注聚合还原（基于响应时延聚类）留 v0.3.0+。
- UNION 报错聚合还原（基于 union_columns 跨行对齐）留 v0.3.0+。
- `blind_aggregator` 的 `true_size = min(body_size)` 方向是 fixture-specific 假设；
  若未来接入「条件成立 → body 更大」的靶机，需把取法从 `min` 改为 `max`（已在
  模块注释中标注，留后续）。
- 多层嵌套 `read_target` 正则不支持（regex crate 无 look-around，已知简化）。
