# v0.2.4 规划需求

## 范围

日志扫描盲注切片的「聚合结果数据库格式还原」补丁：在 v0.2.3 跨 entry 布尔盲注二分序列
聚合还原（`blind_aggregation` 数组 + 每条 `AggregatedResult.decoded_string`）的基础上，
把分散的 4 类标准 read_target 还原串交叉关联，重建出结构化 `ReconstructedDatabase`
（schema → tables → 全量列 columns → rows），GUI 用 antd Table 按表展示，未 fetch 列
留空单元格。同时保留 v0.2.3 的逐 read_target 卡片作为「原始聚合明细」兜底，满足非标准
CTF 日志的可读性。

## 目标

- **后端结构 + 算法（T4-1）**：
  - `crates/core/src/logsign/blind_aggregator.rs` 新增 3 结构：
    `ReconstructedDatabase { schema, tables, unmatched_results }` /
    `ReconstructedTable { name, columns, rows, row_data_columns, column_separator, source_probe_count }` /
    `ReconstructedRow { cells: Vec<Option<String>> }`（与 `columns` 等长，未 fetch 列 `None`）。
  - 新增关联函数 `BlindAggregator::reconstruct_database(&[AggregatedResult]) -> ReconstructedDatabase`：
    - **Step 1 分类**：对每个 `AggregatedResult` 按 `read_target` 模式分 4 类：
      `schema`（`database()`）、`table_list`（`group_concat(table_name) from information_schema.tables`）、
      `column_list`（`group_concat(column_name) from information_schema.columns where table_name='X'`）、
      `row_data`（`group_concat(col1,0xNN,col2,...) from <table>`，非前三类）；未匹配进 `unmatched_results`。
    - **Step 2 拼装**：schema 直填；对 `table_list` 解码出的每个表名 `T`，
      按 `table_name='T'` 谓词匹配 `column_list`（无谓词按索引对齐）→ `columns` 全量列
      （无列清单 → `columns = row_data_columns` 兜底）；按 `from T` 匹配 `row_data` → 解析 rows。
      rows 解析：`decoded_string` 按 `,` split 行（group_concat 默认行分隔符）→
      每行按 `column_separator`（`0xNN` 解码）split 列 → 映射到 `row_data_columns → value` →
      投影到 `columns` 全量列，未 fetch 列 `None`。
    - **Step 3 unmatched**：未匹配的 `AggregatedResult` 原样塞 `unmatched_results`，前端兜底渲染。
  - 分类正则：`table_name\s*=\s*'([^']+)'` 谓词、`from\s+(\w+)` 表名、
    `group_concat\s*\(([^)]*)\)` 列清单、`0x([0-9a-fA-F]{2})` 分隔符（复用现有
    `parse_separator_char` 取首个）。
  - `crates/core/src/logsign/mod.rs` re-export 3 新结构。
  - 单测 8 条：4-RT fixture 全还原（schema="person" / 1 表 person_data / 7 列 / 2 行 /
    row[0].cells=[Some("1"),Some("zhangsan"),None,None,None,Some("IDCARD1"),None]）、
    unmatched 收集、缺 column_list 时 columns 兜底 row_data_columns、空 results、
    无分隔符单列 row、3 个正则单元测试。
- **pipeline 集成（T4-2）**：
  - `crates/core/src/pipeline/log_scan.rs` `scan_log` 末尾调
    `BlindAggregator::reconstruct_database(&blind_results)`，结果塞 `Report.extra`
    新键 `reconstructed_database`（与既有 `blind_aggregation` 并列，向后兼容 v0.2.3）。
  - `crates/core/tests/e2e.rs` `log_scan_full` 新增断言：`report.extra` 含
    `reconstructed_database` 键、schema=="person"、tables 含 name=="person_data" 且
    columns 含全 7 列、rows ≥2 行、row[0].cells[id]==Some("1")、row[0].cells[username]
    contains "zhangsan" 或 "lisi"、row_data_columns 含 id/username/idcard、
    column_separator=="~"。
- **GUI 显示（T4-3）**：
  - `frontend/src/components/LogView.jsx` 在段 ③.5 之前插入段 ③.5a「还原数据库视图」Card：
    - 顶部 `Descriptions`：数据库名（schema `<Text code>`）+ 表数 + unmatched 数。
    - 每张 `ReconstructedTable` 一个 inner Card：title=`<Text code strong>{table.name}</Text>` +
      列/行数 Tag；body = antd `Table`，columns 由 `table.columns` 映射（title=列名，dataIndex=列名），
      dataSource 由 `table.rows` 映射（每行 object，键=列名，未 fetch 列 undefined），
      未 fetch 单元格 `render: v => v ?? <Text type="secondary">-</Text>`；extra =
      `column_separator` volcano Tag + `row_data_columns` Tooltip（已 fetch N/M 列）+ 探针 Tag。
    - unmatched_results 非空：`Divider` + 简版列表（read_target + decoded_string copyable）。
    - 空态：`reconstructedDb == null || tables.length === 0` → `<Empty description="无法还原为数据库结构" />`。
  - 段 ③.5 既有逐 RT 卡片（kind Tag / renderDecodedString / Collapse+Table 位置明细）保留，
    Card title 改为「原始聚合明细」作兜底，数据源 `blindAggregation` 不动。

## 未实现 / 遗留（v0.2.4 不交付）

- `group_concat SEPARATOR 'X'` 子句解析：当前仅支持默认行分隔符 `,` 与 `0xNN` 列分隔符；
  若某列值含 `,` 会导致行切错（fixture idcard 为数字无 `,`，已知简化），留 v0.2.5+。
- 多表多列清单对齐：fixture 单表 person_data，多表场景需按 `table_name='T'` 谓词匹配，
  无谓词时按索引对齐（当前实现支持，但 fixture 未覆盖）。
- 三层及以上嵌套 `group_concat` 列清单正则不支持（`[^)]*` 对无嵌套够用；regex crate
  无 look-around，已知简化）。
- UNION 报错聚合还原 / 时间盲注聚合留 v0.3.0+。
