# v0.4.4 规划需求

## 范围

**规则引擎三步重构**：删除添加规则 UI + 删除规则模版 → 重构规则引擎字段 → 引入 tag（用途）+ scope（数据类型）双维度。

1. **删除添加规则 UI + 规则模版**（T11-2 部分）：删除 `frontend/src/components/RuleDrawer.jsx`、`RuleForm.jsx`（及相关已被删除的 `RulesPanel.jsx` / `RuleDocPanel.jsx` / `ParamField.jsx` / `maskerDefs.js` / `validatorDefs.js`）；删除 `rules/default_mask.yaml` 与 `rules/custom_example.yaml` 两个预置模版文件；移除 `load_default_mask_ruleset` / `list_tagged_presets` / `list_mask_op_types` / `list_validate_op_types` 等旧 API。规则改为代码内部维护（`builtin_ruleset()`），不依赖 YAML 文件，暂不重建添加规则入口。
2. **重构规则引擎字段**（T11-1/T11-3）：`FieldRule` / `MaskRule` 由旧字段（`validator` / `masker` / `regex` / `tags: Vec<String>`）迁移为新 schema `{ field, scope, tag, params, message, description }`。`tag` 为单值字符串（"extract" | "mask" | "validate"），`scope` 为数据类型（idcard / phone / bankcard / email / ip / mac / username / name / custom）。算子模型 `MaskOp`（template/split_template/regex_replace/const_replace）+ `ValidateOp`（regex/algorithm/regex_with_guard）走 `from_rule`，`scope` 同时作为 `ValidatorRegistry` / `MaskerRegistry` 查键 + `scan::extract_pattern` 查键。
3. **添加规则标签（tag）筛选**（T11-3）：`list_rule_tags` 命令返回静态三选一 `["extract","mask","validate"]`；`RulesView.jsx` 与 `ExtractView.jsx` 顶部 Select 按 tag 过滤规则列表；`RuleSet::by_tag` / `by_tag_mask` 单值匹配。
4. **添加规则范围（scope）**（T11-1）：`scan::extract_pattern(scope)` 查表覆盖 8 种数据类型 → `find_iter` 候选 → `build_validator(rule, &reg).validate()` → 仅 valid==true 记 finding。`Finding.type` 统一填 `rule.scope`，不再有 field/validator 二义。
5. **内置规则加载**（T11-3）：`builtin_ruleset()` 在代码中维护出厂规则（phone/bankcard/ip 提取）；`list_builtin_rules` Tauri 命令序列化 `RuleSet` 为 JSON；前端 `App.jsx` 启动时 `useEffect` 调 `listBuiltinRules()` → `dispatch SET_RULES` 写入 `state.rules`，RulesView/ExtractView 自动显示内置规则。
