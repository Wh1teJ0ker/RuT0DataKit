## 变更明细

### T21-1 ExtractView 类型重命名（P0）

#### 用户诉求

数据提取结果里 `name` / `idcard` 等英文 type 应可批量替换为中文。原本 ExtractView 完全没有 type 重命名功能，CSV/JSON 字段区只能勾选/调序 type/value 两列，无法改值。

#### 设计决策（用户回执）

- **生效范围**：结果表显示 + 导出都替换（所见即所得）。
- **映射列出方式**：自动从当前 findings 取所有不同 type 列出（动态，换一批数据自动重刷）。
- **高频标记**：count ≥ 5 的 type 加 ★ 提示「可能需要重命名」（非强制）。
- **持久化**：不持久化（每次新结果载入重建，关掉即丢）。

#### 前端 `frontend/src/components/ExtractView.jsx`

- 新增 `typeRename` useState（key=原 type，value=新名）。
- `useEffect`：结果出现时从 `extractResult.findings` 去重取全部 type，按高频在前排序后构建 `typeRename` 映射（值初始化为空串）。
- 结果 Card 顶部加「类型重命名」区：每个 type 一行 `Tag（带 ★ 高频标记 + count） → Input`，placeholder 给中文建议（phone→电话 / idcard→身份证 / name→名字 / bankcard→银行卡 / email→邮箱 / ip→IP 地址 / mac→MAC 地址 / username→用户名）。
- 结果表 `columns` 的 type 列 `render` 改为：填了中文名显示「中文名（原 type）」（原名小字），未填显示原 type。
- 顶部计数 Tag 同步显示「中文名（原 type）」。
- `handleExport` 把非空 `typeRename` 透传给 `exportExtract`。

#### 前端 `frontend/src/tauri.js`

- `exportExtract(findings, format, outPath, opts = {})` opts 增加 `typeRename` 字段透传给后端 `export_extract` 命令的 `typeRename` 参数。

#### 后端 `src-tauri/src/commands/export.rs`

- `export_extract` 签名新增 `type_rename: Option<std::collections::HashMap<String, String>>`。
- 新增 `rename_type` 闭包：命中即替换，空值/缺省回退原 type。
- txt 分支：`{type}` 占位符替换为重命名后的值。
- csv/json 分支：type 列单元格值替换为重命名后的值（表头仍为 "type"）。
- 缺省或映射为空时回退原 type（向后兼容）。

## 安全约束（不变）

全本地处理，不外发数据。类型重命名纯前端 state + 后端导出渲染，不涉及网络/外发。`export_extract` 仅写本地文件 `std::fs::write`。与 `docs/00-需求文档.md §6`「不外发数据：全本地处理；规则与样本不上传」约束一致。

## 向后兼容

- `export_extract` 新增 `type_rename` 参数为 `Option<HashMap<String, String>>`，缺省时回退原 type，旧调用方不传新参数仍正常工作。
- `exportExtract` opts 新增 `typeRename` 字段，缺省 `null`，旧调用方不传仍正常。
- `typeRename` state 不持久化，每次新结果载入重建——不污染跨会话状态。
