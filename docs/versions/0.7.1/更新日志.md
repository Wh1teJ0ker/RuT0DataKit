# v0.7.1 更新日志

> SQL 解析路径（`parse_sqls` + `detect_sql_blind_features`）自动识别 URL-encoded 输入并解码。
>
> 用户诉求（verbatim）：用户报告 URL-encoded SQLi payload（如 `username=1'%20or%20ascii(substr((database()),1,1))%3E79%23&password=1`）解析失败，要求「自定识别这种未解码的，开始关于v0.7.1的pacth」。
>
> 用户确认的设计决策（AskUserQuestion）：① 修复范围=两处都修（core `parse_sqls` + Tauri `detect_sql_blind_features`，同一根因）；② 解码策略=检测到才解码（正则 `(?i)%[0-9a-f]{2}` 检测，命中才调 `url_decode_twice`，对已解码输入零影响，向后兼容）。

## 根因

用户样本 `username=1'%20or%20ascii(substr((database()),1,1))%3E79%23&password=1` 是 URL-encoded 形态。`parse_sqls` → `extract_blind_probe` / `parse_payload` 用纯文本正则匹配，期望字面空格 ` ` 和 `>`，遇到 `%20` / `%3E` / `%23` 匹配失败 → 0 探针 → "解析失败"。

同一根因也影响 `detect_sql_blind_features`（T6-4 导入时盲注自动跳转）：raw cell 直接喂 `looks_like_blind_probe`，URL-encoded cell 不命中 → 自动跳转失效。

## 变更明细

### T25-1 双调用点 URL-decode-on-detection + 单测（P0）

#### ① 新增 helper（`crates/core/src/log/mod.rs`，紧邻 `url_decode_twice` 之后）

```rust
/// 检测字符串是否含 URL 编码序列 `%XX`（XX 为合法 hex）（v0.7.1）。
pub fn looks_like_url_encoded(input: &str) -> bool {
    use std::sync::OnceLock;
    static RE: OnceLock<Regex> = OnceLock::new();
    RE.get_or_init(|| {
        Regex::new(r"(?i)%[0-9a-f]{2}").expect("url-encoded detector regex must compile")
    })
    .is_match(input)
}
```

- 复用既有 `regex::Regex`（文件顶部已 `use regex::Regex;`），零新依赖
- `OnceLock` 单例化正则，避免重复编译
- 新增 4 个单测：`pct20` / `pct3e_pct23` 命中；`plain_sql` / `bare_pct_no_hex`（`%` 后非 hex）不命中

## 向后兼容

- **已解码输入**：`looks_like_url_encoded` 返回 `false`，走原路径，零行为变化（v0.5.0 ~ v0.7.0 所有 caller 不受影响）
- **`LIKE '%ab%'` 等含字面 `%XX` hex 序列的普通 SQL**：会被识别为编码并解码（已知简化），但解码后字节 0xAB 为 replacement char，不影响盲注探针正则匹配；SQLi payload 场景此形态极罕见
- **`SqlParseInput.sql` 字段语义放宽**：caller 可传 raw 或 decoded，`parse_sqls` 内部自决——不破坏现有 caller（PreprocessView 列级按钮、SqlParseTool textarea、`detect_sql_blind_features` samples 都传 raw 也能工作）
- **`detect_sql_blind_features` 的 `samples` 改为收集解码后形态**（与 `parse_sqls` 入口一致，避免下游二次解码）——行为微调，但下游 `SqlParseTool` 直接用 samples 填 textarea 再调 `parse_sqls`，解码后形态再过一次 `looks_like_url_encoded` 返回 `false`，走原路径，无双重解码问题
- v0.7.0 删除正则解析 + 列级 SQL 跳转 / v0.6.8 手机号 prefixes / v0.6.7 边界修复全部不破
