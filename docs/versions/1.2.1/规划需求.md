# v1.2.1 规划需求

> 三阶段交付：阶段一（T1–T4）大 TXT 文件性能修复；阶段二（T5–T10）手机号规则一致性修复 + 架构一次性优化；阶段三（T11–T15）第三轮架构优化：后端去重+性能、前端共享 hooks+state 精简、god-file 拆分、文档漂移修正。

## 阶段一：大 TXT 文件性能修复

> 解决单一超大 TXT 文件导致前端卡顿/冻结的性能问题。

### 背景

在完成 ds2time 附件提取题目时，`data.txt`（8.5 MB 单行无换行 TXT 文件）导致前端异常卡顿。
根因：`TxtReader::read()` 将整个文件读成 **1 行 1 列**，单一 cell 持有 8.5 MB 字符串，
使所有下游分页/搜索/提取/渲染机制全部失效。

### 问题链（审计结论）

1. **TxtReader** 将整个 TXT 文件内容塞入 1 个 cell（`content` 字段），产生 1 行数据
2. **DB 分页无效**：`count_rows` 返回 1，`query_cells` 的 LIMIT/OFFSET 永远只返回这 1 行
3. **React 状态**：8.5 MB 字符串被 `toRowObjects` 复制到 React state，存于 AppContext
4. **DataTable 渲染**：antd Table 无虚拟化，`highlightCell` 对 8.5 MB 字符串执行 `TextEncoder.encode`，
   且 `<td>` 无截断/省略，直接渲染全文 → 主线程冻结
5. **ExtractPanel**：`handleRun` 中 `[...input.matchAll(re)]` 在主线程同步执行正则，8.5 MB 输入冻结 UI

### 目标

在 v1.2.1 版本解决大 TXT 文件的性能问题，使 ds2time 附件类题目可正常完成：

- TXT 文件按行分割导入，不再整体作为单一 cell
- 大单元格前端渲染有截断/省略保护，不冻结
- 提取面板前端预览不对超大输入做主线程同步正则

### 验收标准

1. 8.5 MB 单行 TXT 导入后：DB 有多行（按固定 chunk 分割），前端分页正常翻页
2. DataTable 单元格内容超长时截断显示（ellipsis），不冻结浏览器
3. ExtractPanel「执行提取」对超大单元格不再主线程同步冻结
4. 现有 CSV/JSON/XLSX/LOG 等格式行为不变
5. `npx vite build` + `cargo check` 通过
6. SCHEMA_VERSION 不变（=5）

## 阶段二：手机号规则一致性修复 + 架构优化

### 背景

用户反馈：规则管理面板中预览手机号能命中，但实际「提取并校验到新 Tab」时手机号列空白。
同时要求对当前架构做一次性优化：拆分 god-file、提取复用 helper、减少总代码量。

### 手机号空白根因（3 处不一致）

**根因链**：`phone-extract` 规则 pattern `\b[1-9]\d{10}\b` 召回所有 1-9 开头的 11 位数字，
但 `check_phone_prefix(s, [])`（空名单）要求 `starts_with('1')`，导致 2-9 开头的手机号
（如 7xx 测试数据）匹配正则后被校验丢弃 → 新 Tab 空白。

| 路径 | 修复前 | 修复后 |
|------|--------|--------|
| `check_phone_prefix(s, [])` | `starts_with('1')` | `true`（空=不过滤） |
| `validate_extracted_with_params` PhonePrefix 分支 | 仅 `check_phone_prefix`（无长度/数字检查） | `is_valid_phone`（完整：11 位 + 全数字 + 前缀） |
| UI 标签 | RulesPanel 写「留空=默认 1 开头」；ExtractPanel/ValidatePanel/MaskPanel 写「留空=不限」 | 统一「留空=不限」 |

### 架构问题（修复前）

| 文件 | 行数 | 问题 |
|------|------|------|
| `extract_ops.rs` | 1213 | 最大 god-file，3 个 inner 函数重复：分页加载/表头提取/行分组/双 sheet 写出 |
| `func_validator.rs` | 733 | 12 个域混杂（luhn/ip/idcard/phone/地址/邮箱/generic）+ 12 arm dispatch |
| `rules/mod.rs` | 627 | Rule 结构 + RuleKind + RuleRegistry + 17 条内置构造器全挤一文件 |
| `RulesPanel.jsx` | 945 | 列表 + 详情 + 测试 + 4 种 params 分支全挤一文件 |
| 死代码 | ~250 行源码 + ~600 行测试 | `extractor.rs` / `validator.rs` / `extract_column` / `validate_column` 已无前端调用 |

### 目标

- 手机号规则管理与实际功能数据一致：空名单 = 不过滤；PhonePrefix 分支统一走 `is_valid_phone`
- god-file 按域拆分为子模块，单一文件不再承载过多功能
- 提取共享 helper，消除重复代码，减少总代码量
- 删除无前端调用的死代码

### 验收标准

1. `check_phone_prefix("79912345678", &[])` → `true`
2. `is_valid_phone("79912345678", &[])` → `true`；`is_valid_phone("79912345678", &["134"])` → `false`
3. `validate_extracted_with_params(PhonePrefix{[]}, "79912345678")` → `(true, "")`
4. `cargo test -p ruT0-data-kit-core` 全通过
5. `func_validator.rs` 拆为 `validators/` 子模块（8 文件）；`rules/mod.rs` 拆为 `rule.rs` + `registry.rs` + `builtins.rs`
6. `extract_ops.rs` 3 个 inner 函数消除重复（共享 `validate_single` / `query_all_data_cells` / `read_headers` / `write_sheet`）
7. `RulesPanel.jsx` ≤ 500 行（容器）+ `rule/` 子目录（RuleDetail + RuleTest + params/ + constants.js）
8. `grep -r "extractColumn\|validateColumn\|PiiExtractor" frontend/src` 无结果
9. `npx vite build` + `cargo check` + `cargo test` 通过
10. SCHEMA_VERSION 不变（=5）

## 阶段三：第三轮架构优化 — 去重 + 性能 + god-file 拆分 + 文档修正

### 背景

在完成阶段二架构优化后，审计发现仍有 6 处 Rust 后端重复模式、7 处前端重复/god-file、
以及文档漂移（docs/02 + docs/03 仍引用已删除的 `func_validator.rs` / `extractor.rs` /
`validator.rs` / `validate_column` / `extract_column`）。

### Rust 后端（6 处去重 + 1 性能修复）

| 问题 | 量化 | 方案 |
|------|------|------|
| `builtins.rs` 18 个构造器重复 | 397 行 | 表驱动：`const BUILTIN_RULES: &[Rule]` + 单循环 |
| `is_valid_birth_format` 每次编译正则 | datetime.rs | `std::sync::OnceLock<Regex>` 缓存常量正则 |
| Cell-mapping 闭包重复 | 6 处（cells.rs + search.rs） | `fn map_row_to_cell(r: &Row) -> Result<Cell>` |
| `log_operation_with_snapshot` ceremony | ~8 处 | `fn log_column_op(db, sheet_id, kind, col, payload, before, after)` |
| `normalize_gender` + 性别交叉校验重复 | extract_ops.rs 2 处 | 移到 `validators/personal.rs` + `check_gender_consistency` helper |
| `rule_exists` COUNT 重复 | rules.rs 3 处 | 私有 `fn rule_exists(id) -> bool` |
| `conn.lock().expect(...)` | 38 处 | `fn conn() -> MutexGuard` |
| clippy warning | 测试中 unused imports + dead fn | 清理 |

### 前端（7 处优化）

| 问题 | 量化 | 方案 |
|------|------|------|
| `DataTable.jsx` 455 行 | DnD+高亮+搜索+替换全挤一文件 | 拆为 SearchToolbar + ReplaceModal + DndHeader + highlightCell util |
| `ValidatePanel.jsx` 412 行 | 113 行 handleValidate 混合契约组装 | 契约组装移到 contractBuilder.js + RuleRowParams.jsx |
| `ExportModal.jsx` 378 行 | CSV/JSON/TXT 三格式分支内联 | 拆为 per-format 子组件 |
| `state.sheets.find` 重复 | 8 个文件 | `useActiveSheet()` hook 返回 `{ sheet, headers }` |
| AppContext 25 个 useCallback | 每个 `() => dispatch({type})` 无 deps | 精简为 `dispatch` + `ACTION` 常量直接暴露 |
| 死导出 + 魔法数 | `searchCells`/`replaceInColumn` 无调用；`50000`×2、`"INVALID"`×4 | 删死导出 + 集中常量 |
| generation-token 模式重复 | DataTable + App 内联 | `useStaleGuard()` hook |

### 文档漂移（高优先）

`docs/02-技术设计文档.md` + `docs/03-开发任务清单.md` 仍引用已删除的
`func_validator.rs` / `extractor.rs` / `validator.rs` / `validate_column` / `extract_column`。
模块树、IPC 表、任务清单全部过时。
