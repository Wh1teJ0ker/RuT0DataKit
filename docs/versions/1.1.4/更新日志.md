## 本版概要

v1.1.3 把行级多字段校验（T57）做成了独立能力（TopToolbar 单独按钮「行级校验」+ SidePanel 单独面板入口），与单列校验割裂。v1.1.4 初稿曾以 antd `Tabs` 把「单列校验」与「行级校验」并列入 `ValidatePanel`，但仍需用户在两个 Tab 间手动切换、且行级校验固定 7 字段、无法自由组合规则。

本版（T67 + T68 + T69）重做校验模块为**统一校验页面**：用户可动态添加任意多条「目标列 + 校验规则」组合，一个「校验」按钮即把通过 / 失败的行分流到两个新 Tab。身份证规则可勾选跨字段比对性别 / 出生日期。后端新增 `validate_multi_rules_to_two_sheets` 命令承接多规则列式校验。

## T71：前端续轮 — 按规则类型统一参数 UI

### 背景

T70 在后端落地了 `ExtractParams::Generic` 变体与 17 条 `generic-validate` seed 规则、`MultiRuleValidation.params_override` 契约、`validate_extracted_with_params` 分发。但前端 `RulesPanel` 对所有 `validate` 规则仍只渲染一个空正则输入框（generic/luhn/ipv4 等函数式规则无正则可填，UI 形同空壳）；`ValidatePanel` 的 `multiRules` 组装也未携带 `paramsOverride`，导致行级 `generic-validate` 参数无法传到后端。T71 把这两端打通。

### 改动

#### 新建 `frontend/src/components/panels/validateParams.js`

- 校验规则参数共享模块，供 `RulesPanel` + `ValidatePanel` 共用
- 导出 `EMPTY_GENERIC_PARAMS`（与后端 `ExtractParams::Generic` camelCase 对齐）
- 导出 `normalizeGenericParams(p)`：防御性默认值填充（后端返回的 params 可能缺字段）
- 导出 `buildGenericParamsForRun(p)`：组装发送给后端的 `{ validator: "generic", allowDigits, allowLetters, allowSpecial, minLen, maxLen }`
- 导出 `VALIDATE_HINTS`：各 validate 规则的提示文案（generic/username/sex/birth/idcard/phone/address/name）

#### `frontend/src/components/panels/RulesPanel.jsx`

- 追加 `Checkbox` 到 antd import；import `validateParams.js` 的 4 个导出
- 新增 `draftGenericParams` state（字符类 + 长度草稿）
- 选中规则变化时按 `params.validator === "generic"` 初始化草稿
- 可填参数 Card 分支调整为：
  - `kind === "mask"` → mask 分支（保持不变）
  - `(kind === "extract" || kind === "validate") && params` → 按 `params.validator` 分支：

  - else（无 params 的 validate 规则，如 name-validate）：hint 文案 + 正则输入框
- `handleSaveParams` 新增 `generic` 分支：调 `updateRuleExtractConfig(id, null, buildGenericParamsForRun(draft))`
- 重置按钮新增 `generic` 分支：用 `normalizeGenericParams(selected.params)` 回填

#### `frontend/src/components/panels/ValidatePanel.jsx`

- `Form.List` 每行新增 `generic-validate` 参数块（`shouldUpdate` 监听该行 `ruleId`）：

  - `InputNumber name=[name, "minLen"]` / `[name, "maxLen"]`
- 组装 `multiRules` 时 `generic-validate` 行附带 `paramsOverride`（用 `buildGenericParamsForRun` 构造）
- 底部说明文案追加：「通用校验规则可在行内设置字符类与长度限制。」

#### `frontend/src/tauri.js`

- `validateMultiRulesToTwoSheets` 的 JSDoc `rules` 参数类型追加 `paramsOverride?: object | null` 字段说明

## T67：后端规则系统扩展

### 背景

v1.1.3 的校验能力受限于固定字段映射：行级校验只能对 username/name/sex/birth/idcard/phone/address 7 个固定字段做内置校验，单列校验只能针对一列跑一条规则。用户真正想要的是「自由组合若干列 + 若干规则」的列式校验，而不是被钉死在 7 字段表上。

为此先把后端规则系统从「按字段 key 分发」泛化为「按规则 id 分发」，并把校验规则从写死在行级逻辑里抽出来成为可枚举的规则记录。

### 改动

- `ExtractParams` 从单一形态扩展为 4 个变体（mask / extract / validate / 自定义），统一通过规则记录描述
- 新增 6 条 `kind=validate` 规则（函数式 + 正则），加上既有的 `name-validate`，共 7 条 validate 规则可供前端自由选择：
  - `username-validate`、`sex-validate`、`birth-validate`、`idcard-validate`、`phone-validate`、`address-validate`、`name-validate`
- 规则分发逻辑泛化：按 `ruleId` 查表 → 路由到对应校验函数
- DB seed 写入上述 7 条 validate 规则
- `idcard-validate` 规则支持 crossField（性别 / 出生日期比对）

### 不变项

- 既有 `validate_column` / `validate_rows_to_two_sheets` 命令保留（向后兼容）
- DB schema 不变（规则表已存在）
- capabilities/default.json 不变

### 验收项

- **E79**：`ExtractParams` 新增 4 变体（Username/Sex/Birth/Address），serde camelCase roundtrip 正确
- **E80**：`validate_extracted` 新增 4 分发分支，分别调 `is_valid_username` / `is_valid_sex` / `is_valid_birth` / `is_valid_address`，返回 `(bool, String)`
- **E81**：`with_defaults()` 注册 6 条新 validate 规则，内置规则总数 10 → 16；DB seed 幂等（老用户升级 upsert 插入新 id，现有 10 条不动）

## T68：新增 validate_multi_rules_to_two_sheets IPC 命令

### 背景

T67 把规则泛化为可枚举记录后，需要一个面向「多规则列式校验」的新命令承接前端统一校验页面：接收任意多条「列 + 规则」组合，一次校验后把通过 / 失败的行分流到两个新 Tab。

### 改动

- 新增 IPC 命令 `validate_multi_rules_to_two_sheets`
- 参数（全 camelCase）：
  - `sheetId: number`
  - `sessionId: number`
  - `rules: Array<{ column: string, ruleId: string, crossField?: { checkSex: boolean, sexColumn: string|null, checkBirth: boolean, birthColumn: string|null } | null }>`
  - `phonePrefixes: string[]`（可选，默认 []）
- 返回：
  - `{ validSheet: ParseResult, invalidSheet: ParseResult, invalidReasons: Array<{ sourceRow: number, field: string, reason: string }> }`
  - `ParseResult = { newSheetId: number, headers: string[], rowCount: number, skipped: number }`
- 落地模式与 `validate_rows_to_two_sheets` 一致：通过 / 失败行分别写入两个新 Tab，保留原列，不新增列
- capabilities/default.json 无需改动（自定义命令无需权限）

### 不变项

- 不改 `validate_rows_to_two_sheets` / `validate_column`（保留向后兼容）
- 不改 DB schema

### 验收项

- **E82**：`validate_multi_rules_to_two_sheets` 命令接收多条 `{column, ruleId, crossField?}` 组合，逐行逐规则校验（phone-validate→`is_valid_phone` / params 非空→`validate_extracted` / pattern 非空→正则 `is_match` / 其他→默认通过），整行分流到 `{源sheet名}_校验通过` / `_校验失败` 两个新 Tab，保留原列不新增
- **E83**：身份证跨字段联合校验 — 仅 `idcard-validate` 规则带 `crossField` 配置且 idcard 本身有效时触发：性别 `normalize_gender` vs `idcard_gender`、出生日期 `is_valid_birth` 后 `idcard[6..14]` 切片比对；6 条集成测试（all_rules_pass / mixed_pass_fail / idcard_cross_field_sex_mismatch / idcard_cross_field_birth_mismatch / regex_rule_validation / partial_mapping）全过

## T69：前端重做统一校验页面

### 背景

T67/T68 把后端能力泛化后，前端的 `ValidatePanel` 仍是 v1.1.4 初稿的 Tabs 双页（单列校验 Tab + 行级校验 Tab）。用户需在两个 Tab 间切换、且行级校验固定 7 字段映射、无法自由组合规则。T69 重做 `ValidatePanel` 为统一表单，承接 `validate_multi_rules_to_two_sheets`。

### 改动

#### `frontend/src/components/panels/ValidatePanel.jsx`（完全重写）

- 移除 antd `Tabs` 双页结构，改为单一表单
- 用 `Form.List name="rules"` 实现动态规则行增删（antd 原生支持）
- 每条规则行：
  - 目标列 `Select`（options 来自当前 sheet headers）
  - 校验规则 `Select`（options 来自 `listRules()` 异步加载、`filter kind === "validate"`，即 T67 的 7 条规则）
  - 删除按钮
- 当选中的规则是 `idcard-validate` 时，用 `Form.Item shouldUpdate` 条件渲染跨字段配置：
  - 勾选「对比性别一致性」+ Select 性别列
  - 勾选「对比出生日期一致性」+ Select 出生日期列
- 勾选跨字段比对后必填对应列（前端校验拦截，避免后端静默跳过）
- 底部手机号前缀白名单 `Select mode="tags"`（可选，应用于 `phone-validate` 规则；全局而非每行单独配；过滤三位纯数字）
- 一个「校验」按钮 → 调 `validateMultiRulesToTwoSheets(sheetId, sessionId, rules, phonePrefixes)`
- 双 Tab 落地：复用 v1.1.3 `RowValidatePanel` 的 `landSheet` 闭包模式（`addSheetFromParse` + `getSheetData` + `SET_SHEET_DATA`），落地 `{源sheet名}_校验通过` / `{源sheet名}_校验失败`
- 汇总消息：通过 / 失败行数 + top 失败原因（按 `field` 计数，取前 3）
- 重置按钮：`form.resetFields()`

#### `frontend/src/tauri.js`

- 新增 `validateMultiRulesToTwoSheets(sheetId, sessionId, rules, phonePrefixes = [])` wrapper，invoke `validate_multi_rules_to_two_sheets`
- 既有 `validateColumn` / `validateRowsToTwoSheets` wrapper 保留（向后兼容）

#### 文档

- `docs/versions/1.1.4/更新日志.md`：重写，删除初版「Tabs 双页合并」描述，记录 T67/T68/T69 三个任务 + 统一校验页面设计
- `docs/versions/1.1.4/RELEASE-NOTES.md`：重写，聚焦「统一校验页面：自由选多规则 + 一按钮 + 双 Tab 输出」

### 不变项

- 不改后端（T67/T68 已完成并合并到 main）
- 不改 `TopToolbar.jsx` / `SidePanel.jsx`（v1.1.4 初稿已移除 rowValidate 入口，validate 走默认 SidePanel 分支）
- 不改 `state/*`（复用 `ADD_SHEET_FROM_PARSE` + `SET_SHEET_DATA`）
- 不改 `App.jsx` 路由
- 不改 `src-tauri/capabilities/default.json`

### 验收项

- **E84**：`pnpm --prefix frontend build` 通过
- `ValidatePanel.jsx` 是单一表单（无 Tabs/Segmented 切换），顶部可动态添加多条规则行
- 每条规则行：目标列 Select + 校验规则 Select + 删除按钮
- 校验规则 options 包含 T67 的 7 条 validate 规则
- 当选中规则是 `idcard-validate` 时展开跨字段配置
- 底部有手机号前缀白名单 `Select mode="tags"`
- 一个「校验」按钮 → 双 Tab 落地 + 汇总消息

### 设计决策

**为什么用 `Form.List` 而非手动 `useState` 数组**：antd `Form.List` 原生支持动态增删行，`getFieldsValue(true)` 直接拿到结构化数据，无需手动维护表单状态；条件渲染用 `Form.Item shouldUpdate` 监听该行 `ruleId` 变化，天然隔离跨字段配置只对 `idcard-validate` 生效。

**为什么手机号前缀是全局而非每行配**：`phone-validate` 规则行的语义是「这一列是不是合法手机号」，前缀白名单是「合法手机号」定义的一部分，多行 phone-validate 共享同一白名单定义更符合用户心智，避免每行重复填同样的前缀。
