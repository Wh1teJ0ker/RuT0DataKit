## 本版概要

v1.1.3 把行级多字段校验（T57）做成了独立能力（TopToolbar 单独按钮「行级校验」+ SidePanel 单独面板入口），与单列校验（`ValidatePanel`）割裂。用户反馈「不应该是在单独的行级校验里，应该就是在校验模块中」。

v1.1.4 将两者合并为统一的「校验」能力：单列校验 + 行级校验作为同一面板（`ValidatePanel`）内的两个 Tab（antd `Tabs`），移除独立的 `rowValidate` 能力入口。后端 IPC 命令（`validateColumn` / `validateRowsToTwoSheets`）与实现保持不变，本版为纯前端 UI 合并。

## T67：校验模块统一

### 背景

v1.1.3 的 `RowValidatePanel` 作为独立能力挂在 TopToolbar「行级校验」按钮下，用户需在「校验」与「行级校验」两个按钮间切换，且两者本质都是「校验」能力，割裂体验。

### 改动

#### 前端合并

- `frontend/src/components/panels/ValidatePanel.jsx`：改造成 antd `Tabs` 容器
  - **Tab1「单列校验」**：保留原 `validateColumn` + `applyRowStatuses` 原位高亮逻辑（行为不变）
  - **Tab2「行级校验」**：内联原 `RowValidatePanel` 的 7 字段映射 + phonePrefix 白名单 + `validateRowsToTwoSheets` 双 Tab 落地逻辑（行为不变）
  - 两个 Tab 各持独立 `Form.useForm()` 实例（`colForm` / `rowForm`），切 Tab 不丢数据，各自 reset 只清自己
  - 从 `useAppContext` 取 `{ state, applyRowStatuses, dispatch, addSheetFromParse }`
- `frontend/src/components/panels/RowValidatePanel.jsx`：**删除**（逻辑已合并入 ValidatePanel）

#### 入口移除

- `frontend/src/components/layout/TopToolbar.jsx`：
  - 从 `CAPABILITIES` 数组移除 `{ id: "rowValidate", label: "行级校验", icon: <SafetyOutlined /> }`
  - 移除未再使用的 `SafetyOutlined` import
  - TopToolbar 能力按钮从 7 个回到 6 个（脱敏 / 校验 / 提取 / 列操作 / 加解密 / 规则管理）
- `frontend/src/components/layout/SidePanel.jsx`：
  - 移除 `import RowValidatePanel`
  - 从 `PANELS` map 移除 `rowValidate: RowValidatePanel`

#### 版本号 bump（1.1.3 → 1.1.4，4 处）

| `Cargo.toml`（workspace 源头） | `version = "1.1.4"` |

### 不变项

- 后端 `validate_rows_to_two_sheets` / `validate_column` IPC 命令、实现、测试均不变
- `frontend/src/tauri.js` 的 `validateColumn` / `validateRowsToTwoSheets` wrapper 保留
- `frontend/src/App.jsx` 路由不变（`validate` 已走默认 SidePanel 分支）
- `frontend/src/state/reducer.js` 无 rowValidate 专用状态，不改
- `frontend/src/state/constants.js:7` 的 `activeCapability` 注释枚举已是 6 个（mask/validate/extract/rules/columnOps/crypto），无需改动
- `src-tauri/capabilities/default.json` 无需改动（自定义命令无需权限）
- v1.1.3 已发布文档（RELEASE-NOTES.md / 更新日志.md / GitHub Release 正文）不改，反映发布时状态

### 验收项

- **E79**：TopToolbar 不再有「行级校验」按钮，只剩 6 个能力按钮
- **E80**：点「校验」按钮 → SidePanel 渲染 ValidatePanel，内含「单列校验」「行级校验」两个 Tab
- **E81**：单列校验 Tab：选列 + 规则 → 执行 → 原位高亮无效行（行为与 v1.1.3 一致）
- **E82**：行级校验 Tab：7 字段映射 + 手机前缀 → 执行 → 双 Tab 落地（`{name}_校验通过` / `{name}_校验失败`），行为与 v1.1.3 RowValidatePanel 一致
- **E83**：`RowValidatePanel.jsx` 已删除，构建无未解析导入
- **E84**：版本号 4 处统一为 1.1.4

### 设计决策

**为什么用 Tabs 而非 Segmented 或单 Form 切换**：单列校验与行级校验的表单字段差异大（前者 2 个 Select，后者 7 字段映射 + phonePrefix），用 `Tabs` 天然隔离两套表单状态，避免字段冲突；`Segmented` 更适合同构表单的视图切换。两个 `Form.useForm()` 实例独立，切 Tab 不丢已填映射。

**为什么删除 RowValidatePanel.jsx 而非保留死代码**：合并后该文件无任何引用（SidePanel 已移除导入），保留只会造成后续维护混淆。逻辑已完整内联到 ValidatePanel 的 `rowTab`。
