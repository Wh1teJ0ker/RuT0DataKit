# v1.1.4 规划需求

> 本文件为 v1.1.4 版本子文档，范围与任务清单与 [`docs/03-开发任务清单.md`](../../03-开发任务清单.md) 对齐。版本状态口径见 [`docs/04-版本标准.md`](../../04-版本标准.md)。进度日志见 [`更新日志.md`](./更新日志.md)，发布说明见 [`RELEASE-NOTES.md`](./RELEASE-NOTES.md)。

## 1. 版本定位

v1.1.4 在 v1.1.3 之上重做**校验模块**为**统一校验页面**——用户可动态添加任意多条「目标列 + 校验规则」组合，一个「校验」按钮即把通过 / 失败的行分流到两个新 Tab。身份证规则可勾选跨字段比对性别 / 出生日期。在此基础上分四轮交付 13 个任务（T67-T79）的增量增强。

v1.1.4 **不实现**：撤销栈 / 操作回滚（已在 v1.1.1 交付）、AI 真实接入、全局搜索、Tools / tshark 集成、PCAP 分析——均推迟至 v1.2+。

## 2. 前置

- v1.1.3 已发布 tag `v1.1.3`（见 [`../1.1.3/RELEASE-NOTES.md`](../1.1.3/RELEASE-NOTES.md)）。
- v1.1.3 把行级多字段校验（T57）做成了独立能力（TopToolbar 单独按钮「行级校验」+ SidePanel 单独面板入口），与单列校验割裂；v1.1.4 初稿曾以 antd `Tabs` 把「单列校验」与「行级校验」并列入 `ValidatePanel`，但仍需用户在两个 Tab 间手动切换、且行级校验固定 7 字段、无法自由组合规则——本版重做。

## 3. 范围定义

### 3.1 首轮（T67/T68/T69）— 统一校验页面

- **T67 后端规则系统扩展**：`ExtractParams` 从单一形态扩展为 4 变体（mask / extract / validate / 自定义）；新增 6 条 `kind=validate` 规则（username / sex / birth / idcard / phone / address），加上既有 `name-validate` 共 7 条；规则分发逻辑泛化为按 `ruleId` 查表路由；`idcard-validate` 支持 crossField（性别 / 出生日期比对）。
- **T68 新增 `validate_multi_rules_to_two_sheets` IPC 命令**：接收任意多条 `{column, ruleId, crossField?}` 组合，一次校验后把通过 / 失败行分流到两个新 Tab，保留原列不新增。
- **T69 前端重做统一校验页面**：`ValidatePanel.jsx` 完全重写为单一表单（无 Tabs/Segmented 切换），antd `Form.List` 动态规则行增删，每行 = 目标列 Select + 校验规则 Select + 删除按钮；`idcard-validate` 行展开跨字段配置；一个「校验」按钮 → 双 Tab 落地 + 汇总消息。

### 3.2 续轮 R2（T70/T71/T72）— 通用校验 + 地址放宽 + 生日清理 + 前端统一化

- **T70 后端续轮**：`ExtractParams::Generic` 变体（字符类 + 长度范围）+ `generic-validate` 内置规则（`with_defaults()` 16 → 17 条）；`is_valid_birth` 改为先 `clean_birth` 清理分隔符再校验；`is_valid_address` 放宽为结构化校验（中文 ≥ 2 + 地址关键词）；`validate_extracted_with_params` 抽取核心逻辑；`MultiRuleValidation.params_override` 字段（前端可覆盖 DB 默认参数）。
- **T71 前端续轮**：新建 `validateParams.js` 共享模块；`RulesPanel` 按规则类型渲染参数 UI（generic 字符类 + 长度 / phonePrefix 前缀 / 其他只读 hint）；`ValidatePanel` generic-validate 行展开参数块 + 组装 `paramsOverride`。
- **T72 文档同步 + E2E + Release QA 增量审计**。

### 3.3 续轮 R3（T73-T76）— 哈希函数 + DB 文件解析

- **T73 后端 R3**：新增 `hash_column` IPC 命令（MD5/SHA1/SHA256，hex 小写，不可逆），复用 v1.1.2 的 `base64_transform_column_cells` 闭包式列变换（单事务 + 快照，可撤销）；新增依赖 `md-5` / `sha1` / `sha2` / `hex`。
- **T74 前端 R3**：`CryptoPanel` 扩展算法选择（Base64 编/解码 + MD5/SHA1/SHA256），选哈希时禁用「解码」按钮；`tauri.js` 新增 `hashColumn` wrapper。
- **T75 后端 R3**：新增 `DbReader` 数据源（`crates/core/src/datasource/db.rs`），打开外部 `.db` / `.sqlite` / `.sqlite3` 二进制 SQLite 文件，读取全部用户表（跳过 `sqlite_%` 内部表），多表联合输出 `__table` 首列标识来源；`detect_format` 新增 3 个 match arm。
- **T76 R3 文档同步 + E2E + Release QA R3 增量审计**。

### 3.4 续轮 R4（T77-T79）— 特殊符号白名单 + 手机号前缀 UX 统一 + name 排序

- **T77 特殊符号自定义白名单**：`ExtractParams::Generic` 的 `allow_special: bool`（全开/全关）改为 `allow_special_chars: String`（空串 = 不允许任何特殊字符；非空如 `_-.@` = 仅允许这些字符，白名单语义）。
- **T78 手机号前缀配置 UX 统一**：校验侧前缀白名单从 ValidatePanel 底部全局 Form.Item 改为每行内嵌（仅 phone-validate 行展开）；提取侧 `extract_validate_to_new_sheet` 新增 `phone_prefixes` 运行时参数覆盖 DB 默认。
- **T79 规则列表按名称排序**：`list_rules` 的 SQL `ORDER BY id ASC` 改为 `ORDER BY name ASC`（Unicode 码点升序），前端各面板自动继承新顺序。

## 6. 不变项

- 既有 `validate_column` / `validate_rows_to_two_sheets` IPC 与 wrapper 保留（向后兼容）；`validate_rows_to_two_sheets` 命令签名不变（内部 birth 比对改用 `clean_birth`）。
- `extract_validate_to_new_sheet_inner` 签名新增 `phone_prefixes: &[String]` 末位参数（T78），既有调用方传 `&[]` 保持兼容。
- `App.jsx` 路由不变（validate 走默认 SidePanel 分支；CryptoPanel 入口 v1.1.2 已有）。
- DB schema / capabilities/default.json 不变（SCHEMA_VERSION=5，`params` 列复用；`operations` 快照列复用存 `hash_column` before/after）。
- `TopToolbar.jsx` / `SidePanel.jsx` 沿用 v1.1.4 初稿已移除 rowValidate 入口的状态。
- `base64_column` 命令不变（`hash_column` 是新增独立命令，复用 DB 层闭包式列变换方法）。
- `crates/core` 的 processor / datasource trait 不变（`DbReader` 是新增 impl，trait 签名不变）。
- `detect_format` 新增 `.db`/`.sqlite`/`.sqlite3` 分支不破坏旧格式（csv/xlsx/json/jsonl/txt/log/sql/pcap/pcapng 分支不变）。
- v1.1.3 已发布文档与 GitHub Release 正文不改。

## 7. 安全约束

- SQL 全部 `?N` + `params![]` 绑定，禁拼接。DbReader 表名例外：表名不能用参数绑定（参数绑定只用于值，不能用于标识符），表名来源限定为受信系统表 `sqlite_master`（`type='table' AND name NOT LIKE 'sqlite_%'`），用 `quote_identifier`（双引号包裹 + 内部双引号翻倍）做防御性转义后拼入 `SELECT * FROM "{table}"`，无 SQL 注入面。
- 无凭据字面量。
- 不创建 tag（v1.1.4 未完成前不打 tag；R3/R4 续轮 qa_passed 后仍等待用户手工验证，不自动 finalize）。
- Mimosa 完整审计未拿到结论前不宣称安全；R3+R4 续轮未重新运行完整审计，沿用 v1.1.3 R1+R2 双轮 0 findings / 487 包 0 漏洞基线（R3+R4 改动为 codec + datasource + 校验参数增强，未改 DB schema / CSP / 权限 / 网络，静态分析基线有效；静态分析非运行时验证，不宣称项目安全）。
