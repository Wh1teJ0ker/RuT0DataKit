# v0.4.0 规划需求

## 范围

**架构性完整重构**：从「按数据源分片（csv/log/pcap）」演进为「按功能分界面（7 个主界面）」的统一架构。
所有数据源（csv / xlsx / sql / pcap / log / json）统一进入「数据预处理」界面，归一化为 `Records`（csv 表格形式），后续功能界面共享同一份预处理产物。

## 目标

### 1. 数据预处理（界面 1，默认入口）

- 支持 6 种文件格式：`csv` / `xlsx` / `sql` / `pcap` / `log` / `json`。
- 所有源统一读为 `Records { headers, rows }`（csv 表格形式），供后续界面消费。
- 界面布局：导入按钮 → 类型自动识别 → antd Table 预览（带行/列计数）→ 底部跳转按钮组（搜索 / 数据脱敏 / 数据校验 / SQL 解析）。
- pcap/log 在预处理阶段也产出 `Records`（pcap 取 HTTP 请求字段做表，log 取 CLF 字段做表），而非各自的 Report 视图——原 LogView/PcapView 的 Report 展示能力下沉到 Tools 的 SQL 解析 / 搜索。

### 2. 规则管理（界面 2）

- 规则引擎重构：`FieldRule` / `MaskRule` 新增 `tags: Vec<String>` 字段（`#[serde(default)]` 向后兼容）。
- 标签语义：`mask` / `validate` / `search` / `sensitive` / `sql_parse` / 自定义。
- 一条规则可挂多标签（如同时是 `mask` + `sensitive`），适配所有功能界面按标签筛选规则集。
- `RuleSet` 提供 `by_tag(tag) -> &[Rule]` 过滤 API；RulesView 支持按标签过滤列表 + 单条规则多标签编辑。
- 预置规则模板按标签分组。

### 3. 搜索（界面 3）

- 关键词匹配（多关键词 AND/OR）+ 正则匹配 + 精确字段匹配。
- 索引算法：构建倒排索引（term → 行号集合），支持大文件（≥10w 行）秒级检索。
- 结果表：命中行 / 命中列 / 命中片段高亮。
- 跳转：结果可带入「数据脱敏」/「数据导出」。

### 4. 数据脱敏（界面 4）

- 复用 v0.1.0 四段垂直布局（原始数据 → 表头-规则映射 → 预览 → 操作面板）。
- 数据源改为消费预处理产物 `Records`（不再各自导入文件）。
- 规则按 `mask` 标签筛选。
- 「导出」按钮跳转数据导出界面。

### 5. 数据校验（界面 5）

- 同 4 的布局，规则按 `validate` 标签筛选，逐 cell 合法性矩阵。

### 6. 数据导出（界面 6）

- 支持 `xlsx` / `csv` / `json` 三种格式。
- 数据源 Select（原始 / 脱敏 / 校验过滤后）+ 列勾选 + 列序拖拽 + 格式 Select。
- json 导出：每行一个对象，按 headers 做 key。

### 7. Tools（界面 7，下拉栏）

下拉菜单两个子工具：

#### 7.1 SQL 解析

- 对 SQL 全方面各盲注全类型做自动化解析：boolean / equality / length / time / error / union / tautology / comment。
- 输入：原始 SQL 片段列表（或多行日志/请求 body），自动提取盲注探针 → 聚类 → 还原完整数据库。
- 复用并重构 v0.2.4 的 `blind_aggregator` + `reconstruct_database`，独立为 `tools::sql_parse` 模块，接受纯 SQL 输入（不再绑定 LogEntry）。
- 输出：`ReconstructedDatabase` + 解析过程明细（每探针的 read_target / position / comparator / kind）。
- GUI：输入框 → 「解析」按钮 → 还原数据库 antd Table + 探针明细表。

#### 7.2 正则解析

- 正则解析：输入正则 → 解释每个 token（字面量 / 字符类 / 量词 / 锚点 / 分组 / 反向引用 / 断言）。
- 辅助写正则：基于常见场景模板（邮箱/手机/身份证/IP/URL/SQL 注入特征）生成正则骨架 + 参数化定制。
- GUI：两个 Tab，输入 → 解析结果表 / 模板选择 → 生成正则 + 测试样例。
