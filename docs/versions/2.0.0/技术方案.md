# 2.0.0 技术方案

> 版本：2.0.0（MAJOR，破坏性重构）
> 创建：2026-07-29
> 依赖版本：v0.6.8（release_complete）
> 状态：planned
> 关联：`docs/versions/2.0.0/规划需求.md`

## 1. 总体架构

v2.0.0 保持 Tauri v2 + Rust core + React 18 前端的技术栈不变，但前端组件层与 Tauri 命令层围绕「工作台范式」重组。架构分三层：

```
┌─────────────────────────────────────────────────────────────────┐
│  前端 Shell 层（React 18 + antd 5）                               │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ Toolbar（上）│ OperationBar（左）│ Workbench（中 70%）│ AIPanel（右）│   │
│  │              │                  │ Sheet/Tab 模型       │ 占位+预留   │   │
│  │              │                  │ 中央表格组件         │ IPC 契约    │   │
│  └──────────────────────────────────────────────────────────┘   │
│  ↓ dispatch（useReducer，Sheet 为操作对象）                       │
├─────────────────────────────────────────────────────────────────┤
│  Tauri 命令层（src-tauri/src/commands/，围绕 Sheet/选区/列重组）  │
│  invoke → Sheet 操作 / 选区脱敏 / 选区校验 / 列操作 / AI 占位      │
├─────────────────────────────────────────────────────────────────┤
│  Rust core 业务层（crates/core/，复用 v0.6.x，零算法重写）        │
│  readers / maskers / validators / extract / scan / logsign /      │
│  pcap / rules / report / pipeline / search / tools               │
└─────────────────────────────────────────────────────────────────┘
```

层间约束：
- 前端 Shell 层只持有 Sheet 模型 + 当前活动表指针，不直接跑业务逻辑；所有计算走 Tauri 命令。
- Tauri 命令层是范式适配层：把工作台操作（选区脱敏/选区校验/列操作）翻译为对 `crates/core` 既有函数的调用。
- `crates/core` 零重写：v0.6.x 的 `mask_pipeline` / `validate_pipeline` / `extract_*` / `scan_log` / `scan_pcap` 等函数签名保持不变，命令层负责组装入参。

- 左侧操作栏（OperationBar）：垂直排列动作入口，脱敏/校验/提取/规则管理/搜索/Tools/设置。点击后弹出侧层面板（antd Drawer/Popover）或在当前表上就地执行。

### 2.2 Sheet/Tab 模型

v0.x 的 `activeView` 状态机被 Sheet 模型替代。前端 state 形状：

```ts
interface WorkbenchState {
  sheets: Sheet[];          // 所有打开的 Sheet
  activeSheetId: string | null;  // 当前活动表（唯一操作对象）
  // 以下为全局共享、跨 Sheet 不丢
  rules: RuleSet;           // 内置 + 用户规则（复用 v0.6.x state.rules）
  settings: Settings;       // tshark 路径等（复用 v0.6.x）
  // 选区/列勾选是"当前活动表"的派生态
  selectedCells?: CellRange;
  selectedColumns?: string[];
  columnOrder?: string[];
  // 操作栏面板态
  panelState: { ... };      // 规则 Drawer / Tools 浮层等开关
}

interface Sheet {
  id: string;               // 唯一 id（uuid 或递增）
  name: string;             // Tab 显示名（"原始数据"/"脱敏结果"/"日志扫描"…）
  kind: SheetKind;          // data | mask_result | validate_result | extract_result | log_scan | pcap_scan | tools
  source: { from: string; ref?: string };  // 来源（导入文件 / 脱敏 / 校验 / 提取 / 扫描）
  records: Records;         // 复用 crates/core Records（headers + rows）
  cellStates?: CellState[][];  // 每格状态：原始/脱敏/非法/提取标记（可选）
  summary?: Summary;        // 该 Sheet 的概要（记录数/命中数等）
}
```

关键约束：
- 任一时刻只有一个 `activeSheetId`。所有工具栏/操作栏动作作用于当前活动表。
- 脱敏/校验/提取/扫描结果默认写新 Sheet（`mask_result`/`validate_result`/…），用户可在 Tab 间对照原始数据与结果。可选"就地应用"模式（结果回写当前表 + cellStates 标记）。
- 跨 Sheet state（rules/settings/panelState）常驻，关 Tab 不丢规则与设置。

### 2.3 中央表格组件（WorkbenchTable）

基于 antd Table 封装，需支持：

- **选区**：行范围 / 列范围 / 矩形选区（用作脱敏/校验/导出的作用域）。
- **列勾选**：表头 checkbox（复用 v0.6.x ExportView 的列选模式）。
- **列序**：上下移按钮或拖拽（复用 v0.6.x ExportView 的列序逻辑）。
- **分页**：受控分页（10/20/50/100，复用 v0.6.4 的受控分页）。
- **状态高亮**：cell 级状态——原始（默认）/ 脱敏（淡黄底）/ 非法（红底）/ 提取标记（蓝边框）。由 `Sheet.cellStates` 驱动。
- **空态**：无 Sheet 时渲染引导（"从工具栏导入文件开始"）。

复用策略：v0.6.x 的 `ExportView`（单一 Table + 列选列序）和 `MaskView`（四段垂直）的表格部分可作为 WorkbenchTable 的实现参考，但组件重写为工作台中央组件，不沿用 view 结构。

## 3. Tauri 命令层重组

v0.6.x 命令按 view 组织（`mask.rs` / `validate.rs` / `export.rs` / `extract.rs` / `log.rs` / `pcap.rs` / `ruleset.rs` / `search.rs` / `tools.rs` / `encrypt.rs` / `file.rs`）。v2.0.0 围绕工作台操作重组，但底层调用 `crates/core` 不变。

### 3.1 命令重组原则

- **按操作对象而非 view 分组**：`sheet_ops`（导入/导出/列操作/选区）、`mask_ops`（脱敏）、`validate_ops`（校验）、`extract_ops`（提取）、`scan_ops`（日志/PCAP）、`ruleset_ops`（规则）、`tools_ops`（SQL/正则/加解密）、`ai_ops`（占位）。
- 既有命令签名尽量保留，新增工作台语义命令在上方薄包装。例如 `mask_pipeline_columns` 保留，新增 `mask_selection(sheet_id, columns, rules)` 在命令层映射到前者。
- `crates/core` 函数零修改；命令层负责 Sheet↔Records 转换、选区↔列集合转换。

### 3.2 关键命令契约（工作台语义）

| 命令 | 入参 | 出参 | 底层调用 |
|------|------|------|----------|
| `import_to_sheet(path)` | 文件路径 | `{ sheet_id, records, detected_type }` | `readers::*` + 自动识别 |
| `mask_selection(sheet_id, columns, rule_ids)` | 活动 Sheet + 选列 + 规则 | `{ result_sheet_id, records, summary }` | `mask_pipeline_columns` |
| `validate_sheet(sheet_id, rule_ids)` | 活动 Sheet + 规则 | `{ result_sheet_id, valid_matrix, summary }` | `validate_pipeline` |
| `extract_from_sheet(sheet_id, types)` | 活动 Sheet + 提取类型 | `{ result_sheet_id, records }` | `extract_*` |
| `export_sheet(sheet_id, format, columns, order)` | Sheet + 格式 + 列选列序 | 文件路径 | `export_records_*` |
| `scan_log_to_sheet(path)` | 日志路径 | `{ sheet_id, report }` | `scan_log` |
| `scan_pcap_to_sheet(path)` | pcap 路径 | `{ sheet_id, report }` | `scan_pcap` |
| `ai_suggest(kind, payload)` | 占位 | `{ placeholder: "not_implemented" }` | 无（v2.0） |
| `invoke_ai_op(op, payload)` | 占位 | `{ placeholder: "not_implemented" }` | 无（v2.0） |

`ai_suggest` / `invoke_ai_op` 是 v2.0 的预留契约：命令存在、可调、返回明确"未实现"占位，为 v2.1+ 真实 AI 集成留接口。

## 5. 数据流（典型主流程）

### 5.1 导入 → 脱敏 → 导出

```
用户点 Toolbar「导入」→ 选 CSV
  → invoke import_to_sheet(path)
  → 后端 readers::csv → Records
  → 前端新建 Sheet（kind=data, name="原始数据"）→ 设为 activeSheetId
  → WorkbenchTable 渲染
用户在表格选列（表头 checkbox）→ 操作栏点「脱敏」
  → 侧弹脱敏配置（选规则）→ 确认
  → invoke mask_selection(sheet_id, columns, rule_ids)
  → 后端 mask_pipeline_columns(records, rules, columns)
  → 返回结果 Records
  → 前端新建 Sheet（kind=mask_result, name="脱敏结果"）→ 设为 activeSheetId
  → WorkbenchTable 渲染（cellStates 标记脱敏格淡黄）
用户点 Toolbar「导出」→ 选 XLSX + 列选列序
  → invoke export_sheet(sheet_id, "xlsx", columns, order)
  → 后端 export_records_xlsx
  → 文件落盘
```

### 5.2 日志导入 → 扫描 → 看 AI 面板（占位）

```
用户点 Toolbar「导入」→ 选 access.log
  → import_to_sheet → 新 Sheet（kind=log_scan, name="日志"）
用户点操作栏「扫描」（或自动触发）
  → invoke scan_log_to_sheet(path)
  → 后端 scan_log → Report
  → 前端新建 Sheet（kind=log_scan, name="日志扫描结果"）
  → 同时把 Report.summary 推到右侧 AI Panel 占位区
  → AI Panel 显示"扫描已完成，AI 解读将在 v2.1+ 提供"
```

## 7. AI 面板预留契约

v2.0.0 右侧 AI Panel 不实现真实 AI，但落两件事：

1. **版式**：渲染 antd Empty + 文案"AI 能力将在 v2.1+ 提供"；预留区域可被未来填充。
2. **IPC 契约**：Tauri 命令 `ai_suggest(kind, payload)` 与 `invoke_ai_op(op, payload)` 存在且可调，返回 `{ placeholder: "not_implemented", version: "2.0.0" }`。前端 AI Panel 不调用真实 LLM，只渲染占位。

这保证 v2.1+ 接真实 AI 时，前端调用链与命令契约已就绪，无需改 Shell。

## 8. 性能与边界

- **大表性能**：antd Table 在万行级可能卡顿。v2.0 复用 v0.6.x 的受控分页（10/20/50/100）+ 虚拟滚动评估。超过阈值时只渲染当前页。
- **选区复杂度**：矩形选区在 antd Table 上需自定义 rowSelection + cell selection；先打通列选 + 行范围选，矩形选作为增强。
- **多 Sheet 内存**：跨 Sheet records 常驻内存。大文件多 Sheet 时可能占用高；v2.0 不做懒加载，但 Sheet 关闭即释放（除 rules/settings）。
- **命令层薄包装**：工作台语义命令是对 `crates/core` 的薄包装，不引入额外计算开销。

## 9. 测试策略

- **后端**：`crates/core` 既有测试零修改、零回归。命令层新增薄包装测试（Sheet↔Records 转换正确性）。
- **前端**：WorkbenchShell 三栏布局快照；Sheet reducer 状态转换；WorkbenchTable 选区/列选/列序交互。
- **e2e**：`cargo test --test e2e` 既有用例不回归；新增工作台主流程 e2e（导入→脱敏→导出端到端）。
- **能力等价**：用 v0.6.x fixture 在 v2.0 工作台跑相同脱敏/校验/提取/扫描，结果等价。
