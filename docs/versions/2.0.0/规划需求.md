# 2.0.0 规划需求

> 版本：2.0.0（MAJOR，破坏性重构）
> 创建：2026-07-29
> 依赖版本：v0.6.8（release_complete）
> 状态：planned
> 依据：用户 goal「v2.0.0 版本，完全与之前不同的设计理念和。工具将类似 Excel：主视图在中间侧占 70%，上方工具栏，左侧操作栏，右侧 AI 操作面板（后期实现，v2.0 仅占位+预留接口）。」

## 版本目标

v2.0.0 是 RuT0DataKit 的**设计理念级重构**。它放弃 v0.x 的「侧边栏多独立视图」范式，改为「以表格工作台为中心」的单页工作台范式：一个持续可见的中央表格承载用户数据，操作以工具栏（上）+ 操作栏（左）触发，结果就地反映在表格上或右侧 AI/结果面板。v2.0.0 同时是 v0.1.0~v0.6.8 所有既有能力的迁移载体，不是新工具的空壳——它必须在不丢失既有能力的前提下换骨。

核心设计理念（与 v0.x 的根本差异）：

1. **表格即工作台**：中央表格不是某个视图的局部预览，而是整个应用的唯一主舞台。导入、脱敏、校验、提取、导出都围绕这张表进行，用户在同一张表上完成全部主流程，不再在视图间反复横跳。
2. **就地操作而非跳转视图**：v0.x 的「导入→预处理→脱敏→校验→导出」多视图串联，在 v2.0.0 变为「在同一张表上选区→执行→看结果」。工具栏与左侧操作栏是动作入口，表格是动作落点。
3. **Sheet/Tab 多页承载多源**：主视图支持多 Sheet（原始数据/脱敏结果/校验结果/提取结果/日志/流量等），用户在 Tab 间切换，但全局只有一张"当前活动表"接受操作。这替代了 v0.x 的 view 状态机。
4. **工具栏高频 / 操作栏中频 / 右侧低频**：上=高频（导入/导出/格式/撤销/列操作/运行），左=中频（脱敏/校验/提取/规则管理/搜索/Tools 子能力），右=AI 与未来扩展（v2.0 仅占位 + 预留 IPC 契约）。
5. **AI 面板是预留位，不是 v2.0 主特性**：右侧版式与接口契约在 v2.0 落地，但真实 AI 能力推迟到 v2.1+。文档明确"后期实现"，避免范围蔓延。
6. **后端核心 crates 复用，命令层重新组织**：`crates/core` 的脱敏/校验/扫描/提取/正则等业务逻辑保持复用，但 Tauri 命令层围绕工作台操作重新设计（Sheet/选区/列操作/公式式规则应用），以贴合新范式而非沿用旧 view API。

### 与 v0.6.x 的根本差异对照

| 维度 | v0.6.x（侧边栏多视图范式） | v2.0.0（工作台范式） |
|------|---------------------------|----------------------|
| 主舞台 | 侧边栏切换的多个独立 view | 中央单一表格工作台（占 70%） |
| 操作入口 | 视图内四段垂直布局 + 视图间跳转 | 工具栏（上）+ 操作栏（左）触发，就地落表 |
| 数据承载 | `App.jsx` useReducer 跨视图 state | Sheet/Tab 模型，当前活动表为唯一操作对象 |
| 脱敏/校验流程 | 导入→预处理→脱敏→校验→导出 串联视图 | 选区→应用规则→结果就地渲染（同一张表） |
| AI | 无 | 右侧面板预留位 + IPC 契约（v2.0 不实现真实 AI） |
| 后端 API | Tauri 命令绑定各 view | Tauri 命令围绕 Sheet/选区/列操作重组 |
| 前端栈 | React 18 + Ant Design 5 | 同（React 18 + Ant Design 5），但组件层重组 |

### 迁移策略（既有能力不丢）

v2.0.0 必须迁移以下 v0.6.x 既有能力到工作台范式，**功能等价、交互升级**：

- CSV/XLSX/JSON/SQL/TXT/日志/PCAP 导入与自动识别 → 工具栏「导入」按扩展名识别，导入结果直接进新 Sheet。
- 脱敏（内置 maskers + 富规则 + 算子） → 操作栏「脱敏」入口，对当前表选区/选列应用规则，结果写新 Sheet 或就地高亮。
- 校验（validators + 算子） → 操作栏「校验」入口，对当前表应用，结果以 cell 合法性矩阵渲染（非法红底）。
- 数据提取（phone/bankcard/ip/idcard/name/mac） → 操作栏「提取」入口，从当前表或文本输入提取，结果进新 Sheet。
- 导出（CSV/XLSX/txt/json + 列选列序） → 工具栏「导出」对当前表执行。
- 规则管理（内置 + 用户规则 + 试运行） → 操作栏「规则管理」打开侧弹/抽屉面板，独立于表格但回填到当前操作。
- 搜索（统一 SearchQuery） → 操作栏「搜索」对当前表搜索，结果高亮 + 跳转。
- Tools（SQL 解析/正则构造/加解密） → 操作栏「Tools」子菜单入口。
- 日志扫描（SQLi 签名 + 盲注聚合 + 数据库还原） → 日志导入后自动/手动扫描，结果进 Sheet + 右侧面板展示。
- PCAP 扫描（tshark 子进程 + HTTP 字段提取） → 流量导入后扫描，结果进 Sheet。
- 设置（tshark 路径 + 持久化） → 工具栏或操作栏底部「设置」入口。

## 范围

### 包含

- 工作台 Shell：上方工具栏 + 左侧操作栏 + 中央表格主视图（占 70%）+ 右侧 AI 预留面板（占位）。
- Sheet/Tab 模型：多源数据以 Sheet 承载，Tab 切换，"当前活动表"为操作对象。
- 表格核心：基于 antd Table 的可编辑/选区/列勾选/列序/分页/状态高亮的中央组件。
- 工具栏：导入（多格式自动识别）/ 导出（多格式 + 列选列序）/ 格式 / 撤销重做 / 列操作（增删序）/ 运行高频动作。
- 操作栏：脱敏 / 校验 / 提取 / 规则管理（侧弹）/ 搜索 / Tools（SQL/正则/加解密）/ 设置。
- 右侧 AI 面板：版式 + 占位 + 预留 IPC 契约（`invoke_ai_op`、`ai_suggest` 等空实现命令），v2.0 不接真实 LLM。
- 既有能力迁移：脱敏/校验/提取/导出/规则/搜索/Tools/日志扫描/PCAP 扫描/设置全部迁移到工作台范式，功能等价。
- 后端命令层重组：Tauri 命令围绕 Sheet/选区/列操作重新组织；`crates/core` 业务逻辑复用，不重写算法。
- 版本号 bump：0.6.8 → 2.0.0（5 处 manifest 同步）。
- 文档体系：完整版本文档（本文件 + 技术方案 + 更新日志 + QA 报告）+ 更新 04-版本标准 里程碑。

### 不包含

- 真实 AI 能力（自然语言操作、LLM 集成、智能规则推荐等）——v2.0 仅占位 + 预留接口，推迟到 v2.1+。
- 新的业务算法（新脱敏器/新校验器/新扫描签名）——v2.0 是范式重构，不是功能扩张；算法复用 v0.6.x。
- 在线/SaaS/云同步——继续本地优先。
- 移动端/平板适配——桌面端单平台。
- 旧 v0.x 多视图代码的物理删除——v2.0 期间旧组件可保留为"工具面板"参考，迁移完成后清理作为 v2.0 内部任务。

## 验收标准

- **范式验收**：应用启动即见三栏工作台（工具栏/操作栏/中央表格/右侧 AI 占位），中央表格占 70%；无 v0.x 侧边栏多视图范式残留（旧组件已清理）。
- **能力等价**：v0.6.x 的脱敏/校验/提取/导出/规则管理/搜索/Tools/日志扫描/PCAP 扫描/设置十项能力在工作台范式下功能等价，行为不回归（用 v0.6.x fixture 跑相同结果）。
- **Sheet 模型**：多源数据以 Sheet 承载，Tab 切换，"当前活动表"为操作对象；切 Sheet 不丢数据。
- **就地操作**：脱敏/校验结果就地反映在表格（高亮/矩阵）或写新 Sheet，不跳转视图。
- **AI 占位**：右侧面板渲染占位 + `invoke_ai_op`/`ai_suggest` 空实现命令存在且可调，返回明确"未实现"占位。
- **后端复用**：`crates/core` 业务逻辑零重写；Tauri 命令层围绕 Sheet/选区/列操作重组。
- **构建/测试**：`npm run build` 绿；`cargo test --workspace` 全绿（含 e2e）；既有测试不回归。
- **版本同步**：5 处 manifest 版本号 0.6.8 → 2.0.0 同步；`docs/versions/2.0.0/更新日志.md` 与 TASK-BOARD 对齐；`docs/qa/versions/2.0.0/QA-审计报告.md` 结论 `qa_passed`。

## 风险

- **范围蔓延**：工作台范式容易诱发"顺便加 AI/顺便加新能力"的冲动。控制手段——AI 仅占位、不新增业务算法、迁移而非扩张。
- **既有能力回归**：迁移十项能力到新范式，任一项行为回归都会拖慢验收。控制手段——每项迁移任务用 v0.6.x fixture 做等价验证。
- **表格组件复杂度**：antd Table 的选区/列勾选/列序/状态高亮组合可能触发性能或交互边界。控制手段——T20-3 独立验收，先打通最小选区再扩。
- **后端命令层重组破坏前端调用链**：Tauri 命令重新组织可能误伤既有调用。控制手段——命令层重组作为各迁移任务的一部分，而非独立大重构任务，边迁移边验证。
- **旧组件清理误删**：T20-16 删旧 view 可能误删仍被引用的组件。控制手段——清理前先 `npm build` 验证无残留引用。
