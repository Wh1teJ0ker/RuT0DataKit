# RuT0DataKit 需求文档

> **版本覆盖说明**：本文为 v1.0.0 范围文档。v0.8.0 及之前的历史代码与文档归档于 `release/v0.8.0` 分支，v1.0.0 起完全从零重写，不复用历史代码。

## 1. 产品定位

RuT0DataKit 是面向数据安全 CTF 的**本地优先**数据工作台。目标选手在竞赛中拿到结构化表格、日志、流量包等附件后，在一个桌面应用内完成「导入 → 工作台就地分析 → 导出」的闭环，帮助数据安全方向题目快速完成数据脱敏、日志取证、流量敏感数据提取等任务。

核心范式：**以表格工作台为中心**——中央 Sheet/Tab 多页承载多源数据，上方工具栏放高频操作，左侧操作栏放中频分析能力，右侧 AI 面板预留。所有处理在本地完成，数据不外发。

非目标：

- 不做通用渗透 / 漏扫 / Webshell 管理。
- 不做密码学爆破、隐写通用解密（仅在涉及题目样本时做最小适配，留接口不内置实现）。
- 不做 SaaS / 云同步 / 账号体系。
- 不提供 CLI 形态（v1.x 仅交付 GUI）。

## 2. 目标用户与场景

- 主要用户：参加数据安全方向 CTF 的选手、出题人、裁判。
- 场景：
  1. 拿到 csv/xlsx，在工作台 Sheet 内就地完成列脱敏、校验、导出。
  2. 拿到 access.log，导入为 Sheet 后就地做注入特征识别、盲注二分还原。
  3. 拿到 pcap，导入后就地提取 HTTP 字段、敏感数据扫描。
  4. 拿到自由文本/SQL，按规范提取 PII 或还原盲注数据库结构。
- v1.0.0 仅交付承载上述场景的**框架 shell**，具体分析能力从 v1.1.0 起逐项重构。

## 3. v1.0.0 范围（MVP = 纯框架）

> **当前文档中的需求默认即 v1.0.0 MVP 范围**。v1.0.0 不实现任何业务功能，只搭建应用框架，功能从 v1.1.0 起逐项完整重构。

### 3.1 必须实现

1. **四区布局 shell**
   - 上方工具栏：导入 / 导出 / 格式 / 撤销 / 列操作 / 运行（高频入口，v1.0.0 仅导入/格式/列操作可用，其余占位提示「v1.1+」）
   - 左侧操作栏：脱敏 / 校验 / 提取 / 规则 / 搜索 / Tools / 设置（中频，v1.0.0 仅设置可用，其余点击提示「v1.1+」）
   - 中央 Workbench（占比 70%）：Sheet/Tab 多页 + antd Table（选区框选 / 列 checkbox 选 / 列拖拽排序 / 状态高亮）
   - 右侧 AI 面板：占位 + 预留 IPC 契约（`ai_suggest` / `invoke_ai_op` 空实现，v1.0.0 显示「AI 能力 v1.1+」占位）
2. **Sheet/Tab 多页工作台**
   - 新建 Sheet（导入文件时自动创建）、切换、关闭、重命名
   - 每个 Sheet 独立承载一组数据（headers + rows），Tab 标题显示源文件名或自定义名
3. **antd Table 集成**
   - 选区框选（鼠标拖拽选矩形区域）
   - 列 checkbox 选（表头 checkbox 勾选目标列）
   - 列拖拽排序（拖拽表头调整列顺序）
   - 状态高亮（非法/已脱敏/命中 等状态 cell 着色，v1.0.0 仅框架，具体状态规则随 v1.1+ 能力迁移）
4. **SQLite 全量数据持久化**
   - 选用 `rusqlite`（bundled 特性，编译自带 SQLite，无系统依赖）
   - 持久化导入数据全量 cell（按 sheet/行/列存入表）
   - 持久化操作日志（脱敏/校验/提取参数与结果快照，v1.0.0 仅记录导入操作）
   - 重启应用可重打开 session 看到完整表格 + 历史操作记录
5. **自动检查更新（Tauri updater 插件，带签名）**
   - 启动后台检查 GitHub Release latest 版本
   - 有新版提示用户，确认后下载 + 验签 + 一键安装
   - 配置 `TAURI_SIGNING_PRIVATE_KEY` 签名密钥 + updater JSON
6. **设置入口**
   - 检查更新（手动触发 updater）
   - tshark 路径配置（v1.1+ PCAP 能力预留，v1.0.0 仅 UI 入口）
   - DB 路径显示（SQLite 文件位置）
7. **AI 面板占位 + IPC 契约**
   - 右侧面板渲染占位 UI（「AI 能力 v1.1+」）
   - Tauri IPC 契约 `ai_suggest` / `invoke_ai_op` 空实现（返回 `unimplemented`，预留接口不实现逻辑）

## 4. 非功能需求

- **本地优先**：所有数据处理在本地完成，数据不外发。唯一网络调用是 updater 检查版本元数据 + 下载签名产物，不传用户数据。
- **跨平台**：macOS（arm64/x64）、Windows（x64）、Linux（x64）三平台桌面应用。
- **持久化**：SQLite 单文件 DB，便于备份迁移。重启不丢数据。
- **性能基线**：10 万行 × 10 列 CSV 导入 < 5s，Table 渲染分页（默认 50/页）。
- **可维护**：Rust core + Tauri 命令层 + 前端三层清晰分离，IPC 契约显式定义。

## 5. 安全约束

> 保留 v0.1.0 §6 安全约束，v1.0.0 不变。

- **不外发数据**：全本地处理；规则与样本不上传。
- **updater 例外**：自动检查更新仅拉取版本元数据（版本号、更新日志、签名产物下载地址）与签名后的安装包，不传输用户数据或样本。updater 请求由 Tauri 插件发起，不经过用户业务代码。
- **签名验证**：updater 下载的产物必须通过 Tauri updater 签名校验（`TAURI_SIGNING_PRIVATE_KEY` 对应的公钥），验签失败拒绝安装。
- **DB 本地**：SQLite 文件存储在 `app_config_dir`，不上传任何远程服务。

## 6. v1.0.0 验收标准

1. `cargo tauri dev` 启动后看到四区布局：上方工具栏 + 左侧操作栏 + 中央 Workbench + 右侧 AI 占位面板。
2. 左侧操作栏 7 项（脱敏/校验/提取/规则/搜索/Tools/设置）可见，点击前 6 项弹出「v1.1+」提示，点击「设置」进入设置页。
3. 工具栏「导入」可选 CSV/XLSX 文件 → 自动新建 Sheet → 中央 Table 渲染数据 → 写入 SQLite。
4. Sheet/Tab 可新建/切换/关闭/重命名；多 Sheet 并存。
5. antd Table 支持选区框选（矩形区域）、列 checkbox 勾选、列拖拽排序。
6. 关闭应用后重启，设置页可看到历史 session 列表，点击重打开可看到完整表格数据 + 操作日志。
7. 设置页可手动触发「检查更新」，updater 向 GitHub Release 发请求比对版本号（v1.0.0 无新版时提示「已是最新」，有新版时提示下载安装——需已发布至少一个 Release）。
8. 右侧 AI 面板显示占位 UI；`ai_suggest` / `invoke_ai_op` IPC 调用返回 `unimplemented` 不 panic。
9. `cargo test --workspace` 全绿（core 骨架 + SQLite 管理器单测 + updater 配置单测）。
10. `pnpm --prefix frontend run build` 0 error。
11. 三平台（macOS/Windows/Linux）`cargo tauri build` 产物存在。
