# RuT0DataKit 需求文档

## 1. 产品定位

面向数据安全 CTF 的快速分析工具箱。针对竞赛中常见的三类附件——结构化表格（CSV / XLSX）、日志文件（access.log 等通用日志）、网络流量（PCAP / PCAPNG）——提供"选文件 → 自动识别 → 按规则跑 → 出报告"的一站式流程，帮助选手在数据安全方向题目中快速完成数据脱敏、日志取证分析、流量包敏感数据提取。

非目标：

- 不做通用渗透 / 漏扫 / Webshell 管理。
- 不做密码学爆破、隐写通用解密（仅在涉及题目样本时做最小适配，如 blind_watermark 调用留接口，不内置实现）。
- 不做 GUI 之外的 SaaS / 云同步。

## 2. 目标用户与场景

- 主要用户：参加数据安全方向 CTF 的选手、出题人、裁判。
- 场景：
  1. 拿到 csv/xlsx，按脱敏规范输出脱敏后表格（v0.1.0 交付）。
  2. 拿到 access.log，解析 CLF，提取注入 / 越权 / 弱口令 / SQLi 等攻击特征，并对 query 串做敏感数据扫描（v0.2.0 交付）。
  3. 拿到 pcap，自动过滤 HTTP、解码参数、重组 base64 片段、扫描身份证 / 手机号 / MAC / 邮箱 / 银行卡等敏感数据（v0.3.0 交付）。
  4. 数据规范提取（valid/invalid 校验）作为 v0.1.0 的同源能力，与脱敏共用 reader 与 masker/validator 注册表；是否在 v0.1.0 默认交付 GUI 入口由任务细化决定。
  5. 拿到自由文本（.txt / 粘贴文本），按规范提取 phone/bankcard/ip 三类 PII 并按 `type_value` 格式导出（v0.4.3 交付）。

## 3. 版本范围

### v0.1.0 — 数据脱敏切片（四功能重构补丁，T0-15 ~ T0-20）

- CSV/XLSX reader + 脱敏 pipeline + masked.csv 导出。
- 内置 maskers：idcard / phone / bankcard / email / name / customer_id / custom。
- 富规则 maskers（v0.1.0 重构新增）：`regex_replace` / `regex_extract` / `delete` / `replace`。
- 行选择 pipeline：`mask_pipeline_selected` 只对勾选行脱敏，未选中行原样输出（保留向后兼容）。
- **列选择 pipeline**（T0-15）：`mask_pipeline_columns(records, rules, selected_columns: &HashSet<String>)` 只对勾选列应用 masker，未勾选列原样；`selected_columns` 与 `rules.maskers[].field` 取交集。
- **校验 pipeline**（T0-15）：`validate_pipeline(records, rules) -> ValidateResult { headers, rows, valid_matrix, summary }`，逐 cell 填合法矩阵；未声明 validator 的列全 true。

- **四功能导航**（T0-17 ~ T0-19）：侧边栏 4 active view（数据脱敏 / 数据校验 / 数据导出 / 规则管理）+ 2 disabled（日志 v0.2.0 / 流量 v0.3.0）。
  - 数据脱敏 view：导入 CSV/XLSX → 预览表格 → **列勾选**（表头列 checkbox）→ 规则面板 → 「应用规则到勾选列」。
  - 数据校验 view：选 validator → 「运行校验」→ 逐 cell 合法性矩阵展示；「跳转到数据导出」按钮把当前数据带入导出 view。
  - 数据导出 view：选数据源（原始数据 / 脱敏数据 / 校验数据）→ **列选 + 列序拖拽 + 格式（CSV / XLSX）** → 「导出」；XLSX 由 src-tauri 的 `rust_xlsxwriter` 写出。

- **跨视图 state 持久化**（T0-17）：前端 `App.jsx` 顶层 `useReducer` 常驻，`SET_VIEW` 只切 view 不重置数据；切回各 view 数据不丢。
- 验收样本：`tests/fixtures/samples/csv/sample_mask.csv` + `default_mask.yaml`。

**UI 重构 + 规则引擎重构补丁（T0-21 ~ T0-26）**：

### v0.2.3 — 日志扫描盲注三轴优化

- 算法优化（T3-1）：`blind_aggregator` 的 `true_size` 判定由 v0.2.2 的 `min(body_size)`（fixture-specific 假设）改为 `mode_per_position_true_size`——按 `char_position` 分组取每个混合位置真假簇 body_size 的 min/max → 跨位置众数（并列取较小者），无混合位置退化 `min(body_size)`；修复 v0.2.2 R1 第 4 read_target（false 频次高于 true）全 `?` 回归。自带正则从单层扩到两层嵌套 `((?:[^()]|\((?:[^()]|\([^()]*\))*\))*)` 覆盖 `where table_schema=database()`。`AggregatedResult` 新增 `separator_char: Option<char>` 从 `read_target` 首个 `0xNN` 字面量解码（`0x7e`→`~`）。
- 盲注类型扩展（T3-2）：`BlindProbe` 新增 `probe_kind: ProbeKind`（`AsciiBinary` / `Equality` / `Length`）+ `equality_char`；新增 equality / length 两条正则；聚合分组键升级为 `(read_target, source_ip, ProbeKind)` 三元组防串扰；`AggregatedResult` 新增 `kind` 字段；`PositionDetail.status` 新增 `equality_resolved` / `length_resolved`。
- GUI 显示优化（T3-3）：LogView 段 ③.5 inner Card 加 kind Tag 着色（ascii_binary=red / equality=orange / length=blue）+ separator 高亮（volcano Tag + 复制按钮）+ Collapse 内嵌 Table 位置明细（列 位置/字符/ASCII/探针数/状态，status Tag 6 色着色），替代 v0.2.2 的 JSON.stringify Tooltip。
- 向后兼容：新字段 `kind` / `separator_char` 均 `#[serde(skip_serializing_if)]`，不破 v0.2.2 既有消费者。

### v0.2.4 — 日志扫描盲注聚合数据库格式还原

- 后端结构 + 算法（T4-1）：`blind_aggregator` 新增 `ReconstructedDatabase` / `ReconstructedTable` / `ReconstructedRow` 三结构 + `BlindAggregator::reconstruct_database(&[AggregatedResult]) -> ReconstructedDatabase` 关联函数。三步算法：Step1 把每个 `AggregatedResult` 的 `read_target` 按 4 类模式分类（`schema`=database() / `table_list`=group_concat(table_name) from information_schema.tables / `column_list`=group_concat(column_name) ... where table_name='X' / `row_data`=group_concat(col1,0xNN,col2,...) from <table>，未匹配进 `unmatched_results`）；Step2 拼装：schema 直填 → table_list 解码的每个表名按 `table_name='T'` 谓词匹配 column_list（无谓词按索引对齐）→ 全量 columns（无列清单兜底 row_data_columns）→ 按 `from T` 匹配 row_data → 行按 `,` split + 列按 `column_separator`（`0xNN` 解码）split → 映射到 row_data_columns → 投影到全量 columns，未 fetch 列 `None`；Step3 unmatched 原样塞回兜底。
- pipeline 透传（T4-2）：`scan_log` 末尾调 `reconstruct_database`，结果塞 `Report.extra.reconstructed_database`（与 `blind_aggregation` 并列，向后兼容 v0.2.3）。fixture 4 类探针自动还原：schema="person" / 1 表 person_data / 7 列 (id/username/password/sex/birth/idcard/phone) / ≥2 行 / row[0].id=Some("1") / row[0].username=contains zhangsan/lisi。
- GUI 显示（T4-3）：LogView 段 ③.5 之前新增段 ③.5a「还原数据库视图」Card——顶部 Descriptions（schema + 表数 + unmatched 数），每张 ReconstructedTable 一个 inner Card + antd Table（全量列做表头，未 fetch 单元格显示 `-`），unmatched 非空时下方 Divider + 简版列表；空态 Empty。段 ③.5 改名「原始聚合明细」保留兜底（kind Tag / separator 高亮 / Collapse 位置明细表全部不动）。
- 向后兼容：`blind_aggregation` 数组保留不动，新增 `reconstructed_database` 键；新字段 `schema`（Option）/ `column_separator`（Option）`#[serde(skip_serializing_if)]`。
- 非范围：`group_concat SEPARATOR 'X'` 子句解析、三层+嵌套正则、UNION 报错聚合 / 时间盲注聚合留 v0.3.0+。

### v0.3.0 — 流量包处理切片

- Pcap 模块：tshark 子进程后端（`tshark -Y "http.request" -T fields -e ...` → TSV → HttpRequest）+ 双重 URL 解码 + 自动 base64 字段解码（JSON / form-urlencoded / 纯文本三降级 + charset/length/printable_ratio 三重防误伤）+ `reassemble_base64.param` 规则兜底 + 复用 `DefaultSensitiveScan` 敏感扫描（仅敏感，不做 SQLi 签名）+ 产出 `Report(kind="pcap_scan")`，summary 含 `total_requests` / `sensitive_hits` / `decoded_fragments` / `top_src_ips`。
- GUI PcapView 四段布局：① 导入 `.pcap/.pcapng`；② 原始 HTTP 请求表（frame_no / src_ip / dst_ip / method / host / uri / body 预览 / user_agent）；③ summary Descriptions + top_src_ips Tag；④ Findings 表（type Tag 着色 / value / location=frame:N / context）。侧栏 pcap 项启用。
- tshark 缺失：`CoreError::DependencyMissing("tshark")`，GUI 弹 `message.error("流量分析需要系统 tshark，请先安装 Wireshark CLI (brew install wireshark)")`。
- 验收样本：`tests/fixtures/samples/pcap/data.pcapng`（60290 帧 / 5000 HTTP POST，每 POST body 为 JSON 各字段 base64 编码）。

### v0.4.0 — 架构性质完整重构（7 界面 + 多标签规则引擎 + 统一预处理 + 搜索 + Tools）

- **界面 1 数据预处理**：统一入口读 csv / xlsx / sql / pcap / log / json 6 类源，全部归一化到 `Records { headers, rows }` CSV 表格语义。`read_records(path)` 在 core 层按 `detect_type(path)` 分派到 `CsvReader` / `XlsxReader` / `SqlReader`（按 `;` 切分语句、跳过字符串内分号，产出 `sql_text` + `statement_type` 两列）/ `JsonReader`（数组对象 union keys 作 headers、单值数组归 `value` 列、标量 to_string）/ `PcapRecordsReader`（tshark 缺失返回 `DependencyMissing("tshark")`）/ `LogRecordsReader`（同 v0.2.0 行解析口径产出统一列）。前端 `PreprocessView` 调 `read_records` 命令后写入 `state.records`，并暴露「搜索 / 数据脱敏 / 数据校验 / 数据导出」4 个跳转按钮。
- **界面 2 规则管理**：`FieldRule` 与 `MaskRule` 均增加 `tags: Vec<String>`（默认空 Vec 向后兼容），`RuleSet::by_tag(tag)` / `by_tag_mask(tag)` 按标签过滤。一条规则可同时挂多个标签（如 `[mask, sensitive]` / `[validate, sensitive]`），让同一规则在脱敏 / 校验 / 搜索 / SQL 解析多个视图复用。`RulesView` Drawer 支持多标签编辑。
- **界面 3 搜索**：`search_records(records, query)` 统一入口，`SearchQuery` 枚举 `Keyword { terms, mode: And|Or }` / `Regex { pattern }` / `ExactField { field, value }`。keyword 走 `SearchIndex::build` 倒排索引（term → (row, col) 反向表）+ `search_keyword`；regex 线性扫，非法 pattern 返回 `InvalidInput`；exact_field 按列名定位 + 精确匹配。`SearchView` 三选 Radio + 命中表（行号 / 列名 / 字段值 / 片段，片段用 React `<mark>` 高亮，无 `dangerouslySetInnerHTML`），「跳转脱敏 / 跳转导出」按钮把命中行号去重排序写入 `state.filteredRowIndices` 后 `SET_VIEW`。大文件基线：10w 行 × 10 列 build < 5s、keyword 单次索引查询 < 200ms（见 `search_big_file` e2e）。
- **界面 4 数据脱敏**：四段垂直——① 原始数据表（v0.4.0：消费 `state.filteredRowIndices`，开启「仅搜索命中行」开关时按命中行过滤）→ ② 表头-规则映射（全局规则按 `mask` 标签筛 + 无标签兼容）→ ③ 预览表 → ④ 操作面板（应用 / 导出跳转）。`mask_pipeline_columns` 按列勾选只对选中列脱敏。
- **界面 5 数据校验**：四段垂直同上；非法 cell 红底高亮；全局规则按 `validate` 标签筛。
- **界面 6 数据导出**：单一 antd Table——表头 Checkbox 勾选导出列 + 上下移调序 + 单元格预览；源数据 Select（脱敏后 / 校验后 / 原始）+ 行过滤 Select（仅校验源：全部 / 仅合法 / 仅非法）+ 格式 Select（CSV / XLSX / JSON）；v0.4.0：当源为原始数据且 `filteredRowIndices` 非空时，「仅导出搜索命中行」开关默认开启（写入 `selectedRowIndices` 传后端）。
- **界面 7 Tools**：antd `Tabs` 下拉两个子工具——(a) **SQL 解析**：`parse_sqls(inputs: Vec<SqlParseInput>) -> SqlParseResult { probes, aggregated, reconstructed, parsed_payloads }`，`extract_blind_probe(sql, response_body_size, source_ip)` 从纯 SQL 抽出 `BlindProbe`（AsciiBinary / Equality / Length 三类），`BlindAggregator::collect_from_probes → aggregate → reconstruct_database` 自动还原出 `ReconstructedDatabase { schema, tables: Vec<ReconstructedTable>, unmatched_results }`；非盲注 payload（union / error / time / tautology / comment）走 `parse_payload` 进入 `parsed_payloads` 兜底。前端 `SqlParseTool` 渲染 schema/表数/探针数 Descriptions + 每张表 inner Card + unmatched 兜底 + 探针明细表 + payload 语义解析表（comparator / compared_ascii 等）。
  - **v0.7.0：移除 (b) 正则解析子工具**（`explain_regex` / `regex_construct` / `regex_template` 三个 core 模块 + 两个 Tauri 命令 + `RegexTool` / `RegexConstructTab` 前端组件 + Sidebar `tools.regex` 入口 + state 5 个 REGEX_* 字段全部删除）。Tools 现仅余 SQL 解析 + 加密/解密两个子工具。
  - **v0.7.0：PreprocessView 表头新增「SQL 解析」按钮**（`ConsoleSqlOutlined` 图标，与 ✏ 重命名并列）：点击后取该列全部非空行作为 `SqlParseInput[]` 调 `parse_sql_tool`，结果预填 `sqlParseInput`（textarea 多行）+ `sqlParseResult`，然后 `SET_VIEW("tools")` + `SET_TOOLS_ACTIVE_TAB("sql")` 跳转 Tools/Sql 复用现有 UI 继续调整或重跑。空列 `message.warning` 不跳转；失败 `message.error` 不清空已有结果。
- **跨视图 state 不丢**：`App.jsx` 顶层 `useReducer` 内存常驻，`SET_VIEW` 只切 view 不重置数据；搜索命中行号、脱敏结果、校验结果、SQL 解析结果均跨视图保留。
- **不外发数据**：全本地处理；规则与样本不上传（保留 v0.1.0 §6 安全约束，v0.4.0 不变）。
- 验收样本：`tests/fixtures/samples/sql/sample.sql`（6 类语句类型 + 字符串内分号反例）/ `tests/fixtures/samples/json/sample.json`（3 对象数组 union keys）/ 复用 v0.1.0 csv/xlsx + v0.2.0 log + v0.3.0 pcap。

## 5. 技术约束

- 核心全部 Rust 实现，不引入 Python 运行时（pcap 在 v0.3.0 通过调用系统 `tshark` CLI，不绑 pyshark/scapy）。
- GUI 用 Tauri v2；前端 v0.1.0 采用 React 18 + Vite 5 + Ant Design 5 + @ant-design/icons（纯白主题，无 emoji，下拉使用 antd `Select` 组件）。
- 规则以 YAML 文件表达 + 内置 Rust 校验器/脱敏器注册表；用户可在 GUI 加载自定义 YAML。
- 校验与脱敏是两条独立 pipeline，可分别调用（v0.1.0 交付脱敏 pipeline `mask_pipeline` / `mask_pipeline_selected` / `mask_pipeline_columns` + 校验 pipeline `validate_pipeline`，四功能 view 全部交付：数据脱敏 / 数据校验 / 数据导出 / 规则管理）。
- 前端跨视图 state 持久化：`App.jsx` 顶层 `useReducer` 内存常驻，`SET_VIEW` 只切 view 不重置数据；切回各 view 数据不丢。
- XLSX 导出依赖 `rust-xlsxwriter`（src-tauri 侧），CSV 导出依赖 `csv` crate（src-tauri 侧）；前端规则 YAML 序列化依赖 `js-yaml@5.2.1`。
- 样本放在 `tests/fixtures/`，可在 `cargo test` 中复现。
- 规则引擎基于抽象算子 `MaskOp` / `ValidateOp`：内置 masker / validator 名全部收敛到通用算子枚举 + 预置库映射表；新增脱敏类型 = 加一个 `MaskOp` variant + 在 `rules::presets` 加一行预置映射，`build_masker` 自动 dispatch，无需改 pipeline 或前端调用约定。

## 6. 非功能要求

- macOS（arm64）为主开发平台；CI 跑 Linux。
- 单文件 ≤ 200MB 可在 30s 内完成扫描（v0.1.0 用 fixture 验证基线）。
- 不外发数据：全本地处理；规则与样本不上传。

## 7. 共享能力预留

为避免 v0.2.0/v0.3.0 大规模重构，v0.1.0 在实现脱敏时必须同时落地以下"共享底座"：

- `Validator` / `Masker` trait 与 `ValidatorRegistry` / `MaskerRegistry`。
- `SourceReader` trait + `Records` 抽象（csv/xlsx 实现两种，log/pcap 在后续版本实现自己的 reader，但复用 Records 思路）。
- `SensitiveScan` trait（v0.1.0 可只留 trait + 一个基于 RuleSet 的通用实现占位，具体签名规则在 v0.2.0 实现时绑定）。
- 统一 `Report` / `Finding` serde 结构（v0.1.0 脱敏报告也用该结构，kind="csv_mask"）。
- `CoreError` 含 `DependencyMissing("tshark")` 变体（v0.3.0 用，提前定义）。

这些底座在 v0.1.0 必须有最小可编译实现 + 单测，保证 v0.2.0/v0.3.0 是"扩展"而非"重构"。
