## 2. 关键模块职责

### 2.1 rules

- `RuleSet { validators: Vec<FieldRule>, maskers: Vec<MaskRule> }`，从 YAML 反序列化。
- `Validator` trait：`fn validate(&self, value: &str) -> ValidationResult`。
- `Masker` trait：`fn mask(&self, value: &str) -> String`。
- 内置校验器注册表（`ValidatorRegistry`）：name → 工厂函数。
- 内置脱敏器注册表（`MaskerRegistry`）：同上。
- 自定义规则：v0.1.x 仅支持引用内置 validator/masker；YAML 中可声明 `regex:` 做正则兜底校验。
- 可扩展算子模型（T0-21 增）：`rules::operator` 模块定义两个通用算子枚举，作为内置 masker/validator 的统一收敛点，对外暴露稳定的可扩展 API：
  - `MaskOp`（4 种）：`Template` / `SplitTemplate` / `RegexReplace` / `ConstReplace`。配套 `MatchMode { All, First }`、`MaskOp::from_rule(name, params)` 构造器、`apply_mask_op(op, value)` 应用函数。11 个旧 masker 名（含 6 预设 `idcard_mask` / `phone_mask` / `bankcard_mask` / `email_mask` / `name_mask` / `customer_id_mask` + 富规则 `custom` / `regex_replace` / `regex_extract` / `delete` / `replace`）均收敛到这 4 种算子。
  - `ValidateOp`（3 种）：`Regex` / `Algorithm` / `RegexWithGuard`。配套 `AlgoKind` / `GuardKind`、`ValidateOp::from_rule(rule)` 构造器、`apply_validate_op(op, value)` 应用函数。8 个旧 validator 名收敛到这 3 种算子（`Algorithm` / `RegexWithGuard` 委托给既有 `IdCardValidator` / `BankCardValidator` / `PhoneValidator` / `MacValidator` 结构体，复用既有算法实现）。
  - `rules::presets` 模块提供 `lookup_mask_preset(name)` / `lookup_validate_preset(name)` 预设查表，以及 `list_mask_op_types()` / `list_validate_op_types()` 列举所有可识别名（含预设别名，保证 YAML 向后兼容）。
  - `build_masker` / `build_validator` 签名与行为不变，内部改走 `Op::from_rule → apply_*_op` 路径；旧 `Masker` / `Validator` trait、`MaskRule` / `FieldRule` / `RuleSet` 结构、`mask_pipeline*` / `validate_pipeline` 全部保持原样。

### 2.2 readers

```rust
pub trait SourceReader {
    fn detect(path: &Path) -> bool;        // 后缀 / magic
    fn read(&self, path: &Path) -> Result<Records>;
}
```

`Records` = 行流（每行 `Vec<(String, String)>` 字段名→值），csv/xlsx 都映射到它。v0.1.1/v0.1.2 的 log/pcap 不强制走该 trait（它们没有"字段名→值"结构），但复用其读取抽象思路，各自定义独立 output。

### 2.3 maskers（内置，v0.1.0 必交付）

| name | 规则 |
|------|------|
| idcard_mask | 前6+后4，中间8位 `*` |
| phone_mask | 前3+后4，中间4位 `*` |
| bankcard_mask | 前6+后4，中间 `*` |
| email_mask | 本地部分首末字符保留，中间 `*`；域名完整 |
| name_mask | 2字→`X*`；≥3字→`X*…*Y` |
| customer_id_mask | 首字符保留，其余 `*` |
| custom | YAML 提供 `keep_prefix / keep_suffix / mask_char / mask_min_len` 通用参数 |
| regex_replace | 富规则：`pattern` 正则 + `replacement`（支持 `$1`/`$2` 捕获组）；非法/缺失 pattern 时原值返回 |
| regex_extract | 富规则：`pattern` 正则提取首个匹配子串；无匹配返回原值 |
| delete | 富规则：对任意输入返回空串 `""`，无参数 |
| replace | 富规则：对任意输入返回 `with` 字符串；缺失 `with` 时退化为空串 |

> 富规则（`regex_replace` / `regex_extract` / `delete` / `replace`）由 v0.1.0 重构（T0-10）落地，经 `build_masker` 统一 dispatch，可与 7 个内置 masker 混挂在同一 `RuleSet.maskers` 中。

**抽象算子模型（T0-21 增）**：

- `MaskOp` 枚举 4 variant：`Template(TemplateOp)` / `SplitTemplate(SplitTemplateOp)` / `RegexReplace(RegexReplaceOp)` / `ConstReplace(ConstReplaceOp)`；配套 `MatchMode { All, First }`。
- 公共 API：`apply_mask_op(op: &MaskOp, value: &str) -> String`；`MaskOp::from_rule(name, params) -> Option<MaskOp>` 构造器；`MaskOp` impl `Masker` trait，可直接作为 `Box<dyn Masker>` 注入 pipeline。
- 预置库（`rules::presets`）：`lookup_mask_preset(name) -> Option<MaskOp>` + `list_mask_op_types() -> Vec<(op_name, label)>`（10 项 = 4 通用算子 + 6 预置别名 `idcard_mask` / `phone_mask` / `bankcard_mask` / `customer_id_mask` / `name_mask` / `email_mask`）。
- `build_masker` 内部走 `MaskOp::from_rule` 路径，签名与行为不变；旧 `MaskRule` / `RuleSet` / `mask_pipeline*` 全部保留向后兼容。
- 新增脱敏类型 = 加一个 `MaskOp` variant + 在 `rules::presets` 加一行映射，`build_masker` 自动 dispatch，无需改 pipeline 或前端调用约定。

**按列勾选脱敏 pipeline（T0-15 增）**：

```rust
pub fn mask_pipeline_columns(
    records: &Records,
    rules: &RuleSet,
    selected_columns: &HashSet<String>,
) -> Result<MaskResult, CoreError>;
```

只对同时满足「在 `selected_columns` 中」且「在 `rules.maskers[].field` 中」的字段应用 masker；未勾选的规则列原样；`selected_columns` 中未声明规则的列原样；未知名 masker 静默跳过。返回与 `mask_pipeline` 同形 `MaskResult`，`summary.by_field` 只统计实际被 masker 调用的字段。

向后兼容：旧 `mask_pipeline` / `mask_pipeline_selected`（行选择）保留不动，三者共用 `build_masker` dispatch 与 `MaskResult` 产出结构。

### 2.4 validators（内置，v0.1.0 留接口+注册表，具体实现可按需提前到 v0.1.0 或后置）

| name | 规则 |
|------|------|
| idcard | 18位，地址码+出生日期码(YYYYMMDD 有效)+顺序码+校验码(weights `[7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2]`, mod 11 查表 `10X98765432`) |
| phone | 11位数字；号段集合可配置（内置 CTF 虚假号段集 + 真实三大运营商号段集，由规则 YAML 选择 `prefix_set: ctf\|real`） |
| bankcard | 13..19 位数字 + Luhn 校验 |
| email | 标准邮箱正则 |
| mac | 通用 `([0-9A-Fa-f]{2}[:-]){5}[0-9A-Fa-f]{2}`；可加 `prefix` 约束 |
| ip | IPv4，禁前导零，0..255 |
| username | `^[A-Za-z0-9]+$` |
| name | 全中文 `^[\u4e00-\u9fa5]+$` |
| birth | 8位 YYYYMMDD |
| address | 全中文 + 号(1-1500) + 室(101-999) |
| password | 长度≥8 + 大写/小写/数字/符号各一 |

> 说明：v0.1.0 的脱敏 pipeline 不强依赖 validators，但 SensitiveScan 与 v0.1.1 日志扫描会用到。v0.1.0 内至少落地 idcard/phone/bankcard/email/mac/username/name 这几个被脱敏/扫描共用的校验器，其余（birth/address/password/ip）可在 v0.1.1 随日志模块一起补齐。具体由任务 T3-v0.1.0 圈定。

**数据校验 pipeline（T0-15 增，v0.1.0 起 GUI 交付）**：

```rust
pub struct ValidateResult {
    pub headers: Vec<String>,
    pub rows: Vec<Vec<String>>,
    pub valid_matrix: Vec<Vec<bool>>,
    pub summary: ValidateSummary,
}
pub struct ValidateSummary {
    pub total_rows: usize,
    pub invalid_rows: usize,
    pub by_field: HashMap<String, usize>,
}
pub fn validate_pipeline(records: &Records, rules: &RuleSet) -> Result<ValidateResult, CoreError>;
```

逐 cell 填合法矩阵：对 `rules.validators` 中每个 `FieldRule`，`build_validator` 构造校验器并对该列所有 cell 跑 `validate`，非法 cell 置 `false`。未声明 validator 的列 `valid_matrix[*][col]` 全 true；字段不在 `headers` 中或 validator 未知名且无 regex 时该规则静默跳过（不报错）。`summary.invalid_rows` = 至少有一个非法 cell 的行数；`summary.by_field` = 每个声明了 validator 的字段的非法 cell 数。

**抽象算子模型（T0-21 增）**：

- `ValidateOp` 枚举 3 variant：`Regex(RegexOp)` / `Algorithm(AlgorithmOp)` / `RegexWithGuard(RegexWithGuardOp)`；配套 `AlgoKind { IdCard, BankCard }` + `GuardKind { PhonePrefix { prefix_set }, MacPrefix { prefix } }`。
- 公共 API：`apply_validate_op(op: &ValidateOp, value: &str) -> ValidationResult`；`ValidateOp::from_rule(rule) -> Option<ValidateOp>` 构造器；`ValidateOp` impl `Validator` trait，可直接作为 `Box<dyn Validator>` 注入 pipeline。
- 预置库（`rules::presets`）：`lookup_validate_preset(name, params, message) -> Option<ValidateOp>` + `list_validate_op_types() -> Vec<(op_name, label)>`（10 项 = 3 通用算子 + 7 预置别名 `email` / `username` / `name` / `idcard` / `bankcard` / `phone` / `mac`）。`Algorithm` / `RegexWithGuard` 委托既有 `IdCardValidator` / `BankCardValidator` / `PhoneValidator` / `MacValidator` 复用算法实现。
- `build_validator` 内部优先走 `ValidateOp::from_rule`（覆盖 regex 兜底 + 7 个预置别名），未命中时回退 `ValidatorRegistry`；签名与行为不变。

### 2.5 scan（共享，v0.1.0 占位）

```rust
pub trait SensitiveScan {
    fn scan(&self, text: &str, rules: &RuleSet) -> Vec<Finding>;
}
```

v0.1.0 提供一个基于内置 validators 的 `DefaultSensitiveScan`（可空实现或最小实现），保证 trait 与类型落盘；v0.1.1 在 log 模块真正使用时补齐实现与签名。v0.1.0 不要求其被 GUI 调用。

### 2.6 report（统一 schema，v0.1.0 落地）

```rust
pub struct Report {
    pub source: String,
    pub kind: String,             // "csv_mask" | "csv_validate" | "log" | "pcap"
    pub summary: serde_json::Value,
    pub findings: Vec<Finding>,
    pub extra: serde_json::Map<String, serde_json::Value>,
}
pub struct Finding {
    pub r#type: String,           // idcard/phone/...
    pub value: String,
    pub location: Option<String>,
    pub valid: Option<bool>,
    pub context: Option<String>,
}
```

v0.1.0 脱敏报告 `kind="csv_mask"`，summary 含 `{ total_rows, masked_rows, by_field: {field: count} }`，findings 可为空（脱敏不产出 finding，但结构统一）。

### 2.7 pcap（v0.1.2）

- `PcapScanner::scan(path, rules) -> Report`
- 内部：tshark 子进程 → TSV → HttpRequest → 双重 URL 解码 → base64 重组 → 敏感扫描。
- tshark 不存在时返回 `CoreError::DependencyMissing("tshark")`，不 panic。

### 2.8 log（v0.1.1）

- `LogScanner::scan(path, rules) -> Report`
- CLF 解析 → `LogEntry { ip, ts, method, path, query, status, ua }`。
- 攻击特征（内置签名）：SQLi / 路径穿越 / 命令注入 / 弱口令 / 越权。
- 对 query / ua 跑敏感扫描。

## 3.1 关键数据流（v0.1.0 四功能重构补丁后，T0-15 ~ T0-20）

```
[ FileToolbar 导入 CSV/XLSX ]
        │
        ▼
detect_type ──► SourceReader::read ──► Records { headers, rows }
        │
        ▼
load_preview (src-tauri command)
   - 取前 N 行 + headers，回填前端 state（filePath / headers / rows）
        │
        ├──────────────────────┬──────────────────────┬──────────────────────┐
        ▼                      ▼                      ▼                      ▼
[ MaskView ]            [ ValidateView ]       [ ExportView ]         [ RulesView ]
列勾选 selected_columns  选 validators          选数据源/列/序/格式     编辑规则 + description
+ rules.maskers         run_validate           export_records_csv     保存 YAML save_ruleset
apply_rules_cols        → state.validateResult export_records_xlsx    加载 YAML read_ruleset
→ state.maskedRows      「跳转到数据导出」       → 用户指定路径          查看规则说明 RuleDocPanel
                                                 （未选规则时占位提示）
```

跨视图 state：`App.jsx` 顶层 `useReducer` 常驻 `state = { view, filePath, headers, rows, rules, maskedRows, selectedColumns, validateResult, exportConfig, ... }`；`SET_VIEW` action 只切 `view` 字段，不重置其他数据，因此切回各 view 数据不丢。

ExportView 数据源说明：
- **原始数据**：直接投影 `state.rows`，不脱敏。
- **脱敏数据**：投影 `state.maskedRows`（已由 `apply_rules_cols` 产出）。
- **校验数据**：ExportView 校验源导出 = **先按 `selected_columns` 跑 `mask_pipeline_columns`，再投影列序**；即校验源仍会应用 maskers（src-tauri `exportRecordsCsv` / `exportRecordsXlsx` 内部先调 `mask_pipeline_columns`）。若需导出未脱敏原始数据，请选「原始数据」源。此为设计选择，非 bug。

要点：
- `mask_pipeline_columns` 是按列勾选脱敏入口；`mask_pipeline`（全量）与 `mask_pipeline_selected`（行选择）保留向后兼容，三者共用 `build_masker` dispatch。
- `validate_pipeline` 不改数据，只产出 `valid_matrix`；非法 cell 在前端高亮。
- `MaskRule` / `FieldRule` 均带 `description: Option<String>`（`#[serde(default)]`），RulesView 的 RuleDocPanel 读取该字段展示规则说明。
- 规则既可来自 YAML（`read_ruleset` / `load_ruleset`），也可由前端编辑后以 JSON 透传后端（`apply_rules_cols` / `run_validate` 直接接 `RuleSet`），不再强制走 YAML 文件。
- `summary.masked_rows` 只统计被脱敏的行；`by_field` 只统计 masker 被调用的 cell 数。

**UI 重构后数据流（T0-21~T0-26）**：

- RulesView 试运行：前端把当前规则（`MaskRule` / `FieldRule`）+ 当前数据首行 value 透传到 `preview_mask_rule` / `preview_validate_rule`（src-tauri 命令）；命令内部走 `MaskOp::from_rule` / `ValidateOp::from_rule` 构造算子 → 调 `apply_mask_op` / `apply_validate_op` → 返回 `{ input, output }`（脱敏）或 `{ input, valid, message }`（校验）；前端 Drawer 内卡片展开结果，不写 state、不改实际数据。
- MaskView / ValidateView 四段垂直：「原始数据 → 表头-规则映射 → 预览 → 操作面板」；操作面板「应用」按钮触发 `apply_rules_cols`（脱敏）/ `run_validate`（校验）→ reducer `SET_MASKED` / `SET_VALIDATE` 把结果回填 `state.maskedRows` / `state.validateResult` → 预览表 rerender；未点应用前预览表为空。MaskView「导出」按钮调 `SET_VIEW("export")` 跳转 ExportView（不直接导出）。
- ExportView 单一 Table：`columnOrder` / `exportColumns` / `exportFormat` 三段 state 常驻 reducer（切走再切回不丢）；Table 表头 checkbox 勾选列、上下移按钮调列序、单元格预览按当前列序+勾选投影数据；「导出」按钮按 `columnOrder ∩ exportColumns` + `exportFormat` 调 `export_records_csv` / `export_records_xlsx`，src-tauri 内部按数据源类型 dispatch（原始数据=直接投影 rows，脱敏数据=投影 maskedRows，校验数据=先 `mask_pipeline_columns` 再投影）。

## 4. 依赖策略

- `serde` / `serde_yaml`（或 `serde_yml`）/ `csv`（core 用 `calamine` 读 xlsx；src-tauri 用 `csv = "1"` 写 CSV 导出）/ `calamine`(xlsx 读) / `regex` / `base64`(v0.1.2) / `url`(v0.1.2) / `tempfile`(v0.1.2) / `thiserror`。
- `rust_xlsxwriter = "0"`（src-tauri 侧 XLSX 导出，T0-16 增）。
- pcap（v0.1.2）：调用 `tshark` 子进程，不直接依赖 libpcap。
- Tauri：v2 稳定版（`tauri = "2"` + `tauri-plugin-dialog = "2"`，环境无 v1）。前端基于 React 18 + Vite 5 + Ant Design 5 + @ant-design/icons；`js-yaml@5.2.1`（frontend 侧 YAML 序列化/反序列化，T0-19 增，用于 RulesView 保存/加载 YAML）。
- 公共算子 API（T0-21 增）：core 暴露 `apply_mask_op(op, value) -> String` / `apply_validate_op(op, value) -> ValidationResult` / `MaskOp::from_rule` / `ValidateOp::from_rule` / 预置库 `lookup_mask_preset` / `lookup_validate_preset` / `list_mask_op_types` / `list_validate_op_types`，作为 src-tauri 试运行命令（`preview_mask_rule` / `preview_validate_rule` / `list_mask_op_types` / `list_validate_op_types`，T0-22 增）与未来 CLI / 测试的统一入口。
- 不引入 Python、不引入 `pyo3`。

## 5. 错误处理

- 所有公共 API 返回 `Result<T, CoreError>`，`CoreError` 用 `thiserror` 派生。
- v0.1.0 即定义 `DependencyMissing(String)` 变体（v0.1.2 tshark 用，提前定义）。

## 6. 测试策略

- 单元测试：每个 masker 一条 `#[test]`，覆盖 spec.pdf 给的正反例。
- 集成测试：`tests/` 下用 fixtures 跑端到端，断言 masked.csv 关键字段。
- v0.1.1/v0.1.2 的 pcap 集成测试在 tshark 不可用时 `#[ignore]`。
