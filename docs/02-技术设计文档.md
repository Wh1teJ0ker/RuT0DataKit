## 2. 架构分层

### 2.1 设计原则

模块化是 v1.0.0 架构的核心约束，目的是让 v1.1+ 的能力能以「新增模块 + 注册到 trait」的方式增量落地，不改动既有模块内部：

- **单向依赖**：`frontend → src-tauri → crates/core`，下层不引用上层，层间禁止循环依赖。
- **trait 边界**：crates/core 对外只暴露 trait + 数据结构，src-tauri 依赖 trait 而非具体实现；新增处理器只需实现 trait 并注册。
- **模块自洽**：每个模块拥有独立的 `mod.rs`（公共导出 + trait 定义）、内部实现文件、独立测试，不跨模块直接访问其他模块私有项。
- **契约稳定**：IPC 契约（§4）与 trait 签名是 v1.x 系列稳定接口，内部实现可替换，接口不破坏性变更。
- **能力注册化**：脱敏/校验/提取/规则等 v1.1+ 能力以「实现 trait + 注册到 registry」方式接入，不硬编码到调用链。

### 2.2 依赖方向

```
┌─────────────────────────────────────────────────────┐
│  frontend (React shell)                             │
│  • 仅依赖 tauri.js 封装层，不直接 invoke 裸字符串    │
│  • 仅消费 IPC 契约类型，不知道 Rust 内部分层          │
└────────────────────────┬────────────────────────────┘
                         │ invoke (IPC 契约 §4)
┌────────────────────────▼────────────────────────────┐
│  src-tauri (Tauri 命令层)                            │
│  • 编排：commands → db / updater / core trait        │
│  • 不实现业务逻辑，只做 IPC ↔ trait ↔ 持久层 桥接     │
│  • commands 分文件按领域拆，不混在一个文件             │
└────────┬──────────────────┬──────────────────────────┘
         │ trait 调用        │ 直属持有
┌────────▼────────┐  ┌───────▼────────────────────────┐
│  crates/core    │  │  src-tauri/db + updater          │
│  • 纯逻辑引擎   │  │  • 持久层 + 更新器（不进 core）   │
│  • trait + 数据 │  │  • 基础设施层，非业务逻辑         │
└─────────────────┘  └──────────────────────────────────┘
```

**禁止方向**：
- core 不得依赖 src-tauri 或 frontend（core 是可被任何宿主复用的纯逻辑 crate）。
- db / updater 是 src-tauri 的直属基础设施，不进 core（持久化是宿主职责，不是引擎职责）。
- frontend 不得绕过 `tauri.js` 封装层直接拼写命令字符串。

### 2.5 模块化收益与扩展路径

- **v1.1+ 新增脱敏能力**：只需在 `core::processor::masker` 下新增 `HashMasker`/`RegexMasker` 实现 `Masker` trait，注册到 `ProcessorRegistry`，src-tauri 新增 `commands::mask.rs` 桥接，frontend 新增操作入口。不改动 datasource / db / table 模块。
- **新增数据源**（如 PCAP）：在 `core::datasource/` 新增 `pcap.rs` 实现 `Reader` trait，`detect_format` 工厂按扩展名分发。不触动 processor 模块。
- **替换持久层**：若未来从 SQLite 切其他存储，只需重写 `src-tauri::db` 内部实现，`DbManager` 公共方法签名不变，commands 层无感知。
- **前端组件复用**：`components/table/DataTable.jsx` 不绑定具体数据源，任何 Sheet 都能复用选区/列序/状态高亮能力。

## 3. SQLite 表结构

DB 文件路径：`app_config_dir/ruT0datakit.db`（通过 Tauri `path::app_config_dir` 解析）。

> **SCHEMA_VERSION=3**（v1.1.1）：v1.0.0 为 `SCHEMA_VERSION=1`（sessions/sheets/cells/operations/app_settings + 3 索引）。v1.1.0 增量迁移新增 `rules` 表 + `idx_rules_kind` 索引（`SCHEMA_VERSION=2`）。v1.1.1 增量迁移为 `operations` 表新增 `before_snapshot_json` 列（撤销前置快照）+ `idx_cells_sheet_col` 复合索引（搜索加速），均 `IF NOT EXISTS` / `PRAGMA table_info` 检查列存在再 ALTER，幂等，不触发备份重建。

### 3.1 `sessions`

| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | session ID |
| name | TEXT NOT NULL | session 显示名（默认源文件名） |
| source_path | TEXT | 源文件绝对路径 |
| source_type | TEXT NOT NULL | csv / xlsx / log / pcap / sql / json / txt |
| row_count | INTEGER NOT NULL DEFAULT 0 | 总行数 |
| created_at | TEXT NOT NULL | ISO8601 创建时间 |
| updated_at | TEXT NOT NULL | ISO8601 最后更新时间 |

### 3.2 `sheets`

| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | sheet ID |
| session_id | INTEGER NOT NULL REFERENCES sessions(id) | 所属 session |
| name | TEXT NOT NULL | Tab 标题 |
| position | INTEGER NOT NULL DEFAULT 0 | Tab 顺序 |
| column_order | TEXT | 列顺序 JSON 数组（`["col1","col2"]`） |
| column_visibility | TEXT | 列可见性 JSON（`{"col1":true}`） |
| created_at | TEXT NOT NULL | 创建时间 |

### 3.3 `cells`（全量 cell 持久）

| 列 | 类型 | 说明 |
|---|---|---|
| sheet_id | INTEGER NOT NULL REFERENCES sheets(id) | 所属 sheet |
| row_idx | INTEGER NOT NULL | 行索引（0-based） |
| col_idx | INTEGER NOT NULL | 列索引（0-based） |
| value | TEXT | cell 值（NULL 表示空） |
| PRIMARY KEY | (sheet_id, row_idx, col_idx) | 复合主键 |

> 全量持久化策略：导入时把所有 cell 写入 `cells` 表。大表（>5 万行）仍全量写入（DB 体积可接受，SQLite 单文件便于备份）；前端 Table 分页（默认 50/页）通过 `LIMIT/OFFSET` 查询。

### 3.4 `operations`（操作日志）

| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | 操作 ID |
| sheet_id | INTEGER REFERENCES sheets(id) | 作用 sheet（NULL 表示 session 级） |
| kind | TEXT NOT NULL | 操作类型：import / mask / validate / extract / search / export / column_rename / column_reorder |
| params_json | TEXT | 操作参数 JSON |
| before_snapshot_json | TEXT | 撤销前置快照 JSON（v1.1.1 新增，存操作前 cell 原值，撤销用；NULL 表示该操作不可撤销） |
| result_snapshot_json | TEXT | 结果快照 JSON（如脱敏后 cell diff） |
| created_at | TEXT NOT NULL | 操作时间 |

v1.0.0 仅记录 `import` / `column_rename` / `column_reorder` 三类操作；v1.1.0 新增 `mask`（`mask_column` 调用 `log_operation` 记录脱敏操作）。其余类型（`validate` / `extract` / `search` / `export`）随后续版本能力迁移。

### 3.5 `app_settings`

| 列 | 类型 | 说明 |
|---|---|---|
| key | TEXT PRIMARY KEY | 设置键（如 `tshark_path` / `last_update_check`） |
| value | TEXT | 设置值 |

### 3.6 `rules`（v1.1.0 新增）

| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PRIMARY KEY | 规则 ID（如 `name-validate`） |
| name | TEXT NOT NULL | 规则显示名 |
| kind | TEXT NOT NULL | 规则类别：`mask` / `validate` / `extract`（`RuleKind` lowercase 序列化） |
| field | TEXT | 目标列名（如 `name`），可空 |
| pattern | TEXT | 正则 pattern（validate/extract 用），可空 |
| replacement | TEXT | 脱敏掩码字符（mask 用，取首个字符；`None`/空 → 默认 `*`；≥3 字符保留首尾 + 中间掩码字符替换，2 字符保留首字符末位掩码字符），可空 |
| enabled | INTEGER NOT NULL DEFAULT 1 | 启用状态（0/1） |
| description | TEXT NOT NULL DEFAULT '' | 规则说明 |

> 启动时 `DbManager::seed_builtin_rules()` 在 `rules` 表为空时写入 3 条内置规则（`name-validate` / `name-mask` / `name-extract`）。v1.1.0 **不提供新增规则能力**，用户仅可调整可填参数（`pattern` / `replacement`）并通过 `update_rule_params` IPC 持久化。

### 3.7 索引

```sql
CREATE INDEX IF NOT EXISTS idx_cells_sheet_row ON cells(sheet_id, row_idx);
CREATE INDEX IF NOT EXISTS idx_cells_sheet_col ON cells(sheet_id, col_idx);  -- v1.1.1 新增（搜索加速）
CREATE INDEX IF NOT EXISTS idx_operations_sheet ON operations(sheet_id);
CREATE INDEX IF NOT EXISTS idx_sheets_session ON sheets(session_id);
CREATE INDEX IF NOT EXISTS idx_rules_kind ON rules(kind);  -- v1.1.0 新增
```

## 4. Tauri IPC 契约

> 所有命令走 `#[command]`，参数与返回值均 `serde` 序列化。**嵌套 struct 必须加 `#[serde(rename_all = "camelCase")]`**（吸取 v0.8.0 serde 丢字段教训）。

### 4.1 数据命令

| 命令 | 签名 | v1.0.0 |
|---|---|---|
| `import_file` | `(path: String) -> Result<ImportResult, String>` | ✅ CSV/XLSX |
| `get_sheet_data` | `(sheet_id: i64, page: u32, page_size: u32) -> Result<PageData, String>` | ✅ |
| `list_sessions` | `() -> Result<Vec<SessionSummary>, String>` | ✅ |
| `open_session` | `(session_id: i64) -> Result<SessionDetail, String>` | ✅ |

```rust
#[derive(Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
struct ImportResult { session_id: i64, sheet_id: i64, row_count: u32, headers: Vec<String> }

#[derive(Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
struct PageData { headers: Vec<String>, rows: Vec<Vec<Option<String>>>, total: u32, page: u32, page_size: u32 }
```

### 4.2 选区/列命令

| 命令 | 签名 | v1.0.0 |
|---|---|---|
| `reorder_columns` | `(sheet_id: i64, new_order: Vec<String>) -> Result<(), String>` | ✅ |
| `rename_column` | `(sheet_id: i64, old_name: String, new_name: String) -> Result<(), String>` | ✅ |
| `set_column_visibility` | `(sheet_id: i64, visibility: HashMap<String, bool>) -> Result<(), String>` | ✅ |

| 命令 | 签名 | v1.1.1 |

```rust

#[serde(rename_all = "camelCase")]

#[derive(Serialize)]
#[serde(rename_all = "camelCase")]

#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
struct UndoableOp { id: i64, kind: String, created_at: String }
```

> `mask_column` v1.1.1 改用 `log_operation_with_snapshot(sheet_id, "mask", &params, Some(&before_json), &after_json)`，before/after 快照仅含被修改列的 cells JSON。撤销 = 回写 before；重做 = 回写 after。撤销/重做只覆盖「就地变更」类操作（mask / replace_in_column / replace_all）；`import`/`validate`/`extract`/`undo`/`redo` 本身不入撤销栈。undo/redo 自身 log 一条 kind=`undo`/`redo` 的操作（`before_snapshot_json=None`），因此不会被自身撤销，也不出现在 `list_undoable_operations` 结果中（IN 子句只含 `mask`/`replace_in_column`/`replace_all`，硬编码常量无注入风险）。

### 4.8 搜索 / 全表替换命令（v1.1.1 新增）

| 命令 | 签名 | v1.1.1 |
|---|---|---|
| `search_cells` | `(sheet_id: i64, query: String, use_regex: bool, col_idx: Option<u32>, page: u32, page_size: u32) -> Result<SearchPage, String>` | ✅ 关键字模式 `LIKE '%kw%'` + `ESCAPE '\'`；正则模式 `LIKE` 预筛 + Rust `regex` 精确匹配；分页返回命中 cells + 匹配区间 |
| `search_rows` | `(sheet_id: i64, query: String, use_regex: bool, col_idx: Option<u32>, page: u32, page_size: u32) -> Result<SearchRowsPage, String>` | ✅ v1.1.1 hotfix **行级**搜索：按 `distinct row_idx` 分页，返回整行数据 + 仅命中列的 `matches`；前端用其结果「只保留搜索结果」渲染 |
| `replace_all` | `(sheet_id: i64, from: String, to: String, use_regex: bool) -> Result<ReplaceResult, String>` | ✅ 全表搜索替换（单事务），`log_operation_with_snapshot` 存 before/after 快照供撤销 |

```rust
#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
struct SearchHit { row_idx: u32, col_idx: u32, value: Option<String>, matches: Vec<MatchSpan> }

#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
struct MatchSpan { start: usize, end: usize }  // 字节偏移，end exclusive

#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
struct SearchPage { rows: Vec<SearchHit>, total: u32, page: u32, page_size: u32 }

// v1.1.1 hotfix 行级搜索
#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
struct RowCellMatch { col_idx: u32, value: Option<String>, matches: Vec<MatchSpan> }

#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
struct SearchRow { row_idx: u32, cells: Vec<Option<String>>, hits: Vec<RowCellMatch> }

#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
struct SearchRowsPage { rows: Vec<SearchRow>, total: u32, page: u32, page_size: u32 }

#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
struct ReplaceResult { affected: u32 }
```

> 搜索语义：`page` 从 1 开始（下界 1），`page_size` 下界 1；`col_idx=None` 搜全表所有列，`Some(c)` 只搜指定列；空 `query` 返回空结果（不报错）。匹配区间按**字节偏移**计算（`str::find` / `regex::Match`），前端高亮时需注意 Rust 字节偏移与 JS UTF-16 code unit 不一致（前端 T34 处理转换）。正则模式 `total` 取全量命中数（无法用 SQL COUNT），超大表性能待后续版本优化。`replace_all` 的 before/after 快照序列化后存入 `operations` 表，供 `undo_operation` / `redo_operation` 使用。
>
> v1.1.1 hotfix：`search_rows` 按 `distinct row_idx` 分页（`search_matched_row_ids` + `count_matched_rows` / 正则等价），再 `query_row_cells` 取整行 cells 对齐成 `Vec<Option<String>>`（长度 = `count_columns`），同时组装 `hits`（仅命中列）。前端 `APPLY_SEARCH_ROWS` action 把 `SearchRowsPage.rows` 转 antd 行对象写入 `sheet.searchRows`，DataTable 在 `searchRows !== null` 时切换为「只保留搜索结果」渲染（dataSource = searchRows，pagination total = searchTotal）。`APPLY_SEARCH_HITS` 改为先清空 `searchHits = {}` 再写入，修复 stale highlight。

## 7. 错误处理与边界

- core 返回 `CoreError`（thiserror 枚举），Tauri 命令层 `map_err(|e| e.to_string())` 转 `Result<_, String>`。
- 前端 `invoke` 失败统一 `message.error` Toast，不阻塞其他 Sheet。
- 导入大文件不阻塞 UI：`import_file` 在 Rust 侧异步写 DB，前端 Spin 覆盖。
- DB 文件损坏：启动迁移检测 schema_version，损坏则备份为 `.bak` 后重建空 DB（用户数据丢失时明确提示）。
- updater 无网络：`check_update` 失败静默降级（设置页显示「检查失败，请稍后重试」），不阻塞应用启动。
