## 2. 架构分层

### 2.1 设计原则

模块化是 v1.0.0 架构的核心约束，目的是让 v1.1+ 的能力能以「新增模块 + 注册到 trait」的方式增量落地，不改动既有模块内部：

- **单向依赖**：`frontend → src-tauri → crates/core`，下层不引用上层，层间禁止循环依赖。
- **trait 边界**：crates/core 对外只暴露 trait + 数据结构，src-tauri 依赖 trait 而非具体实现；新增处理器只需实现 trait 并注册。
- **模块自洽**：每个模块拥有独立的 `mod.rs`（公共导出 + trait 定义）、内部实现文件、独立测试，不跨模块直接访问其他模块私有项。
- **契约稳定**：IPC 契约（§4）与 trait 签名是 v1.x 系列稳定接口，内部实现可替换，接口不破坏性变更。
- **能力注册化**：脱敏/校验/提取/规则等 v1.1+ 能力以「实现 trait + 注册到 registry」方式接入，不硬编码到调用链。

### 2.2 依赖方向

```
┌─────────────────────────────────────────────────────┐
│  frontend (React shell)                             │
│  • 仅依赖 tauri.js 封装层，不直接 invoke 裸字符串    │
│  • 仅消费 IPC 契约类型，不知道 Rust 内部分层          │
└────────────────────────┬────────────────────────────┘
                         │ invoke (IPC 契约 §4)
┌────────────────────────▼────────────────────────────┐
│  src-tauri (Tauri 命令层)                            │
│  • 编排：commands → db / updater / core trait        │
│  • 不实现业务逻辑，只做 IPC ↔ trait ↔ 持久层 桥接     │
│  • commands 分文件按领域拆，不混在一个文件             │
└────────┬──────────────────┬──────────────────────────┘
         │ trait 调用        │ 直属持有
┌────────▼────────┐  ┌───────▼────────────────────────┐
│  crates/core    │  │  src-tauri/db + updater          │
│  • 纯逻辑引擎   │  │  • 持久层 + 更新器（不进 core）   │
│  • trait + 数据 │  │  • 基础设施层，非业务逻辑         │
└─────────────────┘  └──────────────────────────────────┘
```

**禁止方向**：
- core 不得依赖 src-tauri 或 frontend（core 是可被任何宿主复用的纯逻辑 crate）。
- db / updater 是 src-tauri 的直属基础设施，不进 core（持久化是宿主职责，不是引擎职责）。
- frontend 不得绕过 `tauri.js` 封装层直接拼写命令字符串。

### 2.5 模块化收益与扩展路径

- **v1.1+ 新增脱敏能力**：只需在 `core::processor::masker` 下新增 `HashMasker`/`RegexMasker` 实现 `Masker` trait，注册到 `ProcessorRegistry`，src-tauri 新增 `commands::mask.rs` 桥接，frontend 新增操作入口。不改动 datasource / db / table 模块。
- **新增数据源**（如 PCAP）：在 `core::datasource/` 新增 `pcap.rs` 实现 `Reader` trait，`detect_format` 工厂按扩展名分发。不触动 processor 模块。
- **替换持久层**：若未来从 SQLite 切其他存储，只需重写 `src-tauri::db` 内部实现，`DbManager` 公共方法签名不变，commands 层无感知。
- **前端组件复用**：`components/table/DataTable.jsx` 不绑定具体数据源，任何 Sheet 都能复用选区/列序/状态高亮能力。

## 3. SQLite 表结构

DB 文件路径：`app_config_dir/ruT0datakit.db`（通过 Tauri `path::app_config_dir` 解析）。

> **SCHEMA_VERSION=4**（v1.1.3）：v1.0.0 为 `SCHEMA_VERSION=1`（sessions/sheets/cells/operations/app_settings + 3 索引）。v1.1.0 增量迁移新增 `rules` 表 + `idx_rules_kind` 索引（`SCHEMA_VERSION=2`）。v1.1.1 增量迁移为 `operations` 表新增 `before_snapshot_json` 列（撤销前置快照）+ `idx_cells_sheet_col` 复合索引（搜索加速），均 `IF NOT EXISTS` / `PRAGMA table_info` 检查列存在再 ALTER，幂等，不触发备份重建。v1.1.2 无 schema 变更（`SCHEMA_VERSION=3` 保持，`operations.kind="base64_column"` 复用 v1.1.1 已加的 `before_snapshot_json`/`result_snapshot_json` 列）。v1.1.3 增量迁移为 `rules` 表新增 `template TEXT` 列（存 `TemplateParams` JSON），`migrate_v3_to_v4` 用 `PRAGMA table_info` 检查列存在再 ALTER，幂等；`migrate()` 新增链式分支 `Some(2) => v2→v3→v4` 和 `Some(3) => v3→v4`。

v1.1.4 新增 `.db` / `.sqlite` / `.sqlite3` 二进制 SQLite 数据库文件导入支持，遵循 §2.5 扩展路径（实现 `Reader` trait + `detect_format` 工厂分发，不触动 processor / db / table 模块）：

| 数据源 | Reader | 扩展名 | 列结构 | v1.1.4 |
|---|---|---|---|---|

`DbReader` 与 `SqlReader` 并存但职责不同：`SqlReader` 用 `Connection::open_in_memory` 执行 `.sql` 文本脚本（建表 + INSERT + SELECT）；`DbReader` 用 `Connection::open(path)` 直接打开外部二进制 `.db` 文件。实现要点：

1. **用户表发现** — 查询 `sqlite_master` 过滤 `type='table' AND name NOT LIKE 'sqlite_%'`，按 `name` 升序保证输出稳定，跳过 `sqlite_sequence` 等内部表。
2. **多表联合** — `union_headers` 首列固定 `__table`，其余按各表列名首次出现顺序扩展；每行 `fields` 含 `__table` = 来源表名 + 各列对齐 union_headers（缺列补空串）。
3. **表名安全** — 表名无法参数绑定（SQLite 限制），用 `quote_identifier`（双引号包裹 + 内部双引号翻倍）防御性转义；表名来源为受信系统表 `sqlite_master`。
4. **错误处理** — 路径不存在或文件非 SQLite 格式返回 `CoreError::DataSource`（`Connection::open` 默认带 `SQLITE_OPEN_CREATE` 会静默建库，故先校验文件存在）。
5. **空库** — 无用户表时返回 `Dataset { headers: [], rows: [] }`。

`detect_format` 工厂在既有格式基础上新增 `.db` / `.sqlite` / `.sqlite3` 三个 match arm 路由到 `DbReader`，无新依赖（`rusqlite` 已是 `crates/core` 依赖）。

### 4.13 PCAP 解析的 Windows 兼容（v1.2.2 新增）

v1.2.2 修复 Windows 上导入 pcap 文件失败的问题。根因有三层，分别修复：

1. **`-q` 标志 + 错误分类**（`crates/core/src/pcap/reader.rs`）：
   tshark 默认把 banner / 捕获信息写到 stderr，Windows 控制台编码（GBK / UTF-16）下经 `String::from_utf8_lossy` 解码后变成含乱码的错误串，被误判为「解析失败」。修复：命令统一加 `-q` 关闭 banner，使 stdout 纯净为字段、stderr 纯净为错误；spawn 失败 → `DependencyMissing`（提示配置路径/安装 Wireshark）；非零退出 → `Other`（stderr 单行化）；字段无效 → `NotImplemented`（引导升级）；无 HTTP 匹配帧 → 空列表（正常语义）。

2. **自动探测 + 缓存**（`crates/core/src/pcap/detect.rs`）：
   旧 `resolve_tshark_cmd()` 在用户未显式配置路径时直接回退字面量 `"tshark"`，依赖 PATH 查找。但 Windows 上 Wireshark 默认安装到 `C:\Program Files\Wireshark\` 而**不加入 PATH**，导致 `Command::new("tshark").output()` spawn 失败 → 导入报 `missing dependency: tshark program not found`。修复：`resolve_tshark_cmd()` 在覆盖为 None 时调 `detect_tshark()` 自动探测候选路径（含 Windows 绝对路径），探测结果进程生命周期内缓存（`TSHARK_CACHE`），`set_tshark_path` 改变覆盖时清空缓存。

3. **探测健康检查简化 + `CREATE_NO_WINDOW`**（`crates/core/src/pcap/detect.rs`）：
   第二层修复后用户反馈「设置页配置路径后仍无法使用」。根因：`probe_tshark` 在 `--version` 之外额外跑 `-q -T fields -e frame.number -r <null>` 健康检查，但 Windows 上 `tshark -r NUL` 因 NUL 不是合法 pcap 文件会导致 tshark 报错退出非 0，且部分版本 stderr 含「not valid」字样被探测逻辑误判为「字段不兼容」→ `probe_tshark` 对有效 tshark 返回 `None` → `detect_tshark` 失败 → 设置页「自动检测」返回 null（用户无法「使用检测路径」）；即便用户手动选了路径，`resolve_tshark_cmd` 在覆盖为 None 的路径上仍会走探测缓存拿到被污染的结果。修复：`probe_tshark` 简化为仅检查 `--version` 退出 0 + 首行非空，字段兼容性改由实际 pcap 解析时的 `classify_tshark_failure` 兜底（stderr 含 `aren't valid` → `NotImplemented`）。同时新增 `build_tshark_command()` 公共构造器，所有 tshark 子进程（探测 + 实际解析）统一通过它构造，Windows 上设 `CREATE_NO_WINDOW`（`0x08000000`）标志，避免 GUI 应用（`windows_subsystem = "windows"`）spawn CLI 子进程时弹控制台窗口闪烁。

三层修复叠加后：Windows 用户即使未在设置页配置 tshark 路径，导入 pcap 时也会自动探测到 `C:\Program Files\Wireshark\tshark.exe` 并成功解析；设置页「自动检测」也能正确返回探测结果。无新增依赖、不改 `SCHEMA_VERSION`、不改前端 IPC 契约。

v1.1.2 把硬编码的 `PAGE_SIZE = 50`（`frontend/src/constants.js`）改为可在设置页配置的全局默认值，持久化到 `settings.json`（与 tshark 路径同文件同模式）。

**后端**：`src-tauri/src/commands/settings.rs` 的 `TsharkSettings` 扩展为 `AppSettings`，新增 `#[serde(default)] pub(crate) page_size: Option<u32>` 字段。`settings.json` 结构变为 `{ "tshark_path": "...", "page_size": 50 }`。`#[serde(default)]` 保证旧版 `settings.json`（无 `page_size` 字段）反序列化时自动取 `None` → 前端回退 `PAGE_SIZE=50`。新增两个 `#[tauri::command]`：`load_page_size` / `save_page_size`（见 §4.5）。

**前端 state**：`state/constants.js` 的 `initialState` 新增顶层 `pageSize: 50`（全局默认值，与单 Sheet 的 `sheet.pageSize` 区分）；`ACTION` 新增 `SET_PAGE_SIZE`。`state/reducer.js` 的 `SET_PAGE_SIZE` case 合并全局 + Sheet 同步：

```js
case ACTION.SET_PAGE_SIZE: {
  const pageSize = action.payload;
  return {
    ...state,
    pageSize,                                              // 全局默认值
    sheets: state.sheets.map((s) => ({ ...s, pageSize, page: 1 })),  // 所有 Sheet 同步 + page 重置 1（避免越界）
  };
}
```

一次 dispatch 同时更新全局 `state.pageSize` 与所有 `sheet.pageSize`（page 重置 1），`PageSizeCard` 只需 dispatch 一次 + 刷新当前激活 Sheet 首页。新建/导入 Sheet 的 `pageSize` 由 reducer 从 `state.pageSize` 继承（`ADD_SHEET` / `IMPORT_SUCCESS` / `ADD_SHEET_FROM_PARSE` 调工厂时传 `state.pageSize`，工厂有 `pageSize = PAGE_SIZE` 兜底参数）。

**前端 IPC**：`tauri.js` 新增 `loadPageSize()` / `savePageSize(size)` 封装；`toRowObjects` 的 `base = (page - 1) * PAGE_SIZE` 改为接收 `pageSize` 参数：`toRowObjects(rawRows, headers, sheetId, page = 1, pageSize = PAGE_SIZE)`，消除硬编码行号计算。`PAGE_SIZE` 常量保留作为编译期兜底默认值（state 初始值、factory 兜底、toRowObjects 默认参数、未加载设置时的回退）。

**设置卡片**：`components/settings/cards/PageSizeCard.jsx`（新建）参考 `TsharkPathCard.jsx` 模式：`useAppState` + antd `Form`/`Select`（档位 20/50/100/200，默认 50）+ Save 按钮。`handleSave`：`savePageSize(value)` → `dispatch SET_PAGE_SIZE` → 刷新当前激活 Sheet 首页（`getSheetData(id, 1, value)` + `SET_SHEET_DATA`）→ `message.success`。`SettingsView.jsx` 注册 PageSizeCard，插入到 `TsharkPathCard` 与 `DbPathCard` 之间。

**启动加载**：`App.jsx` 启动 `useEffect` 调 `loadPageSize()`，若返回有效值则 `dispatch SET_PAGE_SIZE` 覆盖默认 50。导入首页 `getSheetData(id, 1, state.pageSize)`（原硬编码 `PAGE_SIZE`）。`DataTable.jsx` 搜索 L241/269 改 `sheet.pageSize || PAGE_SIZE`（修既有不一致：搜索原用 raw `PAGE_SIZE`，分页用 `sheet.pageSize || PAGE_SIZE`）。

搜索命中高亮（v1.1.1 新增，v1.2.1 加固）：`DataTable` 在 `searchHits[rowKey][colHeader]` 存在时，用 `<mark style="background:#fff48f">` 包裹命中区间（后端返回字节偏移，前端用 `TextEncoder`/`TextDecoder` 按字节区间还原字符串，中英文混合安全）。v1.2.1 加固：`highlightCell` 增加大单元格防护，当 `text.length > 50000`（约 50KB）时跳过 `TextEncoder.encode` + mark 高亮，直接返回纯文本，防止 8.5 MB 级单元格在主线程分配巨型 `Uint8Array` 冻结 UI；阈值与 `ExtractPanel` 保持一致。列配置增加 `ellipsis: true`、`Table.scroll.y = "calc(100vh - 280px)"`，使超长单元格截断显示、表体可纵向滚动；`column.render` 对返回纯字符串超 200 字符时截断加 `…` 兜底，防 antd ellipsis 在某些场景未生效。

行级搜索模式（v1.1.1 hotfix 新增）：`APPLY_SEARCH_ROWS` 把 `search_rows` 返回的 `SearchRowsPage.rows` 转为 antd 行对象写入 `sheet.searchRows`，`searchTotal` 写入命中行总数。`DataTable` 检测 `sheet.searchRows !== null`（`isSearchMode`）时切换渲染：`Table.dataSource = searchRows`、`Table.pagination.total = searchTotal`、翻页调用 `handleSearchPageChange`（再次 `search_rows` 拉对应页）。`APPLY_SEARCH_HITS` 在写入前先 `searchHits = {}` 清空旧值，修复「第一次搜索高亮在第二次搜索后仍残留」的 stale highlight bug。`CLEAR_SEARCH` 同时把 `searchRows` 置 `null`、`searchTotal` 置 0，退出搜索模式恢复全表分页。

## 7. 错误处理与边界

- core 返回 `CoreError`（thiserror 枚举），Tauri 命令层 `map_err(|e| e.to_string())` 转 `Result<_, String>`。
- 前端 `invoke` 失败统一 `message.error` Toast，不阻塞其他 Sheet。
- 导入大文件不阻塞 UI：`import_file` 在 Rust 侧异步写 DB，前端 Spin 覆盖。
- DB 文件损坏：启动迁移检测 schema_version，损坏则备份为 `.bak` 后重建空 DB（用户数据丢失时明确提示）。
- updater 无网络：`check_update` 失败静默降级（设置页显示「检查失败，请稍后重试」），不阻塞应用启动。
