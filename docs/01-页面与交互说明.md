## 2. 文件选择与类型识别

- 点击「选择文件…」→ 系统文件对话框，多选。
- 类型识别规则：
  - 后缀 `.csv` / `.xlsx` → csv
  - `.pcap` / `.pcapng` / `.dasctf`（用户可手动覆盖为 pcap）→ pcap
  - `.log` / `.txt`（含 CLF 头部）→ log
  - 其余 → 用户手动选择 csv/pcap/log
- 识别失败不阻塞：弹提示「无法识别，请手动选择类型」。
- v0.1.0：仅 csv/xlsx 入口可用；pcap/log 按钮置灰并标"v0.3.0 / v0.2.0 提供"。v0.2.0 起日志按钮切 active。

## 3. 规则加载

- 内置规则下拉：
  - v0.1.0：`default_mask`（脱敏）。
  - v0.2.0+：增加 `sensitive_scan`（日志扫描用）。
  - v0.3.0+：增加 pcap 专用规则。
- 「加载自定义 YAML…」选本地规则文件，加载失败弹错误提示。

## 4. 操作按钮

> v0.1.0 起校验已是独立 view，不再以顶部「校验」按钮形式存在；各 view 自带主操作按钮。

- **MaskView**：「应用」按钮触发预览（调 `apply_rules_cols` → `SET_MASKED`），预览表展示脱敏后数据；未点应用前预览表为空。「导出」按钮 `SET_VIEW("export")` 跳转 ExportView（state 常驻不重置）。
- **ValidateView**：「应用」按钮触发校验（调 `run_validate` → `SET_VALIDATE`），预览表展示逐 cell 合法性矩阵，非法单元格红底高亮；未点应用前预览表为空。「导出」按钮跳转 ExportView。
- **ExportView**：单一 antd Table 集成——表头行 checkbox 勾选导出列、上下移按钮调列序、单元格预览；顶部数据源 Select（原始 / 脱敏 / 校验）/ 过滤 Select / 格式 Select（CSV / XLSX）；「导出」按钮按勾选列 + 列序 + 格式调 `export_records_csv` 或 `export_records_xlsx`。
- **RulesView**：单一列表渲染脱敏 + 校验全部规则，每条带「试运行」/「编辑」/「删除」按钮；右上角「添加规则」打开 Drawer 抽屉表单完成新建/编辑。试运行按钮调 `preview_mask_rule` / `preview_validate_rule` 动态读取当前数据首行展示 `input → output`（脱敏）或 `input → valid + message`（校验）。「保存 YAML」（`save_ruleset`）/「加载 YAML」（`read_ruleset`）保留。
- 「扫描」：pcap / log 模块；v0.1.0 置灰，v0.2.0（log）/ v0.3.0（pcap）启用。
- 按钮根据当前选中文件类型与版本能力启用/禁用。

## 5. 结果展示

- 概览：源、类型、记录总数、脱敏字段数、耗时。
- 命中明细：v0.1.0 用于展示脱敏前后对比表（字段名、原值、脱敏值）；v0.2.0+ 用于敏感/攻击命中。
- 报告 JSON：只读文本框，可全选复制。
- 导出：masked.csv / report.json，弹保存对话框。
- v0.2.1 LogView 命中明细列（sqli finding）：
  - 原始日志表（每行一条 LogEntry）：`line_no` / `ip` / `method` / `path` / `query` / `status` / `user_agent` + **decoded_path** / **decoded_query** / **decoded_ua**（已 `+`→space + 双重 `%XX` 解码）。
  - findings 表（每行一条 Finding）：`type` / `value`（rule_id）/ `location`（line_no）/ `context`（命中文本段）+ **解析结果**（`ParsedPayload.summary`，如「盲注二分：读取 database() 第 1 字符 ascii > 79」）+ **读取目标**（`read_target`，如 `database()` / `user()` / `version()`）。
  - weak_password / sensitive finding 的「解析结果」/「读取目标」列为空（`extra=None`）。
- v0.2.2 LogView 命中明细新增「盲注聚合结果」段 ③.5：
  - 位置：findings 表下方独立区块，读 `Report.extra.blind_aggregation`（`Vec<AggregatedResult>`）渲染。
  - 每行一个 read_target 的还原结果，呈 antd inner Card：
    - 标题：`read_target`（如 `database()` / `select group_concat(table_name) from information_schema.tables where table_schema=database()`）。
    - extra：探针类型 Tag（`probe_kind`，v0.2.3，`ascii_binary`=red / `equality`=orange / `length`=blue；`r.kind` 缺失时前端按 `position_details[0].status` 兜底推断）+ 「已解 N/M」Tag（red）。
    - 主内容：antd `Typography.Text` strong 展示还原串 `decoded_string`（如 `"person"` / `"person_data"` / `"id,username,password"`）。
      - 若 `r.separator_char` 存在（T3-1，read_target 首个 `0xNN` 字面量解码出的分隔符，如 `~`）：用 volcano 色 `Tag` 包裹分隔符字符高亮分段展示，并提供「复制」按钮（`navigator.clipboard.writeText`）一键复制完整还原串。
      - 否则：`Text strong copyable` 原样展示并支持 antd 内置复制。
    - 副信息（Descriptions）：探针数 `probe_count` + 来源 IP（`source_ips` 去重列表）+ 解析统计（`resolved_chars` 已解 / `beyond_end_positions` 越界 / `unresolved_chars` 未解）。
    - 位置明细表（v0.2.3，替代旧 Tooltip+JSON.stringify）：Descriptions 下方 antd `Collapse`（ghost / size=small，默认折叠，label=`位置明细（N 项）`），展开后内嵌 `Table`（size=small / pagination=false / scroll y=200 / rowKey=position），列：
      - 位置（`position`）
      - 字符（`decoded_char`）：resolved 显示字符本体（`Text code`）；unresolved/beyond_end/insufficient 显示 `-`；length_resolved 显示 `ascii_val` 数值。
      - ASCII（`ascii_val`）
      - 探针数（`probe_count`）
      - 状态（`status`）Tag 着色：`resolved`=green / `unresolved_all_true`=orange / `beyond_end`=default / `insufficient_probes`=red / `equality_resolved`=blue / `length_resolved`=purple。
  - 空态：`Report.extra.blind_aggregation` 为空数组或缺失时，该区块显示 antd `Empty`（「无盲注聚合结果」），不阻塞其它 Tab。
- v0.2.4 LogView 新增「还原数据库视图」段 ③.5a（在段 ③.5 之前），把 4 类聚合 read_target 还原串交叉关联按数据库格式还原展示：
  - 位置：段 ③.5「原始聚合明细」上方独立 Card，读 `Report.extra.reconstructed_database`（`ReconstructedDatabase`）渲染。
  - 顶部 Descriptions：数据库名（`schema`，`Text code` 展示，如 `"person"`）+ 表数（`tables.length`）+ 未匹配聚合数（`unmatched_results.length`）。
  - 每张 `ReconstructedTable` 一个 inner Card：
    - 标题：`<Text code strong>{table.name}</Text>`（如 `person_data`）+ 列/行数 Tag。
    - 主内容：antd `Table`（size=small / pagination=false / scroll x=max-content），列由 `table.columns` 全量列生成（title=列名，dataIndex=列名，如 id/username/password/sex/birth/idcard/phone），dataSource 由 `table.rows` 映射（每行 object 键=列名，未 fetch 列 undefined），未 fetch 单元格 `render: v => v ?? <Text type="secondary">-</Text>` 显示 `-`。
    - extra：`column_separator` volcano Tag（如 `分隔符 ~`）+ `row_data_columns` Tooltip（已 fetch N/M 列）+ 探针数 Tag（`source_probe_count`）。
  - 未匹配聚合：`unmatched_results` 非空时下方 antd `Divider` + 简版列表，每项展示 `read_target` + `decoded_string`（copyable）。
  - 空态：`reconstructed_database` 缺失或 `tables.length === 0`（如只有 `database()` 无 row data 的非标准 CTF 日志）→ antd `Empty`（「无法还原为数据库结构（缺少 database()/table_name/column_name/row data 四类探针）」）。
- v0.2.4 段 ③.5「盲注聚合结果」改名「原始聚合明细」保留兜底：既有逐 read_target inner Card（kind Tag / separator 高亮 / Collapse+Table 位置明细）全部保留不动，数据源 `blind_aggregation` 不变，满足非标准 CTF 日志的可读性。
- v0.3.0 增量交付：侧栏「流量分析」由 disabled 切 active（`PcapView`），四段垂直布局（镜像 LogView）：
  - 段 ① 导入 `.pcap/.pcapng`：`select_file` → `detect_source_type === "pcap"` 校验 → `scanPcapFile(path)`（一次 IPC 返回 `{ entries, report }`，`entries` 为 `Vec<HttpRequest>`，`report` 为 `Report(kind="pcap_scan")`）。失败（含 tshark 缺失）→ `message.error` 提示，不切状态。
  - 段 ② 原始 HTTP 请求表：antd `Table`（pageSize 50），列 frame_no / src_ip / dst_ip / method / host / uri / body 预览（slice 200） / user_agent；rowKey=frame_no。
  - 段 ③ 扫描结果 summary：顶部「运行敏感扫描」按钮（再调 `scanPcapFile` 仅取 report，复用导入时的 entries 缓存）；antd `Descriptions` 展示 `summary.total_requests` / `sensitive_hits` / `decoded_fragments`；`top_src_ips`（按 hits 倒序取前 5）每项 antd `Tag` volcano 着色（`{ip}: {hits}`）。
  - 段 ④ Findings 表：antd `Table`，列 type（`Tag` 按 `TAG_COLOR_BY_TYPE` 着色：idcard=purple / phone=blue / bankcard=magenta / email=cyan / mac=geekblue / username=gold / name=green） / value / location（`frame:N`） / context（`{method} {host} -> {src_ip}`）。
  - 空态：无 entries → antd `Empty`（「请先导入 .pcap/.pcapng 文件」）；report 缺失 → 不渲染段 ③/④。
  - tshark 缺失：错误信息含 `"tshark"` 或 `"DependencyMissing"` → `message.error("流量分析需要系统 tshark，请先安装 Wireshark CLI (brew install wireshark)")`。
  - 0 emoji / 0 原生 select 保持（全 antd 组件）。

> v0.2.0/v0.3.0 的「日志扫描」「流量分析」view 仍保留（向后兼容），不在 v0.4.0 的 7 界面主流程中——v0.4.0 主流程是「预处理 → 搜索/脱敏/校验/导出」+「Tools」的通用数据处理链，日志/流量作为专项扫描入口仍可独立访问。

**界面 1 — 数据预处理（PreprocessView）**：
- 顶部「选择文件」按钮 → `select_file` → `detect_source_type`（csv / xlsx / sql / pcap / log / json / unknown）；unknown 时让用户手动选 csv/sql/json/log/pcap。
- 「读取」按钮调 `read_records(path)` → 写入 `state.records = { headers, rows, rowCount, sourceType }`。
- 主体 antd Table：前 `PREVIEW_ROW_LIMIT` 行预览，表头来自 `records.headers`。
- 底部 4 个跳转 Button：「搜索」/「数据脱敏」/「数据校验」/「数据导出」均 `dispatch SET_VIEW`，state 常驻不重置。
- 无 records 时显示 `Empty`（「请先选择文件并读取」）。
- **v0.4.1 T6-4 SQL 盲注特征自动跳转**：`handleImport` 在 `SET_RECORDS` 成功后调 `detectSqlBlindFeatures(headers, rows)`（Tauri 命令，遍历所有 cell 跑 core `looks_like_blind_probe` 三类正则 ascii_binary / equality / length，仅本地正则匹配，不调用网络，满足 §6「不外发数据」约束）；返回 `{ detected: bool, samples: string[] }`，samples 上限 50。若 `detected === true`，自动 dispatch `SET_VIEW("tools")` + `SET_TOOLS_ACTIVE_TAB("sql")` + `SET_SQL_PARSE_INPUT`（samples 以 `\n` 拼接预填到 SqlParseTool 输入框），并 `message.success` 提示「检测到 SQL 盲注特征，已自动跳转到 SQL 解析工具」；`detected === false` 不跳转，留在预处理视图。detect 命令调用失败仅 `console.warn`，不阻塞主流程。

**界面 2 — 规则管理（RulesView，多标签重构）**：
- 单一列表渲染全部 `maskers` + `validators`，每条带 `tags` 多 Tag 显示（mask / validate / sensitive / search / sql_parse ...）。
- Drawer 抽屉表单：除原 field / masker / validator / params 外，新增 `tags` 多选 antd Select（`mode="tags"`，可自由输入新标签）。
- 试运行 / 编辑 / 删除按钮保留；保存 YAML 时 tags 字段一并序列化。
- 旧 YAML 不含 `tags` 字段时反序列化为空 Vec，向后兼容（v0.1.0 规则集可直接加载）。

**界面 3 — 搜索（SearchView）**：
- 顶部 `Radio.Group`（optionType=button）三选：关键词 / 正则 / 精确字段。
  - 关键词：`AntSearch` 输入框（多关键词空格分隔）+ AND/OR `Radio.Group`。
  - 正则：`Input` monospace + 「搜索」按钮（非法正则后端返回 `InvalidInput` → `message.error`）。
  - 精确字段：字段名 Input + 字段值 Input + 「搜索」按钮。
- 「搜索」调 `searchRecords(headers, rows, queryJson)` → `dispatch SET_SEARCH_RESULTS` + `SET_SEARCH_RESULTS` 携带 `performance.now()` 耗时。
- 顶部 `Descriptions`：命中数 / 耗时 / 模式 Tag。
- 命中表 `Table`：# / 行号 / 列名 / 字段值 / 片段（片段用 React `<mark>` 高亮，按 mode 抽 needle；正则模式用 `RegExp.exec` 全局匹配切片，零宽匹配 `lastIndex++` 防死循环；不使用 `dangerouslySetInnerHTML`）。
- 「跳转脱敏」/「跳转导出」按钮：把命中行号 `Array.from(new Set(hits.map(h => h.row))).sort()` 写入 `state.filteredRowIndices` 后 `SET_VIEW`；hits 为空时按钮 disabled。

**界面 4 — 数据脱敏（MaskView，消费搜索命中行）**：
- 段 ① 原始数据 Table：v0.4.0 新增「仅搜索命中行」`Switch`（仅当 `state.filteredRowIndices` 非空时显示），开启后 `effectiveRows = rows.filter((_, idx) => set.has(idx))`；顶部 `Alert` info 提示已过滤 N 行。
- 段 ② 表头-规则映射：全局 `rules.maskers` 按 `isMaskRule`（无标签 或 含 `mask` 标签）筛 + 会话级 `maskOverrides` 覆盖。
- 段 ③ 预览表：`state.maskedRows` 前 `PREVIEW_ROW_LIMIT` 行。
- 段 ④ 操作面板：「应用」调 `applyRulesColsRecords` → `SET_MASKED`；「导出」`SET_VIEW("export")`。

**界面 5 — 数据校验（ValidateView）**：四段垂直同 MaskView；非法 cell 红底高亮；全局规则按 `validate` 标签筛。

**界面 6 — 数据导出（ExportView，搜索命中行过滤）**：

**界面 7 — Tools（ToolsView，v0.4.1 T6-3 改为下拉栏 Select）**：
- antd `Select` 下拉栏（`options=[{value:"sql",label:"SQL 解析"},{value:"regex",label:"正则解析"}]`，`style={{width:220}}`，`onChange` dispatch `SET_TOOLS_ACTIVE_TAB`，默认 sql fallback）；v0.4.0 原 antd `Tabs` 横版标签在 v0.4.1 改为下拉栏，满足「下拉栏而非横版标签」诉求。
- 选中 sql 渲染 **SqlParseTool**：`TextArea` 多行输入 SQL 探针序列（每行一条，Ctrl/Cmd+Enter 触发解析）→ `parseSqlTool(inputs)` → `dispatch SET_SQL_PARSE_RESULT`。
  - 顶部 `Descriptions` 4 列：schema / 表数 / unmatched / 探针数。
  - 每张 `ReconstructedTable` 一个 inner Card（标题 `表: <name>` + extra Tags：分隔符 / 列数 / 行数 / 探针数）+ antd Table（columns 来自 `tbl.columns`，cells 为 null 显示 `-`）。
  - unmatched 兜底 Card + Table（read_target / decoded_string / probe_count / source_ips）。
  - 探针明细 Card + Table（# / read_target / kind Tag / char_position / comparator / threshold / source_ip / body_size，pageSize 50）。comparator 列：equality 探针显示 `=<char>` Tag，其它显示 `-`（真实 comparator 在 payload 表里）。
  - **payload 语义解析 Card + Table**（v0.4.0 T5-13 新增）：列 attack_type（volcano Tag）/ technique / read_target / char_position / comparator / compared_ascii / union_columns / sleep_seconds / summary，覆盖 union / error / time / tautology / comment 5 类非盲注兜底。空时该 Card 不渲染。
- 选中 regex 渲染 **RegexTool**（v0.4.1 T6-5 重构：移除模板 Tab + 新增构造 Tab）：
  - 解析子 Tab：`Input` monospace 输入正则 → `explainRegex(pattern)` → 渲染 `Vec<RegexTokenDesc>` Table（token / kind / description / position）。反向引用 `\1` / look-around `(?=...)` 触发 `Alert` 警示（regex crate 引擎不支持，仅解释不执行）。
  - **构造子 Tab（v0.4.1 T6-5 替代旧模板子 Tab）**：`TextArea` 输入一句自然语言描述（如「11 位手机号」「以 1 开头共 11 位数字」「邮箱地址」）→ `regexConstruct(statement)` → 渲染 `pattern` `Paragraph` copyable + `matched_clues` antd `Tag` 列表（位数 / 字符集 / 锚定前缀 / 邮箱 / URL / 身份证）+ 测试样例输入框 + 命中高亮（复用 `highlightMatches` + `adaptRegexForJs`）。core `construct_regex(statement)` 规则化推断 6 类线索，语义优先级 邮箱 > URL > 身份证 > 通用，末尾 `Regex::new` 校验保证 pattern 可编译；不调用网络，满足 §6「不外发数据」约束。

## 6. 状态流

- idle → file_selected → rule_loaded → running → done / error。
- running 期间禁用按钮，状态栏显示进度（v0.1.0 仅显示 spinner，不细粒度）。

## 7. 错误处理

- tshark 缺失（v0.3.0）：弹「pcap 模块需要系统 tshark，请先安装 Wireshark CLI」并禁用「扫描」按钮。v0.1.0 即在 GUI 内置该提示文案与禁用逻辑占位。
- 规则 YAML 解析失败：弹错误行号与原因，不切换状态。
- 文件读取失败：弹原因，回到 idle。
