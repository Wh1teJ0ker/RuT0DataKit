# 页面与交互说明

> **版本覆盖说明**：本文为 v0.1.0 ~ v0.3.0 全版本最终形态的**目标超集**描述，用于规划完整交互愿景。
> **v0.1.0 实际交付**（UI 重构 + 规则引擎重构补丁 T0-21 ~ T0-26 后）为：左侧边栏 4 active view（数据脱敏 / 数据校验 / 数据导出 / 规则管理）+ 2 disabled（日志扫描 v0.2.0 / 流量分析 v0.3.0）。前端跨视图 state 在 `App.jsx` 顶层 `useReducer` 常驻，切 view 不丢数据。MaskView/ValidateView 为四段垂直布局；ExportView 为单一 Table 集成；RulesView 为单一列表 + Drawer + 动态试运行。
> **v0.2.0 增量交付**：日志扫描 view 由 disabled 切 active（`LogView`），调用 src-tauri `scan_log` 命令展示 `Report(kind=log_scan)` 概览 + 命中明细；pcap 仍置灰（v0.3.0）。
> **v0.2.1 增量交付**：LogView findings 表新增「解析结果」（`ParsedPayload.summary`）+「读取目标」（`read_target`）列，读 `Finding.extra` 序列化字段渲染；原始日志表新增 `decoded_path` / `decoded_query` / `decoded_ua` 三列（已 `+`→space + 双重 `%XX` 解码）；签名引擎 pattern 扩变体（`union all select` / `exp(~...)` / `floor(rand(0)*2)`）。pcap 仍置灰（v0.3.0）。
> 下文 §1 图示中的 **tabs（概览/命中明细/报告JSON/导出）、状态栏、扫描按钮、pcap 入口** 均属 v0.2.0/v0.3.0 后续版本才启用，v0.1.0 不交付。
> 前端栈：React 18 + Vite 5 + Ant Design 5 + @ant-design/icons（v0.1.0 起统一）。

## 1. 主界面结构（最终形态超集）

单页应用，三块区域：

```
┌───────────────────────────────────────────────────────────┐
│  [选择文件…]   类型: <自动识别 / csv / pcap / log>          │
│  规则: <内置: default_mask ▾>  [加载自定义 YAML…]          │
│  操作: [脱敏] [扫描]                                         │
├───────────────────────────────────────────────────────────┤
│  结果区（tab 切换）                                          │

├───────────────────────────────────────────────────────────┤
│  状态栏：源文件、记录数、命中数、耗时                          │
└───────────────────────────────────────────────────────────┘
```

> **v0.1.0 实际形态**：上图三段式尚未交付。实际为侧边栏 + 四 view，详见下文 §1.1。

## 2. 文件选择与类型识别

- 点击「选择文件…」→ 系统文件对话框，多选。
- 类型识别规则：
  - 后缀 `.csv` / `.xlsx` → csv
  - `.pcap` / `.pcapng` / `.dasctf`（用户可手动覆盖为 pcap）→ pcap
  - `.log` / `.txt`（含 CLF 头部）→ log
  - 其余 → 用户手动选择 csv/pcap/log
- 识别失败不阻塞：弹提示「无法识别，请手动选择类型」。
- v0.1.0：仅 csv/xlsx 入口可用；pcap/log 按钮置灰并标"v0.3.0 / v0.2.0 提供"。v0.2.0 起日志按钮切 active。

## 3. 规则加载

- 内置规则下拉：
  - v0.1.0：`default_mask`（脱敏）。
  - v0.2.0+：增加 `sensitive_scan`（日志扫描用）。
  - v0.3.0+：增加 pcap 专用规则。
- 「加载自定义 YAML…」选本地规则文件，加载失败弹错误提示。

## 4. 操作按钮

> v0.1.0 起校验已是独立 view，不再以顶部「校验」按钮形式存在；各 view 自带主操作按钮。

- **MaskView**：「应用」按钮触发预览（调 `apply_rules_cols` → `SET_MASKED`），预览表展示脱敏后数据；未点应用前预览表为空。「导出」按钮 `SET_VIEW("export")` 跳转 ExportView（state 常驻不重置）。
- **ValidateView**：「应用」按钮触发校验（调 `run_validate` → `SET_VALIDATE`），预览表展示逐 cell 合法性矩阵，非法单元格红底高亮；未点应用前预览表为空。「导出」按钮跳转 ExportView。
- **ExportView**：单一 antd Table 集成——表头行 checkbox 勾选导出列、上下移按钮调列序、单元格预览；顶部数据源 Select（原始 / 脱敏 / 校验）/ 过滤 Select / 格式 Select（CSV / XLSX）；「导出」按钮按勾选列 + 列序 + 格式调 `export_records_csv` 或 `export_records_xlsx`。
- **RulesView**：单一列表渲染脱敏 + 校验全部规则，每条带「试运行」/「编辑」/「删除」按钮；右上角「添加规则」打开 Drawer 抽屉表单完成新建/编辑。试运行按钮调 `preview_mask_rule` / `preview_validate_rule` 动态读取当前数据首行展示 `input → output`（脱敏）或 `input → valid + message`（校验）。「保存 YAML」（`save_ruleset`）/「加载 YAML」（`read_ruleset`）保留。
- 「扫描」：pcap / log 模块；v0.1.0 置灰，v0.2.0（log）/ v0.3.0（pcap）启用。
- 按钮根据当前选中文件类型与版本能力启用/禁用。

## 5. 结果展示

- 概览：源、类型、记录总数、脱敏字段数、耗时。
- 命中明细：v0.1.0 用于展示脱敏前后对比表（字段名、原值、脱敏值）；v0.2.0+ 用于敏感/攻击命中。
- 报告 JSON：只读文本框，可全选复制。
- 导出：masked.csv / report.json，弹保存对话框。
- v0.2.1 LogView 命中明细列（sqli finding）：
  - 原始日志表（每行一条 LogEntry）：`line_no` / `ip` / `method` / `path` / `query` / `status` / `user_agent` + **decoded_path** / **decoded_query** / **decoded_ua**（已 `+`→space + 双重 `%XX` 解码）。
  - findings 表（每行一条 Finding）：`type` / `value`（rule_id）/ `location`（line_no）/ `context`（命中文本段）+ **解析结果**（`ParsedPayload.summary`，如「盲注二分：读取 database() 第 1 字符 ascii > 79」）+ **读取目标**（`read_target`，如 `database()` / `user()` / `version()`）。
  - weak_password / sensitive finding 的「解析结果」/「读取目标」列为空（`extra=None`）。

## 6. 状态流

- idle → file_selected → rule_loaded → running → done / error。
- running 期间禁用按钮，状态栏显示进度（v0.1.0 仅显示 spinner，不细粒度）。

## 7. 错误处理

- tshark 缺失（v0.3.0）：弹「pcap 模块需要系统 tshark，请先安装 Wireshark CLI」并禁用「扫描」按钮。v0.1.0 即在 GUI 内置该提示文案与禁用逻辑占位。
- 规则 YAML 解析失败：弹错误行号与原因，不切换状态。
- 文件读取失败：弹原因，回到 idle。
