# 03 — 开发任务清单（v1.0.0 框架阶段）

> 本清单服务于 [`00-需求文档.md`](./00-需求文档.md) 定义的 v1.0.0「纯框架 shell」MVP 边界。v1.0.0 不实现任何业务能力（脱敏/校验/提取/规则/搜索/Tools/日志/PCAP），仅搭建四区布局 shell + Sheet/Tab 工作台 + SQLite 全量持久 + Tauri updater 签名 + AI 占位 + 设置入口。业务能力自 v1.1+ 起逐项重构，届时在本清单基础上扩展。

## 1. 任务 DAG 总览

```
T1 工作区脚手架
 ├─ T2 四区布局 shell ─────────────┐
 ├─ T4 SQLite 持久层 ──┐            │
 │                     ├─ T5 导入流 │
 T3 Sheet/Tab + Table ─┘            │
 ├─ T6 Tauri updater 插件           │
 ├─ T7 AI 占位 IPC 契约             ├─ T9 双语 README + docs + QA
 └─ T8 设置页 + 7 项操作占位提示 ───┘
```

依赖关系说明：

- T1 为所有任务前置（脚手架未就绪则无法编译）。
- T2、T3、T4、T6、T7 在 T1 完成后可并行启动。
- T5 依赖 T3（工作台 UI）+ T4（持久层）。
- T8 依赖 T2（布局壳）+ T6（设置页需要 updater 检查能力）。
- T9 依赖全部前序任务 verified_complete 后做端到端文档与 QA 收口。

### T1 工作区脚手架

**目标**：从零建立 Cargo workspace + 前端工程 + src-tauri Tauri v2 工程，版本号统一为 `1.0.0`，本地 `cargo tauri dev` 可启动空白窗口。

**前置依赖**：无。

**实现要点**：
- 根 `Cargo.toml`：workspace members = `crates/core`、`src-tauri`，统一 `edition = "2021"`。
- `crates/core/Cargo.toml`：`ruT0-data-kit-core`，v1.0.0 仅骨架（lib.rs + 空模块 `datasource`/`processor`/`model` + trait 占位），不引入业务依赖。
- `src-tauri/Cargo.toml`：`ruT0-data-kit`，依赖 `tauri = "2"`、`tauri-plugin-dialog`、`tauri-plugin-updater`、`rusqlite = { version = "0.32", features = ["bundled"] }`、`serde`/`serde_json`；path dep `../crates/core`。
- `src-tauri/tauri.conf.json`：`productName = "RuT0DataKit"`，`version = "1.0.0"`，`identifier = "com.rut0.datakit"`，`beforeBuildCommand = "pnpm --prefix ../frontend run build"`，`devUrl = "http://localhost:5173"`，`frontendDist = "../frontend/dist"`。
- `frontend/`：Vite 5 + React 18 + antd 5 + @ant-design/icons，`pnpm` 为包管理器；`package.json` 版本同步 `1.0.0`。
- 前端入口仅渲染一个空 antd Layout 占位，确认 Tauri ↔ 前端 dev 链路通。

**交付物**：
- 根 `Cargo.toml` + `Cargo.lock`
- `crates/core/`（骨架）
- `src-tauri/`（Tauri v2 工程骨架，可编译）
- `frontend/`（Vite + React + antd 骨架）
- `rust-toolchain.toml`（固定 Rust 版本，不用 `stable` 浮动 channel）

**验收标准**：
- `cargo check --workspace` 通过。
- `pnpm --prefix frontend install --frozen-lockfile` 后 `pnpm --prefix frontend build` 通过。
- `cargo tauri dev` 可启动空白窗口，前端 antd Layout 渲染正常。
- `tauri.conf.json`、`Cargo.toml`（根 + core + src-tauri）、`package.json` 版本号一致为 `1.0.0`。

**验证方式**：
```sh
cargo check --workspace
pnpm --prefix frontend install --frozen-lockfile && pnpm --prefix frontend build
cargo tauri dev  # 手动确认窗口启动
```

### T4 SQLite 持久层

**目标**：建立 rusqlite（bundled）持久层，落地 5 表 schema + 初始化迁移 + 管理器，DB 文件位于 `app_config_dir/ruT0datakit.db`。

**前置依赖**：T1。

**实现要点**：
- `src-tauri/src/db/mod.rs`：`DbManager` 持有 `Mutex<Connection>`，`new(app_config_dir)` 初始化或打开 DB。
- 5 表 schema（见 [`02-技术设计文档.md`](./02-技术设计文档.md) §3）：`sessions` / `sheets` / `cells` / `operations` / `app_settings` + 3 个索引。
- 迁移：首次启动建表，后续启动校验 schema 版本（`app_settings` 写 `schema_version`），不兼容则备份旧 DB 后重建。
- 大表策略：`cells` 全量写入；前端分页查询用 `LIMIT/OFFSET`，默认 50/页。
- 事务：导入写 `cells` 用单事务批量插入，失败回滚。

**交付物**：
- `src-tauri/src/db/mod.rs`（DbManager + schema + 迁移）
- `src-tauri/src/db/schema.sql`（建表 + 索引 DDL，供嵌入或 include_str!）

**验收标准**：
- 首次启动生成 DB 文件，5 表 3 索引存在（`sqlite3 .schema` 核验）。
- 重复启动不重复建表，`schema_version` 正确。
- 插入 5 万行 `cells` 后查询分页响应 < 200ms。

**验证方式**：
```sh
# 启动后定位 DB 文件
sqlite3 ~/Library/Application\ Support/com.rut0.datakit/ruT0datakit.db ".schema"
cargo test -p ruT0-data-kit db::  # 单元测试覆盖建表/迁移/分页
```

### T5 导入流

**目标**：打通「选文件 → 识别 → 新建 Sheet → 写 SQLite → 渲染 Table」全链路，v1.0.0 支持 CSV 与 XLSX。

**前置依赖**：T3（工作台 UI）、T4（持久层）。

**实现要点**：
- 文件选择：`tauri-plugin-dialog` `open` 过滤 `.csv,.xlsx`。
- 识别：CSV 用 `csv` crate；XLSX 用 `calamine`。首行作为表头。
- 新建 Session + Sheet：写 `sessions`（source_path/source_type/row_count）+ `sheets`（name=文件名，position 自增）。
- 写 cells：事务批量 `INSERT INTO cells`；大表分批 commit（每 5000 行）。
- 操作日志：写一条 `operations`（kind=`import`，params_json 记录路径与行数）。
- 返回 `ImportResult { sessionId, sheetId, rowCount, columns }`，前端新建 Tab + 首页数据 `get_sheet_data`。

**交付物**：
- `crates/core/src/datasource/mod.rs`（CSV/XLSX 解析 trait + 实现）
- `src-tauri/src/commands.rs`：`import_file(path) -> ImportResult`、`get_sheet_data(sheet_id, page, page_size) -> PageData`
- 前端 `frontend/src/tauri.js`：`invoke('import_file', ...)` 封装

**验收标准**：
- 导入 1000 行 CSV：Sheet 新建、Table 渲染首页 50 行、分页可翻。
- 导入 XLSX 同上。
- 重启应用后通过「打开历史 Session」可重新加载该 Sheet 全量数据（验证持久化）。
- `operations` 表有对应 `import` 记录。

**验证方式**：`cargo tauri dev`，准备样例 CSV/XLSX 手动导入 + 重启核验持久化 + `sqlite3` 核验 operations 记录。

### T6 Tauri updater 插件

**目标**：集成 Tauri updater 插件（带 Ed25519 签名），提供「检查更新 / 安装更新」命令，updater JSON 托管于 GitHub Release。

**前置依赖**：T1。

**实现要点**：
- 生成签名密钥：`tauri signer generate -w ~/.tauri/ruT0datakit.key`（本地保存私钥，pubkey 填入 `tauri.conf.json`）。
- `tauri.conf.json` `plugins.updater`：`pubkey` 填入；`endpoints` 指向 GitHub Release latest 的 `latest.json` URL；`windows.installMode = "passive"`。
- GitHub Secrets：`TAURI_SIGNING_PRIVATE_KEY`、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`（CI 构建时注入，本地 dev 不需要）。
- 命令：`check_update() -> UpdateStatus { available: bool, version: Option<String>, notes: Option<String> }`；`install_update()` 委托 `tauri-plugin-updater`。
- 安全边界：updater 仅由插件发起 HTTPS 请求拉版本元数据 + 签名产物，不传用户数据；签名校验失败拒绝安装。

**交付物**：
- `src-tauri/src/updater.rs`（check/install 命令封装）
- `src-tauri/tauri.conf.json` updater 配置
- 密钥生成操作记录（不落盘私钥，仅记录 pubkey 与操作步骤到 `docs/versions/1.0.0/`）

**验收标准**：
- `check_update` 在无新版本时返回 `available=false`。
- 配置一个测试 updater JSON 指向更高版本，`check_update` 返回 `available=true, version=<新版本>`。
- 签名验证失败时 `install_update` 拒绝安装并报错。
- 无网络时 `check_update` 静默降级返回 `available=false`，不弹错。

**验证方式**：`cargo tauri dev`，本地起一个静态服务托管 `latest.json` 模拟检查；手动构造篡改签名验证拒绝。

### T7 AI 占位 IPC 契约

**目标**：落地 `ai_suggest` / `invoke_ai_op` 空实现 IPC 契约，为 v1.1+ 真实 AI 能力预留接口。

**前置依赖**：T1。

**实现要点**：
- `ai_suggest(context: AiContext) -> Result<AiSuggestion, String>`：返回 `Err("ai_suggest not implemented until v1.1+")`。
- `invoke_ai_op(op: String, params: Value) -> Result<Value, String>`：返回 `Err("invoke_ai_op not implemented until v1.1+")`。
- 类型定义见 02 文档 §4，所有嵌套 struct 必须 `#[serde(rename_all = "camelCase")]`。
- 前端 AI 面板调用 `ai_suggest` 时 catch 错误并展示「AI 能力 v1.1+ 释放」文案，不崩溃。

**交付物**：
- `src-tauri/src/commands.rs`：两个命令 + 类型定义
- `frontend/src/tauri.js`：`aiSuggest` / `invokeAiOp` 封装

**验收标准**：
- 前端调用 `aiSuggest` 得到 `v1.1+` 错误文案，UI 不崩溃。
- `invokeAiOp` 任意 op 均返回 `v1.1+` 错误。
- 类型定义中嵌套 struct 均带 `rename_all = "camelCase"`。

**验证方式**：`cargo tauri dev`，前端 AI 面板触发调用核验文案；`grep -n 'rename_all' src-tauri/src/commands.rs` 核验。

## 4. 风险点

- **rusqlite bundled 编译耗时**：首次编译 SQLite C 源较慢，CI 需启用缓存。
- **Tauri updater 签名密钥管理**：私钥不落盘仓库，CI 通过 secret 注入；本地 dev 不签名也能跑。
- **大表导入性能**：5 万行以上需分批 commit + 前端分页，避免一次性渲染卡死。
- **serde camelCase 漏加**：v0.8.0 踩过的坑，v1.0.0 所有嵌套 struct 必须显式 `rename_all`，CI 加 grep 检查。
